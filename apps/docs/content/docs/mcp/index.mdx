Semestra runs an [MCP](https://modelcontextprotocol.io) server, so an AI client outside the app
can read your schedule, grades and tasks, and change them when you allow it. It offers the same
operations as the in-app assistant Sem.

- **Endpoint**: `<your Semestra address>/mcp`, e.g. `https://semestra.example.com/mcp`. Global settings → **AI → API & MCP → MCP server** shows the exact address
- **Transport**: Streamable HTTP (stateless, JSON responses)
- **Authentication**: ChatGPT and Claude sign in to your account (OAuth). Other clients send an API token as `Authorization: Bearer spat_…`. Session cookies are not accepted

## Connect a client

The quickest way: in global settings → **AI → API & MCP**, click **New connection**, then choose the client. ChatGPT and Claude only need the server address: you add it in the app, sign in to Semestra and choose what it may do. For the other clients you choose the access, and Semestra creates an API token named after the client and gives you an install link, command or config with the token already filled in, so you never copy the token by hand.

| Client | How |
| --- | --- |
| [ChatGPT](./chatgpt.mdx), [Claude](./claude.mdx) | Paste the address and sign in (needs an HTTPS address) |
| [Cursor](./cursor.mdx), [LM Studio](./lm-studio.mdx) | Open with one click |
| [Claude Code](./claude-code.mdx), [Gemini CLI](./gemini-cli.mdx) | Run one command |
| [VS Code](./vscode.mdx), [Codex](./codex.mdx), [Claude Desktop](./claude-desktop.mdx) (without HTTPS), [Devin Desktop (formerly Windsurf)](./devin.mdx) | Paste a config |
| [Cline](./cline.mdx), [Zed](./zed.mdx) | Set up by hand |
| [Other clients](./other.mdx) | Enter the address and token |

The last step of the window shows the connection: once the client connects for the first time,
“Waiting” turns into “Connected”. You can keep the window open while you set up the client and
come back to check.

Each client's page covers setting it up by hand, where its config file lives and how to check the connection.

### API tokens

To set a client up by hand, create a token first: in global settings → **AI → API & MCP**, click **New connection**, choose **Other client or script**, enter a name and choose:

- **Access**: _Read only_ or _Read and write_.
- **Expiry**: never, 30, 90 or 365 days.

The token is shown once. Give each client its own token and revoke it under **Clients and API tokens** to disconnect that client; deleting your account revokes all of them.

## What a client may do

| Token / setting                                    | Read tools | Write tools | Delete tools |
| -------------------------------------------------- | ---------- | ----------- | ------------ |
| Read only                                          | yes        | no          | no           |
| Read and write                                     | yes        | yes         | no           |
| Read and write, and **Delete data** turned on      | yes        | yes         | yes          |

- **Write tools run immediately**, except in the cases under "Confirming and choosing" below.
- **Delete data** is off by default. Turn it on in global settings → **AI → API & MCP**, under
  **Client permissions**. It applies to every connection, including API tokens used with the REST
  endpoints.
- Tools of a plugin appear only while that plugin is installed on your account.
- Changes made over MCP appear in open browser tabs right away.
- **Recent changes** lists what clients changed in Semestra over the last 90 days, revoked
  connections included, and can be narrowed to one connection. **⋯ → Recent changes** on a read
  and write connection opens that connection's changes.

## Confirming and choosing

In clients that can show MCP forms, Semestra opens a form when:

- **Confirming a change**: before deleting anything, changing many records at once or committing
  an import, the form lists what will change. Nothing happens until you accept; decline and
  nothing changes.
- **Choosing a course**: when you haven't said which course you mean, or several have similar
  names, the form lets you pick it from a list. Terms and Programs work the same way.
- **Settling conflicts**: when an import differs from what is already in Semestra, such as a
  course's credits, or an assessment with the same name already in the gradebook, the form asks
  for each one whether to keep what you have or use the import.

Clients without forms work as before: the client's AI asks you in the chat before it deletes
anything, changes many records at once or commits an import.

## Skills

Sem's skills, such as recording grades, importing a syllabus or answering from course files, work
in MCP clients too. The client's AI loads the skill that fits your request on its own and follows
the same steps as Sem. A skill appears only when the connection may use every tool it needs.

You can also pick one yourself where the client lists MCP prompts (the **+** menu in Claude, a
slash command in Claude Code): each skill is a prompt there. Clients that support the MCP Skills
extension find them as skills.

## Good to know

- Tool names are capability names with `__` for dots, e.g. `academics__course__create_many`.
- Times are in the program's time zone, with the offset.
- If you have exactly one program, tools that need a `program_id` can be called without it.
- Text other people wrote (Canvas pages, file contents) is returned as data; treat it as such.
- A failed call returns `{"error": {"code", "params", "hint"}}`; `hint`, when present, is one
  English sentence on what to do next. `common.internal` means a bug on the server, not a wrong
  argument: retrying does not help, and `params.request_id` identifies it in a bug report.
- Adding items takes a list (`*_create_many`), even for one item. Reordering is left to the app.

The full list is on [Tools and skills](./tools.mdx).
