这些工具只用于开发，不进入生产镜像。

## 演示环境

```bash
pnpm dev:demo                     # 启动 API、网页、假 Canvas 和假模型接口，并建好演示账户
pnpm dev:demo --scenario large    # 另加一门有几百个文件和作业的 Canvas 课程
```

`pnpm dev:demo` 用单独的数据目录（`apps/api/data/demo`，每次重建）启动 API 和网页，不动平时的开发数据。它注册一个演示账户：一个 Program，上学期已结课的课程，本学期带 Section、成绩册、考试和待办的课程，以及下学期的计划，日期都相对今天生成。随后连接假 Canvas、关联本学期的课程并开始第一次同步（在后台进行，侧边栏状态行显示进度），再把假模型服务商设为所有 AI 用途的模型。准备好后会打印地址和登录信息（`demo@example.com` / `semestra-demo-1`）。`--no-canvas`、`--no-ai`、`--no-web` 可以去掉对应部分。

假 Canvas（`127.0.0.1:8090`）提供和真实 Canvas 相同的接口，Semestra 用的就是真实的 Canvas provider：公告、带提交与反馈的作业、单元、页面、讨论、测验、文件和文件夹（包括扫描版 PDF、Word 文档、锁定的文件和隐藏的文件夹）、大纲和日历事件。有一门课关掉了页面，另一门关掉了文件。假模型接口（`127.0.0.1:8091/v1`）兼容 OpenAI，回答是固定的：Sem 会调用一个工具再用 Markdown 回答，抽取会返回文档里找到的日期和权重，图片返回一段纯文本，embedding 用词的哈希。用真实模型的验证仍然要接真实的服务商。

运行时在 `apps/api` 下操控假服务：

```bash
uv run python -m devtools fake faults '{"kind": "rate_limit", "path": "/files", "times": 3}'
uv run python -m devtools fake faults clear
uv run python -m devtools fake changes '{"op": "change_due", "assignment": 1048, "due_in_days": 3}'
uv run python -m devtools fake requests        # 按接口统计请求次数，找重复读取
uv run python -m devtools fake --server ai faults '{"kind": "payment"}'
```

故障有 `rate_limit`（429；加 `"style": "403"` 则是 Canvas 自己的 403 限流）、`unauthorized`、`payment`、`server_error`、`slow` 和 `drop`（回答中途断开）。改动模拟老师的操作：`add_assignment`、`change_due`、`delete_assignment`、`grade`、`announce`、`add_file`、`replace_file`、`delete_file`；`fake state` 列出课程 id。`uv run python -m devtools --help` 列出全部命令，其中 `seed` 可以单独给任何正在运行的实例建演示账户。Bombadil 也用同一份 seed。

这些工具在 `apps/api/devtools/`，不在应用的包里，所以不会进 Docker 镜像。`tests/test_fake_canvas.py` 用 Canvas provider 的契约测试检查假 Canvas，避免它和 provider 读取的内容脱节；`tests/test_fake_ai.py` 经 M06 和 Sem 调用假模型，让它跟上二者的提示与 schema。假 Canvas 的文件下载跳转回同一个服务器，而真实 Canvas 会跳转到另一个域名上的文件存储，这一跳没有覆盖，文件下载要用真实 Canvas 验证。

## 截图与请求统计

两个脚本都在已登录的 Chromium 里打开正在运行的 Semestra。默认用演示账户，先运行 `pnpm dev:demo`；在 `pnpm dev` 上用自己的账户时传 `--email` 和 `--password`。每个页面在新的浏览器里打开，界面状态都是默认值（引导和“更新了什么”视为已看过）；页面上改的偏好和界面状态只留在这个浏览器里，不会存进账户。

```bash
pnpm --filter @semestra/web shot /p/{program}/today /p/{program}/c/{course:ECE201H1}/grades
pnpm --filter @semestra/web requests /p/{program}/today
```

路径里可以写 `{program}`、`{term}`、`{course}` 和 `{course:CODE}`，按账户里的数据填入。

- `shot` 把每个页面以浅色和深色、中文、2 倍分辨率截图，存到 `apps/web/.shots/`。截图时关闭动画、固定时钟，同样的页面连跑两次得到的图片相同。`--locale`、`--themes`、`--width`、`--height`、`--out` 可改默认值。
- `requests` 列出直接打开页面时发出的 API 请求：每个路由的次数与最慢耗时、失败和被取消的请求，以及重复发出的请求。用来确认改动没有多发请求，也没有重复读取同一份数据。它统计的是冷启动打开（含外壳的请求），不是应用内的跳转，也不计在浏览器里直接回答的界面状态请求。在 `pnpm dev` 下 React 的 StrictMode 会让 effect 执行两次，所以 effect 里发出的请求在这里会出现两次，生产环境只有一次（查询有去重，不受影响）。

## 推送前检查

```bash
pnpm check            # 跑这次改动在 CI 上会跑的检查
pnpm check --list     # 只列出会跑哪些 job
pnpm check --only api,web
```

`pnpm check` 直接读 `.github/workflows/ci.yml`：把当前工作区（含未提交和未跟踪的文件）当作一次提交，和 `origin/main` 的分叉点比较，按同一份路径规则选出要跑的 job，再按顺序执行这些 job 的步骤，测试同样只挑受影响的部分。草稿 PR 不跑 CI，标成可评审前先在本地跑一遍。

和 CI 的两处不同：安装依赖的步骤会跳过；“生成结果没有变化”的检查（`git diff --exit-code`）看的是这个 job 前面的步骤有没有改动文件，所以有未提交的改动也能用。

脚本只认识 `ci.yml` 现在用到的写法。改 `ci.yml` 时用了新的 `if:` 条件、步骤字段或 `${{ }}` 表达式，`pnpm check` 会报错并指出位置，需要同步更新 `scripts/check.py`。

## 云端会话

仓库的 `.claude/hooks/session-start.sh` 会在 Claude Code 的云端会话开始时准备环境：安装 CI 用的 Node 26 和 `packageManager` 指定的 pnpm，再安装前后端依赖，并把 `CHROME` 指向镜像里自带的 Chromium。依赖文件没变时会跳过安装。本机运行时它什么都不做。

Paraglide 的插件作为开发依赖安装在 `apps/web/node_modules` 里，`project.inlang/settings.json` 直接引用它，编译文案不需要访问 CDN。
