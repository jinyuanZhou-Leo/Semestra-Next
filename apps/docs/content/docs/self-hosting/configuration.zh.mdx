把设置写在 `deploy/selfhost/.env` 里。compose 文件会把它传给容器，并填好下面标为 _compose_ 的变量。带注释的完整列表见
`deploy/.env.example`；以 `apps/api/src/semestra/core/config.py` 为准。

## Compose 文件

这些变量由 `docker-compose.yml` 自己读取。

| 变量                  | 默认值                  | 含义                                                     |
| --------------------- | ----------------------- | -------------------------------------------------------- |
| `SEMESTRA_VERSION`    | `latest`                | 镜像标签，例如 `1.2.0`                                   |
| `SEMESTRA_PUBLIC_URL` | `http://localhost:8000` | 用户打开的地址。决定网页和 API 的源以及 CORS             |
| `SEMESTRA_PORT`       | `8000`                  | 宿主机端口                                               |
| `SEMESTRA_BIND`       | `0.0.0.0`               | 宿主机网卡。放在反向代理后面时用 `127.0.0.1`             |
| `SEMESTRA_DOMAIN`     | （空）                  | 内置 Caddy 使用的域名（`--profile https`）               |

## 账户与登录

| 变量                                  | 默认值  | 含义                                                             |
| ------------------------------------- | ------- | ---------------------------------------------------------------- |
| `SEMESTRA_SESSION_TTL_DAYS`           | `30`    | 网页会话有效期                                                   |
| `SEMESTRA_ACCESS_TOKEN_TTL_SECONDS`   | `900`   | 原生客户端访问令牌有效期                                         |
| `SEMESTRA_REFRESH_TOKEN_TTL_DAYS`     | `60`    | 原生客户端刷新令牌有效期                                         |
| `SEMESTRA_NOTIFY_NEW_SIGN_IN`         | `false` | 有新会话登录时给用户发邮件                                       |
| `SEMESTRA_GOOGLE_CLIENT_ID`           | （空）  | Google 登录。为空时隐藏 Google 按钮                              |
| `SEMESTRA_TRUSTED_PROXY_HOPS`         | `0`     | API 前面的反向代理层数；客户端 IP 从 `X-Forwarded-For` 右数这么多层读取 |
| `SEMESTRA_COOKIE_SECURE`              | （未设置） | 未设置时，公开地址是 `https` 就使用 Secure cookie             |

邮件设置见[邮件](./email.mdx)。

## 存储与文件

| 变量                                   | 默认值（自部署）      | 含义                                  |
| -------------------------------------- | --------------------- | ------------------------------------- |
| `SEMESTRA_USER_STORAGE_QUOTA_BYTES`    | `0` _compose_         | 每个用户的存储空间；`0` 表示不限      |
| `SEMESTRA_FILES_MAX_UPLOAD_BYTES`      | `26214400`（25 MB）   | 单个上传文件的上限                    |
| `SEMESTRA_FILES_PARSE_TIMEOUT_SECONDS` | `300`                 | 解析一个文件的最长时间                |
| `SEMESTRA_FILES_PARSE_MEMORY_BYTES`    | `2147483648`（2 GB）  | 解析进程的内存上限                    |

## 网络

| 变量                            | 默认值（自部署）  | 含义                                                                                      |
| ------------------------------- | ----------------- | ----------------------------------------------------------------------------------------- |
| `SEMESTRA_ALLOW_PRIVATE_EGRESS` | `true` _compose_  | 允许服务器访问内网和回环地址：局域网里的 Ollama、学校自建的 Canvas、纯 http 的 Canvas。compose 文件之外默认是 `false` |

设为 `false` 时，访问用户填写的主机如果解析到内网、回环或链路本地地址，会被拒绝：AI 接口地址返回 `common.egress_blocked`，Canvas
地址返回 `lms.blocked_address`。Canvas 返回的每个重定向目标也要通过同样的检查。

## 本机 OCR

默认镜像（标签以 `-local` 结尾）在服务器上用 [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)（ONNX Runtime，只用
CPU）识别扫描版 PDF 和照片，不会为此调用 AI 模型。每个用户可以在 AI 设置 → 模型的 **OCR** 一行里选择本机的 PaddleOCR
模型（默认是下表的模型），也可以改用某个服务商的模型。支持 amd64 与 arm64（包括 Apple Silicon 上的 Docker）。识别时在应用
本身约 1 GB 之外再占用最多 2 GB 内存，一次处理一个文档，默认模型每页约 2 秒。

镜像里不带模型。每个模型在第一次用到时（用户选中它，或有扫描文件要识别）从 Hugging Face（或 PaddleOCR 的其他镜像源）下载到
数据卷，应用会在 AI 设置和文件状态里显示下载进度。所有用户共用下载好的模型，升级后也不用重新下载。服务器之后不能联网的话，
请趁还能联网时先下载：

```sh
docker compose exec semestra semestra ocr-models --all
```

要换成不带它的小镜像，在 `.env` 里写 `SEMESTRA_IMAGE_VARIANT=`（留空），再运行 `docker compose up -d`；用户之后在 **OCR**
和**搜索**一行里选服务商的模型。改回 `-local` 即可换回来。

| 变量                       | 默认值              | 含义                                                         |
| -------------------------- | ------------------- | ------------------------------------------------------------ |
| `SEMESTRA_LOCAL_OCR`       | `-local` 镜像里为 `true` | 在服务器上识别扫描页                                      |
| `SEMESTRA_LOCAL_OCR_MODEL` | `PP-OCRv6_medium`   | 默认模型：`PP-OCRv6_tiny`、`_small`、`_medium`、`PP-OCRv5_mobile`、`PP-OCRv5_server` |
| `SEMESTRA_LOCAL_OCR_PAGE_TIMEOUT_SECONDS` | `60` | 每页允许的时间（另加两分钟加载模型）；CPU 很慢时调大 |

## 本机 embedding

默认镜像还会在服务器上把文本转成用于搜索的向量，所以不接 AI 服务商也能用**搜索**。它用 ONNX Runtime（只用 CPU）运行
Hugging Face 上的 [ONNX](https://onnx.ai) 模型。每个用户可以在 AI 设置 → 模型的**搜索**一行里选择：

| 模型                    | 说明                                                       |
| ----------------------- | ---------------------------------------------------------- |
| `multilingual-e5-small` | 默认。最小最快：Apple M3 上每秒约 20 段，内存最多约 2 GB |
| `bge-m3`                | 均衡，中英文都好，需要更多内存                             |
| `qwen3-embedding-0.6b`  | 最准确，较慢                                               |

也可以直接输入任何带 ONNX 版本（有 `onnx/` 文件夹和 `tokenizer.json`）的 Hugging Face 模型名，例如
`BAAI/bge-small-zh-v1.5`。模型和 OCR 模型一样，第一次用到时下载到数据卷；下载完成前文件仍可按关键词搜索，下载后会自动补上
向量。换模型后会在后台重建向量。想提前下载：

```sh
docker compose exec semestra semestra embedding-models --all
```

模型常驻在单独的进程里，空闲十分钟后退出。Docker 用不了 Mac 的 GPU，而经 ONNX Runtime 调用 Core ML 在我们的测试里会占用
几十 GB 内存，所以这里只用 CPU。想用 GPU 加速，可以在宿主机上运行 [Ollama](/docs/ai/ollama)，改选它的 embedding 模型。

| 变量                              | 默认值                     | 含义                                             |
| --------------------------------- | -------------------------- | ------------------------------------------------ |
| `SEMESTRA_LOCAL_EMBEDDING`        | `-local` 镜像里为 `true`   | 在服务器上计算向量                               |
| `SEMESTRA_LOCAL_EMBEDDING_MODEL`  | `multilingual-e5-small`    | 默认模型（上表之一，或 Hugging Face 模型名）     |
| `SEMESTRA_LOCAL_EMBEDDING_CUSTOM` | `true`                     | 允许用户添加 Hugging Face 模型；多人共用的服务器可关掉以节省磁盘 |
| `SEMESTRA_LOCAL_EMBEDDING_MAX_GB` | `3`                        | 用户可添加的 Hugging Face 模型的大小上限         |
| `SEMESTRA_LOCAL_EMBEDDING_THREADS` | `0`                       | CPU 线程数（0 表示核数的一半）                   |
| `SEMESTRA_LOCAL_EMBEDDING_IDLE_SECONDS` | `600`                | 闲置这么久后卸载模型                             |

## 后台任务与备份

| 变量                       | 默认值 | 含义                                       |
| -------------------------- | ------ | ------------------------------------------ |
| `SEMESTRA_JOB_CONCURRENCY` | `2`    | 进程内后台任务的并发数                     |
| `SEMESTRA_BACKUP_DIR`      | （空） | 设置后每天自动备份到这个目录               |
| `SEMESTRA_BACKUP_KEEP`     | `7`    | 保留的数据库快照数                         |

## 密钥与日志

| 变量                       | 默认值   | 含义                                                   |
| -------------------------- | -------- | ------------------------------------------------------ |
| `SEMESTRA_SECRET_KEY`      | 自动生成 | 签发会话和令牌                                         |
| `SEMESTRA_ENCRYPTION_KEY`  | 自动生成 | 加密已保存的服务商密钥和 Canvas 令牌的 Fernet 密钥     |
| `SEMESTRA_LOG_LEVEL`       | `INFO`   | 日志级别                                               |
| `SEMESTRA_SENTRY_DSN`      | （空）   | 把错误报告给 Sentry；为空则关闭                        |

只有在 `SEMESTRA_AUTO_SECRETS=true` 时容器才会生成密钥，compose 文件已经设置了它。`SEMESTRA_SKIP_MIGRATIONS=true`
会在启动时跳过迁移。
