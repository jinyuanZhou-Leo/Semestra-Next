---
title: 不用 Docker，部署到小型 VM
description: 在 1 GB 内存的 VM 上用 uv 和 systemd 运行 API，网页应用放在静态托管上。
---

托管版就是这样跑在 Google Cloud 免费的 e2-micro 上的：API 在 VM 上用 uv + systemd 运行，网页应用在
Vercel。脚本和完整的操作手册在
[`deploy/vm`](https://github.com/jinyuanZhou-Leo/Semestra-Next/tree/main/deploy/vm)。它们是按 Google Cloud
和 Cloudflare 写的，但各个部分在任何 Debian VM 上都能照搬。

## 各部分在哪里

| 部分 | 位置 |
|---|---|
| 网页应用 | 静态托管（`apps/web`，构建时把 `VITE_API_ORIGIN` 设为 API 地址；Vercel 用的 SPA 回退和安全头在 `apps/web/vercel.json`） |
| API | `semestra serve` 监听 `127.0.0.1:8000`，systemd 服务，代码在 `/opt/semestra/current` |
| 数据 | `/var/lib/semestra`：SQLite 数据库和上传的文件 |
| 对外访问 | Cloudflare Tunnel 连到 `127.0.0.1:8000`（不开端口，也不需要 IPv4 地址） |
| 备份 | Litestream 把数据库持续复制到 Google Cloud Storage，每日定时器镜像文件 |

## 网页应用和 API 用两个域名

两者要在同一个可注册域名下（例如 `app.example.com` 和 `api.example.com`），这样它们属于同一站点，会话
Cookie 才能用。然后在 API 的环境文件里：

```bash title="/etc/semestra/semestra.env"
SEMESTRA_PUBLIC_WEB_ORIGIN=https://app.example.com
SEMESTRA_PUBLIC_API_ORIGIN=https://api.example.com
SEMESTRA_CORS_ORIGINS=["https://app.example.com"]
SEMESTRA_COOKIE_DOMAIN=example.com     # 网页应用要读取 CSRF Cookie
SEMESTRA_SERVE_WEB=false
SEMESTRA_TRUSTED_PROXY_HOPS=1          # Cloudflare -> cloudflared -> API
```

API 通过工作目录里指向这个文件的 `.env` 符号链接读取配置，所以服务本身和部署时的命令（迁移、
`semestra backup`）看到的是同一份值。

## 1 GB 内存的配置

- 加 2 GB swap（初始化脚本会做）。
- `SEMESTRA_JOB_CONCURRENCY=1`，`SEMESTRA_FILES_PARSE_MEMORY_BYTES=1073741824`。
- 网页应用在别处构建，VM 上只安装锁定版本的 Python 依赖。

## 只有 IPv6 的 VM

Google Cloud 的免费层不包括 IPv4 地址，IPv6 不收费。没有 IPv4 时，VM 能访问有 IPv6 地址的服务（PyPI
和大多数 AI 服务商），但访问不了只有 IPv4 的服务，比如 Canvas、GitHub 和部分 AI 服务商。操作手册里让
Cloudflare WARP 只接管 IPv4 流量，代码则从你的电脑经 IAP 拷过去，而不是在 VM 上克隆。
