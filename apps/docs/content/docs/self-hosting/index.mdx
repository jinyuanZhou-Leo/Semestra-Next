---
title: Run with Docker Compose
description: One container serves the API and the web app. Start it, sign in, upgrade it.
---

The `semestra-allinone` image serves the API and the web app from one origin on port 8000. All
data lives in one Docker volume. You need Docker with the Compose plugin and about 1 GB of RAM.

## Start

<Steps>
<Step>

### Get the compose file

```bash
git clone https://github.com/jinyuanZhou-Leo/Semestra-Next.git
cd Semestra-Next/deploy/selfhost
cp .env.example .env   # optional, every setting has a default
```

</Step>
<Step>

### Get the image

The repository and its images are private for now. Either sign in to the registry with a GitHub
token that has `read:packages`:

```bash
docker login ghcr.io
```

or build the image yourself from the repository root:

```bash
docker build -f deploy/docker/Dockerfile --target allinone \
  -t ghcr.io/jinyuanzhou-leo/semestra-allinone:latest .
```

</Step>
<Step>

### Start it

```bash
docker compose up -d
```

Open `http://localhost:8000` (or `http://<server-ip>:8000`). On the first start the container
generates its keys, migrates the database and starts; this takes under a minute.

</Step>
<Step>

### Sign in

Enter your email address. Until you [configure email](./email.mdx), the verification code is
printed in the log:

```bash
docker compose logs -f semestra
```

</Step>
</Steps>

## Back up the generated keys

On the first start the container writes `/data/secrets.env` with `SEMESTRA_SECRET_KEY` (signs
sessions and tokens) and `SEMESTRA_ENCRYPTION_KEY` (encrypts the AI and Canvas keys your users
save). Values you set in `.env` take precedence.

<Callout type="warn">
  Without `SEMESTRA_ENCRYPTION_KEY` the saved provider keys and Canvas tokens can no longer be
  decrypted. Copy the file somewhere safe.
</Callout>

```bash
docker compose cp semestra:/data/secrets.env ./secrets.env.backup
```

## Upgrade

```bash
docker compose pull && docker compose up -d
```

Database migrations run on every start (`alembic upgrade head`) and only move forward, so
[take a backup](./backup.mdx) first. To stay on one version instead of `latest`, set
`SEMESTRA_VERSION=1.2.0` in `.env`.

## Health checks

| Path       | Answers                                                                        |
| ---------- | ------------------------------------------------------------------------------ |
| `/healthz` | `{"status": "ok"}` while the process is up                                     |
| `/readyz`  | `ok` once the database answers and the background worker runs, otherwise `503` |

The image has a Docker `HEALTHCHECK` built in.

## Troubleshooting

| Symptom                                                  | Check                                                                                         |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| The container keeps restarting                           | `docker compose logs semestra`                                                                |
| "SEMESTRA_SECRET_KEY and SEMESTRA_ENCRYPTION_KEY must be set in prod" | `SEMESTRA_AUTO_SECRETS` was removed from the compose file and no keys are set     |
| Signing in fails over plain HTTP from another machine    | Set `SEMESTRA_PUBLIC_URL` to the exact address you open, or [enable HTTPS](./https.mdx)        |
| Permission errors on a bind mount                        | `sudo chown -R 10001:10001 <dir>`: the container runs as uid 10001                            |

## Not available yet

Single-user mode (`SEMESTRA_SINGLE_USER`, where the first visitor becomes the admin and sign-up
closes) is planned but not implemented: the variable is accepted and has no effect. Once real
email is configured, anyone who can reach your instance can create an account with their email
address, so keep it on a private network or behind your own access control for now.
