These tools are for development only and never ship in the production image.

## Checks before you push

```bash
pnpm check            # run the checks CI would run for this change
pnpm check --list     # only list the jobs it would run
pnpm check --only api,web
```

`pnpm check` reads `.github/workflows/ci.yml` itself: it treats the working tree (uncommitted and untracked files included) as one commit, compares it with the merge base of `origin/main`, picks jobs with the same path filters and runs each job's steps in order, with tests narrowed to the affected ones as on a pull request. Draft PRs skip CI, so run it before marking a PR ready for review.

It differs from CI in two places: dependency installs are skipped, and the "nothing to regenerate" check (`git diff --exit-code`) looks at whether the job's earlier steps changed any files, so uncommitted work is fine.

The script only understands the forms `ci.yml` uses today. If a change to `ci.yml` adds a new `if:` condition, step field or `${{ }}` expression, `pnpm check` stops and points at it; update `scripts/check.py` to match.

## Cloud sessions

`.claude/hooks/session-start.sh` prepares Claude Code cloud sessions: it installs the Node 26 that CI uses and the pnpm version `packageManager` pins, installs both dependency trees, and points `CHROME` at the Chromium that ships with the image. Installs are skipped when no dependency file changed. On a local machine it does nothing.

The Paraglide plugin is a dev dependency in `apps/web/node_modules`, and `project.inlang/settings.json` points at it, so compiling messages needs no CDN.

## Screenshots and requests

Both scripts open pages in a signed-in Chromium against a running Semestra. They default to the demo account, so start `pnpm dev:demo` first, or pass `--email` and `--password` for your own account on `pnpm dev`.

```bash
pnpm --filter @semestra/web shot /p/{program}/today /p/{program}/c/{course:ECE201H1}/grades
pnpm --filter @semestra/web requests /p/{program}/today
```

Paths can use `{program}`, `{term}`, `{course}` and `{course:CODE}`, filled from the account's data.

- `shot` saves each page in light and dark, in Chinese, at 2x, to `apps/web/.shots/`. The account's theme and language are switched for the shots and put back afterwards, and the clock is frozen so both themes show the same times. `--locale`, `--themes`, `--width`, `--height` and `--out` change the defaults.
- `requests` lists the API requests a page makes when it opens: the count and slowest time per route, failures, and requests made more than once. Use it to check a change doesn't add requests or fetch the same data twice.
