# M10 插件与布局（Plugins, Pages, Cards, Command Palette）

> 依赖：M00（扩展契约）、M01、M02（作用域）、M11（插件设置分区宿主）。被依赖：所有贡献 Page/Card 的模块、M14、M16。
> 本模块解决旧版"Widget、Tab 逻辑混乱"的问题：把 M00 的扩展契约做成完整的用户体验。

## 1. 目标与功能对齐
旧版功能（保留）：
- 插件市场：浏览插件、查看详情、启用/停用。
- 仪表盘小部件：添加（选择器）、拖拽布局、调整大小、删除、每实例设置、头部操作按钮。
- Tab：添加、排序、删除、按作用域显示。
- 斜杠命令/命令面板：切换 Tab、跳到课程、打开小部件选择器；全局命令中心带分组、搜索相关度排序、子页面导航。
- 插件不可用时的统一空状态，插件错误隔离（错误边界）。

新版模型（取代旧版的 Program 安装 / 学期激活 / 课程激活三层和三张 Tab 表）：
- **一层安装**：插件按账户安装（`plugins_installations`）。核心模块不可卸载。
- **Page**：作用域页面（原 Tab）。由模块静态声明，不是用户创建的实例；用户只能**排序和隐藏**，按**作用域类型**统一保存（所有课程共用一个顺序）。
- **Card**：概览网格中的卡片（原 Widget）。是用户创建的**实例**，按**作用域实例**保存布局（每个学期、每门课各自一份），新作用域从用户的"默认布局模板"初始化。
- 插件配置统一存 M11 的 `settings_values`（命名空间 `plugin.<id>`）。

## 2. 领域模型
```
plugins_installations
  user_id, plugin_id, installed_at, PRIMARY KEY (user_id, plugin_id)
  # 首次登录时写入默认安装的插件：default_installed=true 的插件（见 M14、M16）

layouts_nav                        # Page 顺序与隐藏，按作用域类型
  user_id, scope_type ('program'|'term'|'course'), order JSON [page_id], hidden JSON [page_id],   # Page 只存在于这三种作用域；'today' 不参与（今天是 program 作用域下的固定 Page）
  PRIMARY KEY (user_id, scope_type)

layouts_boards                     # 卡片布局，按作用域实例
  id, user_id, scope_type ('program'|'term'|'course'|'today'), scope_id, cards JSON [{instance_id, card_id, size, x, y}], updated_at
  # scope_type='today' 时 scope_id 为 program_id（M04 的"今天"页面）；layouts_templates 与 layouts_card_settings 的 scope_type 取值相同
  UNIQUE(user_id, scope_type, scope_id)

layouts_templates                  # 用户的默认布局模板，按作用域类型
  user_id, scope_type, cards JSON [{card_id, size, x, y, settings?}], PRIMARY KEY (user_id, scope_type)

layouts_card_settings              # 卡片实例设置（例如便签内容、要显示的待办列表）
  instance_id (PK), user_id, card_id, scope_type, scope_id, settings JSON, updated_at
```
- 卡片实例的**业务数据**（例如习惯打卡记录）由提供该卡片的模块自己存，以 `instance_id` 关联；卡片删除时发布 `layouts.card.deleted` 事件，模块清理数据。
- 内置默认模板（用户没有自定义模板时使用）由各模块在 manifest 中声明 `defaultBoard: {scope_type: [{card_id, size}]}`，宿主按模块顺序拼接。

## 3. 后端插件目录
- `modules/plugins/catalog.py`：后端维护插件清单（从各插件后端包的 `PLUGIN = PluginInfo(id, kind, name_key, description_key, version, author, default_installed, provides: {pages, cards, capabilities})` 汇总）。前端 manifest 的 id 必须与之一致；CI 测试比对前端 manifest 列表与 `/plugins/catalog` 输出。
- `plugins.require_installed(ctx, plugin_id)`：M00 capability 框架在调用带 `plugin_id` 的 capability 前调用。

## 4. Capabilities
| name | effect | http | 说明 |
|---|---|---|---|
| `plugins.catalog.list` | read | GET /plugins/catalog | 含是否已安装 |
| `plugins.install` | write | PUT /plugins/{plugin_id}/installation | 发布 `plugins.installed` |
| `plugins.uninstall` | destructive | DELETE /plugins/{plugin_id}/installation | 不删除插件数据（重新安装后恢复）；参数 `purge_data=true` 时发布 `plugins.purge` 由插件清理；从所有 board 中移除该插件卡片 |
| `layouts.nav.get/update` | read/write | /layouts/nav/{scope_type} | |
| `layouts.board.get` | read | GET /layouts/boards/{scope_type}/{scope_id} | 不存在时按模板生成（不落库，首次修改时落库） |
| `layouts.board.update` | write | PUT /layouts/boards/{scope_type}/{scope_id} | 整体替换卡片列表（位置与尺寸），服务端校验 card_id 存在、尺寸被支持、插件已安装 |
| `layouts.card.add` | write | POST /layouts/boards/{scope_type}/{scope_id}/cards | 返回 instance_id |
| `layouts.card.remove` | write | DELETE /layouts/cards/{instance_id} | |
| `layouts.card.settings.get/update` | read/write | /layouts/cards/{instance_id}/settings | 设置用卡片声明的 schema 校验（schema 由后端插件包提供 Pydantic 模型；纯前端卡片使用 JSON Schema，由前端 zod 导出并在构建时生成到后端） |
| `layouts.template.save_from_board` | write | POST /layouts/templates/{scope_type}:from-board | 把当前布局设为默认 |
| `layouts.template.reset` | write | DELETE /layouts/templates/{scope_type} | |

Agent：只暴露 `plugins.catalog.list`、`layouts.card.add`、`layouts.card.remove`、`layouts.board.get`（"在这门课的概览里加一个便签"）。
事件：`plugins.installed|uninstalled|purge`、`layouts.*`、`layouts.card.deleted`。
订阅：`academics.term.deleting`、`academics.course.deleting`（删除对应 board 与卡片实例，逐个发布 `layouts.card.deleted`）。

## 5. 前端
### 5.1 作用域页面栏
- 页头标签栏显示当前作用域的可用 Page（模块已安装、`isAvailable(scope)` 为真、未隐藏），按 `layouts_nav.order`（未出现在 order 中的新 Page 追加到末尾）。
- 标签栏末尾"⋯"菜单：管理页面（拖拽排序、显示/隐藏开关；说明"对所有学期/所有课程生效"）。
- Page 组件包在 `PluginBoundary`（错误边界 + Suspense 骨架 + 统一不可用空状态）中。

### 5.2 卡片网格（Board）
- 4 列 CSS Grid，行高固定（160px），尺寸 s=1×1、m=2×1、l=2×2、xl=4×2；窄屏（<1024px）2 列，xl 占满一行；手机 1 列。
- 实现：`@dnd-kit` 拖拽 + 自研紧凑布局算法（按 y、x 排序后自上而下放置，拖动时实时预览、其它卡片让位），不依赖 react-grid-layout。
- **编辑模式**（页面右上角"编辑"按钮或 `E` 键）：卡片抖动态显示拖拽手柄、尺寸切换（只显示该卡片支持的尺寸）、设置、删除；顶部出现"添加卡片"与"设为默认布局 / 恢复默认"；退出编辑模式时一次性 `layouts.board.update`（编辑过程中本地状态，失败回滚并提示）。离开页面时自动退出编辑模式。
- **添加卡片**对话框：按模块分组的卡片目录（图标、名称、描述、支持尺寸预览），搜索；只列出当前作用域支持且已安装的；`multiple=false` 的卡片已存在时灰显。
- 卡片外框统一（标题、图标、头部操作区 `headerActions`、设置入口），内容区由卡片组件渲染；卡片组件不得自绘外框。
- 卡片设置：卡片声明了 `settings.component` 时用自定义组件，否则根据 zod schema 自动生成表单（TanStack Form）。

### 5.3 插件管理（账户设置分区"插件"，M11 宿主）
- 插件目录网格：图标、名称、简介、作者、"已安装"标记；核心模块单独一栏只读展示（说明"核心功能，无法卸载，可在页面管理中隐藏"）。
- 详情页：描述、提供的页面与卡片列表（带预览图）、所需权限（例如 Canvas Tab 的"需要先添加 Canvas 连接并关联课程"）、安装/卸载按钮（卸载对话框可选"同时删除插件数据"）。
- 插件自己的全局设置分区（M11 `level: 'account'` 且带 `pluginId`）在详情页下方渲染：用 `<PluginSettingsSections pluginId={…} />`（`@/app/settings`）。这些分区不会出现在设置页的导航里。

### 5.4 命令面板（`Cmd/Ctrl + K`）
- 根列表分组：**导航**（各作用域 Page、学期、课程——课程按 code/title/alias 模糊匹配，最近访问优先）、**操作**（模块贡献的 `CommandContribution`，按当前作用域过滤，如"添加考核"、"新建任务"、"导入 syllabus"、"添加卡片"）、**搜索结果**（模块贡献的 `searchProviders`：任务、考核、文件内容等，输入 2 个字符后异步查询，防抖 150ms）、**问 AI**（把输入作为问题发送给 M12 助手）。
- 子页面：命令可声明 `children` 以进入二级列表（例如"切换学期 →"）。
- 排序：无输入时按"推荐"（当前作用域相关 + 最近使用）；有输入时按相关度（前缀 > 单词前缀 > 子串 > 拼音首字母匹配，中文课程名支持拼音首字母，使用 `pinyin-pro`）。
- 最近使用记录存 `useUiPref('commands.recent')`。
- 斜杠命令：在命令面板输入 `/` 只显示操作类命令。

### 5.5 全局快捷键
`Cmd/Ctrl+K` 命令面板、`Cmd/Ctrl+J` AI 助手（M12）、`E` 编辑当前 Board、`G` 然后 `T` 跳到今天（M04）、`Cmd/Ctrl+↑↓` 切换课程（M02）、`?` 显示快捷键帮助。快捷键注册表由本模块提供（`useHotkey`），在输入框聚焦时不触发单键快捷键。

### 5.6 状态条（StatusBar）
- 侧边栏底部（设置与账户菜单上方）渲染 M00 扩展点 `statusItems` 的所有贡献，按 `order` 排列；每项一行：图标、一行文字（过长截断并带 `title`）、可选 2px 细进度条，点击跳转 `to`。折叠为图标栏时只显示图标，悬停显示文字。
- 宿主自带 `core.jobs` 项：汇总当前用户进行中的后台任务（`core.job.list`，SSE `core.job.progress` 更新）；一个任务时显示“阶段文案 + 百分比”，多个时显示“N 个任务进行中”，点击展开列表（任务名、`<JobProgress>`、终止按钮、点击跳转到来源页面，如导入审核界面）。完成的任务短暂显示完成状态（约 3 秒）后移除，失败任务保留直到用户查看。
- 没有任何进行中的项时整条状态条不渲染，不留空位。
- 窄屏（<768px）状态条显示在抽屉底部。

## 6. 错误码
`plugins.not_installed`（params: plugin_id）、`plugins.core_not_removable`、`layouts.card_unknown`、`layouts.size_unsupported`、`layouts.card_not_multiple`、`layouts.scope_mismatch`。

## 7. 测试
- 插件未安装时 capability 被拒、不出现在 agent 列表、前端 Page/Card 不出现。
- 卸载：卡片从所有 board 移除；`purge_data` 时插件收到事件；重装后非 purge 数据恢复。
- Board：模板初始化不落库、首次修改落库；删除作用域清理卡片并发布事件；非法尺寸被拒。
- 前后端插件清单一致性测试。
- 前端：拖拽布局算法单元测试（放置、让位、紧凑）；编辑模式失败回滚；命令面板相关度与拼音匹配。

## 8. 验收
- 用户能在一门课的概览中进入编辑模式，添加便签与番茄钟卡片、调整大小和位置，保存后刷新不变；把这个布局设为默认后，新课程使用同样的布局。
- 隐藏"文件"页面后所有课程都不再显示该标签。
- 在"今天"页面进入编辑模式，添加番茄钟与便签卡片，保存后刷新不变；课程概览的卡片目录里不出现仅限 `today` 作用域的卡片。

## 9. 实现说明（与上文的偏离与补充）
- **插件目录的来源**：没有每个插件后端包里的 `PLUGIN = PluginInfo(...)`。目录由两部分合并：前端导出的 `modules/plugins/web_manifest.json`（模块 kind、Page、卡片的作用域/尺寸/设置 JSON Schema、`defaultBoard`；用 `pnpm --filter @semestra/web manifest:export` 生成，过期时前端测试失败）与后端 `register_plugin(PluginInfo(...))`（kind 为 `plugin` 的模块必须注册，带 `default_installed`；核心模块可选）。后端测试检查两边一致。`/plugins/catalog` 的 `provides.capabilities` 来自 capability 的 `plugin_id`。
- **插件门禁**：`core/capability.py` 新增 `set_plugin_gate`；带 `plugin_id` 的 capability 在未安装时返回 403 `plugins.not_installed`，且不出现在 agent/MCP 工具列表（`registry.available(ctx, expose)`）。
- **默认安装**：新增表 `plugins_default_offers` 记录"已经给这个用户装过一次"，读目录时懒写入。这样用户卸载默认插件后不会被重新装上，后来新增的默认插件也能装给老用户。
- **Board**：没有存储时按模板生成，实例 id 形如 `tpl.<scope_type>.<scope_id>.<n>.<card_id>`；第一次修改时落库，这些 id 原样成为真实 id（前端已拿到的 id 不失效）。新增 capability `layouts.template.get`（编辑模式的"恢复默认"用它）。
- **卡片设置校验**：后端用 `register_card_settings(card_id, PydanticModel)` 注册的模型；没有时用前端 zod 导出的 JSON Schema（`layouts/jsonschema.py` 的精简校验器：类型、必填、枚举、范围、长度）；卡片没有设置时只接受 `{}`。
- **卸载**：插件卡片在所有 board 上隐藏但保留，重装后恢复；`purge_data=true` 时删除卡片与设置并发布 `plugins.purge`。订阅了 `academics.program|term|course.deleting`（program 删除时清理 today board）。
- **前端结构**：Board 在 `app/board/`（`Board`、`CardFrame`、`AddCardDialog`、`CardSettingsDialog`、紧凑算法 `layout.ts`，`useCardSettings` 从 `@/app/board` 导出）；页面栏排序/隐藏在 `app/host/nav.ts` 与 `ManagePagesDialog`（概览页不能隐藏）；插件管理是核心模块 `modules/plugins`（账户设置分组"插件"）；已安装过滤由 `_authed` 布局里的 `InstalledPluginsProvider` 提供，`useModules()` 只返回核心模块与已安装插件，`useAllModules()` 返回全部。
- **命令面板与快捷键**：`app/commands/`（cmdk，匹配排序在 `rank.ts`，拼音首字母用 `pinyin-pro`），快捷键 `app/hotkeys.ts` 基于 `react-hotkeys-hook`（`useHotkey` 注册并进入 `?` 帮助列表，`useListedHotkey` 只列出）。扩展契约新增：`CommandContribution.isAvailable/hotkey`、`navigationSources`（导航分组的条目，M02 贡献学期与课程）、`assistant`（M12 实现 `open(ctx, question?)` 后 `Cmd/Ctrl+J` 与"问 AI"自动出现）、`jobKinds`（状态条里任务的名称与跳转）。命令要操作页面上的东西（编辑布局、添加卡片、管理页面）时用 `useHostAction`/`runHostAction`。
- **窄屏编辑**：窄于 1024px 时也能进入编辑模式（改尺寸、增删、设置），但不能拖动位置（窄屏按阅读顺序排布）。
- **状态条**：任务列表读 `core.job.list`（进行中与排队中的任务全部读取，另取最近 20 条已结束的），成功的任务显示约 3 秒，失败的任务在用户打开列表后才消失（已看过的失败记在 UI 状态 `layout.status_seen_failures`）。
- **shadcn 组件**：`ui/command.tsx`、`input-group.tsx`、`kbd.tsx`、`toggle.tsx`、`toggle-group.tsx` 取自 `claude/shadcn-all-components` 分支（CLI 生成，内容相同，合并不冲突）。
