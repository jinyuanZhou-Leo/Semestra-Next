# M13 数据导出、导入与账户删除

> 依赖：M00、M01、M11，以及所有存储用户数据的模块（每个模块实现自己的导出/导入适配器，本模块负责框架与界面）。
> 建议在 M02–M12 完成后实现；但**导出/导入适配器接口**在本模块开始前就应由各模块按本文第 3 节实现（各模块 spec 的验收中不强制，本模块实现时补齐缺失的适配器）。

## 1. 目标与功能对齐
旧版功能（保留）：
- 导出账户数据（备份文件）。
- 从备份恢复：拖放文件 → 预览内容（Program、LMS 连接、资源、待办、账户设置）→ 冲突处理策略 → 确认导入；可选是否导入账户设置。
- 删除账户：危险区域，确认对话框中输入确认语句后才能删除。

新版：
- 备份格式版本化（`semestra-backup` v1），不兼容旧版备份（明确拒绝旧格式并提示）。
- 备份可选是否包含文件（文件打包进 zip）。
- **不导出任何密钥**（AI key、LMS 凭证、PAT、会话），导入后需要重新填写。
- 导出为后台任务，完成后提供下载链接（24 小时有效）。

## 2. 备份格式
`semestra-backup-<date>.zip`：
```
manifest.json      { format: "semestra-backup", version: 1, exported_at, app_version,
                     modules: { "<module>": <module schema version> }, include_files: bool,
                     counts: { programs, terms, courses, ... } }
data/<module>.json # 每个模块一个文件，内容由模块适配器定义（Pydantic 模型，带 schema_version）
files/<file_item_id>   # 原文件（include_files=true 时）
```
- 所有对象保留原 id；引用关系用原 id 表达。导入时统一重映射。
- 时间统一 ISO 8601 UTC。

## 3. 模块适配器接口
```python
register_portability(
    module="grading",
    schema_version=1,
    depends_on=("academics",),           # 导入顺序
    export=async def (ctx, writer) -> None,         # writer.write_json(obj), writer.add_file(key, stream)
    import_=async def (ctx, payload, id_map, options) -> ImportReport,  # id_map: 跨模块 id 重映射表
    preview=async def (payload) -> dict[str, int],  # 计数
    purge=async def (ctx) -> None,                  # 删除该用户在本模块的全部数据（账户删除与"替换导入"使用）
)
```
- 每个存储用户数据的模块都必须注册（包括 M09 与插件 M14；M16 没有自己的数据）。CI 测试：遍历所有带 `user_id` 列的表，确认其所属模块已注册适配器，且 `purge` 后该表中该用户行数为 0。
- 插件未安装时其数据仍然导出；导入时插件数据照常写入（插件未安装则保持隐藏）。

## 4. 导入
- 上传 zip（≤ 配额 + 50MB 的独立上限）→ 校验 manifest（格式、版本；不支持的版本返回 `portability.unsupported_version`）→ 生成预览：每个模块的计数、Program 列表（名称、学期数、课程数）、是否含文件及大小、是否超出存储配额。
- 选项：
  - **模式**：`merge`（作为新数据追加，所有 id 重新生成；Program 同名时在名称后加"（导入）"）或 `replace`（先 purge 当前账户全部业务数据，再导入；需要输入确认语句）。
  - 选择要导入的 Program（默认全部）。
  - 是否导入偏好与界面布局（默认否）。
- 执行：后台 job，分两阶段。先在事务外调用各模块的 `prepare`，把备份里的文件复制进存储（这一步可能很久，不能占着 SQLite 的写锁）；再按 `depends_on` 拓扑顺序调用各模块 `import_`，**所有行在一个数据库事务中**写入。失败则删除已复制的文件。
- 报告：每个模块导入数量、跳过项与原因。

## 5. 账户删除
- 前置：最近 10 分钟内登录过（否则要求重新验证：邮箱验证码或密码）。
- 确认：输入本地化的确认语句（中文"删除我的账户"，英文"delete my account"），并勾选"我已了解此操作无法撤销"。
- 执行：撤销所有会话与 PAT → 按依赖逆序调用所有模块 `purge` → 删除存储中 `users/<user_id>/` 下全部对象 → 删除 `auth_*` 行 → 发送"账户已删除"邮件（发送到原邮箱）。整个过程为后台 job，前端立即登出并显示"账户正在删除"页面。
- 删除不可恢复；不保留软删除副本。日志中只保留 user_id 与时间。

## 6. Capabilities 与路由（全部 `expose=("http",)`，不对 agent/MCP 开放）
| name / 路由 | 说明 |
|---|---|
| `portability.export.start` POST /me/exports | 参数 include_files；返回 job |
| `portability.export.list` GET /me/exports | 最近的导出及下载状态 |
| GET /me/exports/{id}/download | `routes.py`，下载 zip |
| POST /me/imports（multipart） | 上传并返回预览 |
| `portability.import.start` POST /me/imports/{id}:start | 选项见第 4 节；返回 job |
| `portability.import.discard` DELETE /me/imports/{id} | |
| `account.delete` POST /me:delete | 确认语句 + 勾选；返回 job |

## 7. 前端（账户设置"数据"分区）
- **导出**：说明（包含什么、不包含密钥）、"包含文件"开关（显示文件总大小）、导出按钮 → 进度 → 完成后下载按钮（并列出最近导出）。
- **从备份恢复**：拖放区 → 预览面板（计数表、Program 勾选列表、模式选择、偏好开关、配额警告）→ 确认（replace 模式需输入确认语句）→ 进度 → 结果报告。
- **危险区域**：删除账户按钮 → 对话框（后果说明、确认语句输入、勾选框、必要时重新验证）。

## 8. 错误码
`portability.invalid_archive`、`portability.unsupported_version`（params: version）、`portability.legacy_backup`（检测到旧版 Semestra 备份格式）、`portability.too_large`、`common.quota_exceeded`、`portability.confirmation_mismatch`、`auth.reauth_required`。

## 9. 测试
- 往返测试：构造覆盖所有模块的数据集 → 导出 → 新账户 merge 导入 → 逐模块比较（忽略 id 与时间戳）。
- replace 模式：原数据完全被替换；中途失败整体回滚、存储暂存清理。
- 密钥不出现在导出文件中（扫描 zip 内容中的已知密钥字符串）。
- 账户删除后：所有带 user_id 的表无该用户数据、存储目录不存在、PAT 与会话失效。
- 旧版备份文件被识别并拒绝。

## 10. 验收
- 在一个账户导出（含文件）后，在另一个账户导入，界面与数据完全一致（除需要重新填写的密钥）。

## 11. 实现说明（与上文的偏离与补充）

**框架**（`apps/api/src/semestra/modules/portability/`）
- `registry.py`：`register_portability(module, schema_version, depends_on, export, import_, preview, purge, purge_content=None, tables=())`。比第 3 节多两项：`tables` 是该适配器负责的表名（覆盖测试用），`purge_content(ctx, preferences)` 是"替换导入"要清掉的数据（默认等于 `purge`）。`id_map` 是 `IdMap`：除了旧 id → 新 id，还有 `excluded`（有意不导入的行，如没勾选的 Program，它的下级行静默略过，不算"跳过"）。
- `tables.py`：`table_adapter(module=…, tables=(Table(Model, "key", refs={...}), ...))` 按表描述生成适配器。引用列分 `required`（目标没导入就丢弃该行）、`optional`（置空）、`scope`（`''`/空表示账户级，其余同 required）；其它字符串与 JSON 里出现的已映射 UUID 会被自动替换（卡片列表、设置数据、界面状态的键）。`exclude` 列不导出（密钥），`exported=False` 的表只随账户删除，不导出也不被替换导入清掉，`preferences` 标记偏好行，`upsert_on` 让导入覆盖同自然键的已有行。
- main 上每个模块都在自己的 `portability.py` 注册：academics、grading、schedule、settings、layouts、plugins、ai；插件沿用 `plugins_builtin/portability.py`，在 `plugins_builtin/__init__.py` 注册并列出表。
- **id 一律重新生成**（替换模式也是）：主键全局唯一，同一份备份可能导入别的账户。
- **偏好开关**覆盖：`settings_preferences`、`settings_ui_state`、账户级 `settings_values`、`layouts_nav`/`layouts_templates`、插件安装记录、AI 服务商与模型分配。看板与卡片实例（含便签等卡片内容）随所在的 Program/学期/课程导入，不算偏好。
- **不导出**：AI 用量记录、ICS 订阅链接（令牌是凭证）。AI 服务商导出时去掉密钥、`key_hint` 与检测状态，原来有密钥的服务商导入后为停用状态。
- 合并导入时 Program 重名加"（导入）"/" (imported)"（按请求语言）。
- 文件：适配器的 `prepare(ctx, payload, id_map, options)`（`register_portability(prepare=...)`）在写任何行之前调用 `options.files.store(archive_key, final_key, content_type)`，直接写到正式 key；需要新行 id 的 key 先在 `IdMap` 里预分配（`id_map.setdefault(old_id, new_id())`，`table_adapter` 会沿用）。`import_` 里对保留下来的文件调用 `options.files.claim(final_key)`，拿到大小并计入剩余配额；没人认领的文件（所在行被跳过）在导入成功后删除，导入失败时全部删除。`final_key` 必须在 `users/<user_id>/` 下。
- M07 课程文件：只导出文件夹与文件条目；解析结果、分块与检索索引是派生数据，不导出，导入后重新处理。不含文件的备份里，文件条目不导入并计入跳过（链接照常导入）。
- M08 导入草稿（会话、条目、上传的源文件）是进行中的工作，不导出、不被替换导入清掉，只随账户删除。
- M09 LMS：沿用模块自带的 `lms/portability.py`。连接导出时不带凭证与凭证提示，导入后状态为 `lms.credentials_missing`，要重新输入令牌；替换导入同样会清掉已有连接的令牌。绑定、课程关联与导入记录按 id 映射（导入记录的目标是考核、待办或日程），缓存不导出。
- M12 助手：对话、消息、提议与附件不导出、不被替换导入清掉，只随账户删除（消息与工具调用里的跨模块 id 写在自由格式的 JSON 中，无法重映射）。自动批准等偏好是在本账户上给出的授权，同样不导出。M16 没有自己的表。
- 上传上限：存储配额 + 50 MB；配额为 0（不限）时为 1 GiB + 50 MB。`core/uploads.py` 的 `UploadBodyLimit` 在请求体到达时边收边数，超过就返回 413，不等 multipart 解析把整个文件写进临时文件（头像、课程文件、M08 上传也用它，各自用 `limit_upload(path, limit)` 声明）。导入认领的文件总量受剩余配额限制，不限配额时为 1 GiB。
- 防止堆积：备份不计入存储配额，所以导出和上传各自按用户每小时最多 10 次（`common.rate_limited`）；同类导出还在生成时再次请求返回那一个；新导出完成后只保留最近 3 份已完成的导出；新上传会替换之前未导入（`uploaded`/`failed`）的上传。
- `manifest.json` 与每个 `data/<module>.json` 声明的解压大小不得超过 64 MiB，否则按无效备份拒绝（防解压炸弹）。
- 导入任务若在 `run_import` 之外死掉（重启、OOM），上传会停在 `importing`；读取、开始、放弃和清理时按任务状态对账，任务已失败或已取消即视为 `failed`。
- 替换模式的确认语句：中文"替换我的数据"、英文"replace my data"；两种语言的确认语句（包括删除账户的）后端都接受。
- 表 `portability_archives`（迁移 0015）记录导出与上传：导出列表只返回最近 5 个未过期的；`GET /me/imports/{id}`（`portability.import.get`）读取预览、状态与报告。每小时的 `portability.cleanup` 删除过期的文件与记录。
- 导入任务只尝试一次；失败时上传保留为 `failed`，可以重新开始或放弃。**任务一旦在自己的事务里写库，就不能再报告进度**（进度用单独的短事务写，SQLite 会被锁住），所以导入只在开始写之前报告一次阶段。

**账户删除**
- 请求里立刻：校验确认语句与勾选 → 重新验证（M01 §4.7 的 `require_recent_auth`）→ 设置 `auth_users.deleted_at`、把邮箱改成 `deleted+<user_id>@invalid`（同一邮箱马上可以重新注册，"已删除"邮件发到任务输入里记下的原地址）、撤销全部会话与 PAT（之后任何请求都是 401，登录也被拒绝）→ 入队任务。
- 任务按依赖逆序调用各模块 `purge`；提交后删除存储 `users/<user_id>/`、删除 `auth_users` 行（级联清掉其余，包括任务本身），再发"账户已删除"邮件（`portability/templates/*/account_deleted.txt`）。任务没完成的删除由 `portability.cleanup` 在 1 小时后补完。
- 没有密码的用户在 10 分钟外删除：前端提示重新登录（邮箱验证码或 Google），再回来删除。

**给之后新增的模块**
- 有用户数据的表必须在自己模块的 `portability.py` 里注册（多数情况一个 `table_adapter` 就够），否则 `portability/tests/test_backups.py` 的覆盖测试会失败；那个测试的数据集 `tests/dataset.py` 也要给新表加一行。
- 存文件的模块：导出时 `await writer.add_file(file_id, storage.open(key))`（不含文件的导出会忽略），导入时在 `prepare` 里 `options.files.store(...)`、在 `import_` 里 `options.files.claim(...)`（见上）。替换导入的 `purge_content` 删除存储对象时必须放进 `ctx.after_commit`，否则导入失败回滚后数据库行回来了、文件却已删掉。
- 前端预览/报告里的条目名称来自 `portability_entity_<module>_<entity>`，没有文案的条目不显示。

**前端**（`apps/web/src/modules/portability/`）
- 账户设置"数据"组的三个分区：导出、从备份恢复、危险区域（删除账户，`ConfirmDialog` + 确认语句 + 勾选，必要时输入密码）。拖放区用 `react-dropzone`。
- 恢复进行中的上传 id 记在 `useUiPref('portability.restore')`，离开页面再回来仍能看到进度与结果；导入成功后刷新所有查询。
- 删除成功后调用 `signOut({ to: '/account-deleted', flush: false })`（不再保存界面状态），公开页面 `/account-deleted` 说明账户正在删除。
