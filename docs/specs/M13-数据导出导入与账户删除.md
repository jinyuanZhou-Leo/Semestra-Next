# M13 数据导出、导入与账户删除

> 依赖：M00、M01、M11，以及所有存储用户数据的模块（每个模块实现自己的导出/导入适配器，本模块负责框架与界面）。
> 建议在 M02–M12 完成后实现；但**导出/导入适配器接口**在本模块开始前就应由各模块按本文第 3 节实现（各模块 spec 的验收中不强制，本模块实现时补齐缺失的适配器）。

## 1. 目标与功能对齐
旧版功能（保留）：
- 导出账户数据（备份文件）。
- 从备份恢复：拖放文件 → 预览内容（Program、LMS 连接、资源、待办、账户设置）→ 冲突处理策略 → 确认导入；可选是否导入账户设置。
- 删除账户：危险区域，确认对话框中输入确认语句后才能删除。

新版：
- 备份格式版本化（`semestra-backup` v1），不兼容旧版备份（明确拒绝旧格式并提示）。
- 备份可选是否包含文件（文件打包进 zip）。
- **不导出任何密钥**（AI key、LMS 凭证、PAT、会话），导入后需要重新填写。
- 导出为后台任务，完成后提供下载链接（24 小时有效）。

## 2. 备份格式
`semestra-backup-<date>.zip`：
```
manifest.json      { format: "semestra-backup", version: 1, exported_at, app_version,
                     modules: { "<module>": <module schema version> }, include_files: bool,
                     counts: { programs, terms, courses, ... } }
data/<module>.json # 每个模块一个文件，内容由模块适配器定义（Pydantic 模型，带 schema_version）
files/<file_item_id>   # 原文件（include_files=true 时）
```
- 所有对象保留原 id；引用关系用原 id 表达。导入时统一重映射。
- 时间统一 ISO 8601 UTC。

## 3. 模块适配器接口
```python
register_portability(
    module="grading",
    schema_version=1,
    depends_on=("academics",),           # 导入顺序
    export=async def (ctx, writer) -> None,         # writer.write_json(obj), writer.add_file(key, stream)
    import_=async def (ctx, payload, id_map, options) -> ImportReport,  # id_map: 跨模块 id 重映射表
    preview=async def (payload) -> dict[str, int],  # 计数
    purge=async def (ctx) -> None,                  # 删除该用户在本模块的全部数据（账户删除与"替换导入"使用）
)
```
- 每个存储用户数据的模块都必须注册（包括 M09 与插件 M14；M16 没有自己的数据）。CI 测试：遍历所有带 `user_id` 列的表，确认其所属模块已注册适配器，且 `purge` 后该表中该用户行数为 0。
- 插件未安装时其数据仍然导出；导入时插件数据照常写入（插件未安装则保持隐藏）。

## 4. 导入
- 上传 zip（≤ 配额 + 50MB 的独立上限）→ 校验 manifest（格式、版本；不支持的版本返回 `portability.unsupported_version`）→ 生成预览：每个模块的计数、Program 列表（名称、学期数、课程数）、是否含文件及大小、是否超出存储配额。
- 选项：
  - **模式**：`merge`（作为新数据追加，所有 id 重新生成；Program 同名时在名称后加"（导入）"）或 `replace`（先 purge 当前账户全部业务数据，再导入；需要输入确认语句）。
  - 选择要导入的 Program（默认全部）。
  - 是否导入偏好与界面布局（默认否）。
- 执行：后台 job，按 `depends_on` 拓扑顺序调用各模块 `import_`，**整个导入在一个数据库事务中**完成（文件先写入存储暂存区，事务提交后移动到正式 key；失败则删除暂存）。
- 报告：每个模块导入数量、跳过项与原因。

## 5. 账户删除
- 前置：最近 10 分钟内登录过（否则要求重新验证：邮箱验证码或密码）。
- 确认：输入本地化的确认语句（中文"删除我的账户"，英文"delete my account"），并勾选"我已了解此操作无法撤销"。
- 执行：撤销所有会话与 PAT → 按依赖逆序调用所有模块 `purge` → 删除存储中 `users/<user_id>/` 下全部对象 → 删除 `auth_*` 行 → 发送"账户已删除"邮件（发送到原邮箱）。整个过程为后台 job，前端立即登出并显示"账户正在删除"页面。
- 删除不可恢复；不保留软删除副本。日志中只保留 user_id 与时间。

## 6. Capabilities 与路由（全部 `expose=("http",)`，不对 agent/MCP 开放）
| name / 路由 | 说明 |
|---|---|
| `portability.export.start` POST /me/exports | 参数 include_files；返回 job |
| `portability.export.list` GET /me/exports | 最近的导出及下载状态 |
| GET /me/exports/{id}/download | `routes.py`，下载 zip |
| POST /me/imports（multipart） | 上传并返回预览 |
| `portability.import.start` POST /me/imports/{id}:start | 选项见第 4 节；返回 job |
| `portability.import.discard` DELETE /me/imports/{id} | |
| `account.delete` POST /me:delete | 确认语句 + 勾选；返回 job |

## 7. 前端（账户设置"数据"分区）
- **导出**：说明（包含什么、不包含密钥）、"包含文件"开关（显示文件总大小）、导出按钮 → 进度 → 完成后下载按钮（并列出最近导出）。
- **从备份恢复**：拖放区 → 预览面板（计数表、Program 勾选列表、模式选择、偏好开关、配额警告）→ 确认（replace 模式需输入确认语句）→ 进度 → 结果报告。
- **危险区域**：删除账户按钮 → 对话框（后果说明、确认语句输入、勾选框、必要时重新验证）。

## 8. 错误码
`portability.invalid_archive`、`portability.unsupported_version`（params: version）、`portability.legacy_backup`（检测到旧版 Semestra 备份格式）、`portability.too_large`、`common.quota_exceeded`、`portability.confirmation_mismatch`、`auth.reauth_required`。

## 9. 测试
- 往返测试：构造覆盖所有模块的数据集 → 导出 → 新账户 merge 导入 → 逐模块比较（忽略 id 与时间戳）。
- replace 模式：原数据完全被替换；中途失败整体回滚、存储暂存清理。
- 密钥不出现在导出文件中（扫描 zip 内容中的已知密钥字符串）。
- 账户删除后：所有带 user_id 的表无该用户数据、存储目录不存在、PAT 与会话失效。
- 旧版备份文件被识别并拒绝。

## 10. 验收
- 在一个账户导出（含文件）后，在另一个账户导入，界面与数据完全一致（除需要重新填写的密钥）。
