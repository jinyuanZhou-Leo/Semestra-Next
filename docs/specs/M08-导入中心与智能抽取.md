# M08 导入中心与智能抽取（Import Center）

> 依赖：M00、M02、M03、M04、M05、M06、M07。被依赖：M09（LMS 导入复用本框架）、M12（Agent 发起导入）。
> 核心模块。所有"外部数据进入 Semestra"的路径（ICS、syllabus、课表文件、Canvas、粘贴文本）共用同一套**导入草稿 → 用户审核 → 提交**流程。

## 1. 目标与功能对齐
旧版功能（保留）：
- 从 ICS 文件批量创建课程及上课时间段（学校选课系统导出）。
- 从 ICS 导入某门课的时间段。
- 从 LMS 导入课程、导入作业为考核（一次性，非同步镜像）。
- 导入前预览。

新增：
- **智能抽取**：从 syllabus（PDF/DOCX/图片/粘贴文本）抽取课程信息（课程号、名称、讲师、学分、年课/半年课、简介、网站）、成绩构成（分类、权重、考核项与截止日期）、上课时间、重要日期；从课表截图/PDF 抽取上课时间段。
- 每个抽取字段带**原文出处**（页码 + 引文）与置信度，用户逐项核对后再写入。
- 与已有数据的冲突检测和合并（例如课程已存在时改为"更新这门课"）。

## 2. 核心概念
- **ImportSession**：一次导入，属于某个 Program，有目标作用域（新学期向导中 / 某学期 / 某门课）。
- **ImportItem**：一个待写入的对象，类型固定：
  | type | 写入目标 | 主要字段 |
  |---|---|---|
  | `course` | M02 `academics.course.create` / `update` | code, title, alias?, credits, instructors, description, website_url, term_ids, planned_terms |
  | `meeting` | M04 `schedule.meeting.create_many` | course_ref, term_ref, section_code, type_code, weekday, start/end, recurrence, weeks, location, instructor |
  | `event` | M04 `schedule.event.create` | course_ref?, title, start/end, all_day, type_code? |
  | `category` | M03 `grading.category.create` | course_ref, name, key, weight_total（仅用于校验/提示） |
  | `assessment` | M03 `grading.assessment.create_many` | course_ref, title, category_ref, weight, due_at, due_has_time, note |
  | `task` | M05 `tasks.item.create_many` | course_ref?, title, due, priority |
  | `course_patch` | M02 `academics.course.update` | 对已有课程的字段级修改（旧值→新值） |
- `course_ref`：指向同一 session 中的 `course` item（`item:<id>`）或已存在课程（`course:<id>`）。提交时按依赖顺序（course → category → assessment/meeting/event/task）执行，前者生成的 id 回填后者。
- 每个字段可带 `evidence: {item_id?(M07 文件), page?, quote?}` 和 `confidence: 'high'|'medium'|'low'`。
- 每个 item 有 `decision: 'accept'|'reject'|'pending'` 与 `issues: [{code, params}]`（如 `import.duplicate_course`、`import.date_unresolved`、`import.weights_not_100`、`import.term_unresolved`）。

## 3. 领域模型
```
imports_sessions
  id, user_id, program_id, source_kind ('ics'|'syllabus'|'timetable_image'|'lms'|'text'|'agent'),
  target JSON {kind: 'term_wizard'|'term'|'course', term_id?, course_id?},
  status ('extracting'|'ready'|'committing'|'committed'|'failed'|'discarded'),
  job_id?, source_refs JSON [{file_item_id?, filename?, lms_course_id?}],
  summary JSON (各类型数量、问题数), error_code?, created_at, updated_at, committed_at?
imports_items
  id, session_id, user_id, type, data JSON（按类型的 Pydantic 模型校验）,
  evidence JSON, confidence JSON, decision, issues JSON, depends_on JSON [item_id],
  result JSON? ({created_id} 或 {error_code}), position
```
- 已提交或放弃的 session 保留 30 天（可在"导入历史"中查看结果），之后清理。
- 新学期向导场景：session 在学期创建前就存在，`target.kind='term_wizard'`；向导提交学期时把 session 中的 `course` item 转为向导的课程草稿（`CourseDraft.extras.import_item_id`），学期创建成功后调用 `imports.session.commit`，此时 `term_ref` 解析为新学期 id。

## 4. 导入源
### 4.1 ICS（确定性解析，不用 AI）
- 解析 VEVENT（`icalendar` 库）：按 SUMMARY 中的课程号（正则 `[A-Z]{2,4}\s?\d{3,4}[A-Z0-9]*`）与 section 编号（`LEC|TUT|PRA|LAB|SEM \d{4}` 等，模式表可扩展）分组；RRULE 周期事件 → meeting（星期、时间、起止日期 → 起止周）；无 RRULE 的同时间重复事件合并为周期；单次事件 → event。
- 输出 course + meeting items；课程号与已有课程匹配时生成 `course:<id>` 引用并标记 `import.duplicate_course`（默认只导入时间段，不新建课程）。
- 学期推断：事件日期落入的已有学期；向导中为正在创建的学期。

### 4.2 Syllabus（AI 抽取，需要 `ai.available('extraction')`）
1. 文件先作为课程文件上传（若目标课程已存在则存到该课程，否则暂存到 session 的临时存储，提交时移动到新课程），等待 M07 `doc_status=ready`。
2. 读取全文（`files.document.read`，≤ 60 页；超过时先用 `files.search` 找"grading/assessment/schedule/成绩/评分"相关页，再读这些页及其前后页）。
3. 调用 M06 `extract(purpose='extraction', schema=SyllabusExtraction, texts=pages)`（出处校验、`wrap_untrusted`、长文档分段都由 M06 完成），指令要求：只抽取文档中明确出现的信息；无法确定的字段留空；日期保留原文（如 "Week 5, Friday"）并尽量解析为具体日期。抽取作为后台 job 声明阶段：`stages=[("reading",10),("recognizing",60),("validating",20),("drafting",10)]`，识别阶段按文件计数（"文件 2/3"）。
4. 后处理（确定性代码）：
   - 相对日期解析：结合目标学期 `academics.term.calendar_info`（第 N 周星期几、阅读周）；无法解析标 `import.date_unresolved`。
   - 权重校验：考核权重合计不为 100 时标 `import.weights_not_100`（说明差额）；分类权重与考核权重不一致时标出。
   - 分类映射：名称匹配内置分类 key（quiz/exam/assignment/project/lab/presentation/participation，中英同义词表），否则新建自定义分类。
   - 年课判断：抽取结果 `duration: 'one_term'|'two_terms'` 或课程号后缀规则（如 UofT `Y1` = 全年），映射为 `planned_terms`。
   - 去重：同课程已有同名考核 → 标 `import.duplicate_assessment`，默认 reject。
5. 支持一次选择多个 syllabus 文件（向导常见场景），每个文件一个 job，结果汇入同一 session。

`SyllabusExtraction` 模型（Pydantic，字段均可空）：
```
course: {code, title, credits, duration, term_hint, description, website_url,
         instructors: [{name, email, role ('instructor'|'ta'|'coordinator'), office_hours}]}
grading: {categories: [{name, weight}], assessments: [{title, category, weight, due_text, due_date, due_time, notes}],
          policies_text}
meetings: [{type, weekday, start_time, end_time, location, weeks_text}]
important_dates: [{title, date_text, date, kind ('exam'|'deadline'|'no_class'|'other')}]
每个叶子字段旁有 <field>_evidence: {page, quote} 与整体 confidence
```

### 4.3 课表截图 / 课表 PDF（AI，需要 `vision`）
- 图片或 PDF 页面图 → `structured(purpose='vision', schema=TimetableExtraction)`：每个格子的课程号、类型、section、星期、时间、地点。
- 后处理同 ICS 的分组与匹配。

### 4.4 粘贴文本
- 文本框粘贴（如邮件、网页上的作业列表）→ 与 syllabus 相同的抽取管线（跳过文件步骤，evidence 只有 quote）。

### 4.5 LMS（由 M09 实现数据获取，本模块提供 session/item 写入接口）
- M09 调用 `imports.session.create(source_kind='lms', source_meta={provider, connection_id})` 与 `imports.items.add(...)` 生成课程、作业（assessment 或 task，用户在审核界面切换类型）、日历事件 items。

## 5. Capabilities
| name | effect | http | 说明 |
|---|---|---|---|
| `imports.session.create` | write | POST /programs/{program_id}/imports | 指定 source_kind、target、文件 item ids 或文本；入队抽取 job，立即返回 session |
| `imports.session.get` | read | GET /imports/{session_id} | 含 items、issues、进度 |
| `imports.session.list` | read | GET /programs/{program_id}/imports | 导入历史 |
| `imports.item.update` | write | PATCH /imports/{session_id}/items/{item_id} | 修改 data、decision；修改后重新运行该 item 的校验 |
| `imports.items.bulk_decide` | write | POST /imports/{session_id}/items:decide | 按类型/问题批量接受或拒绝 |
| `imports.items.add` | write | （内部 + agent） | 追加 item（M09、Agent 使用） |
| `imports.session.commit` | write | POST /imports/{session_id}:commit | 按依赖顺序写入；单个 item 失败不回滚其它（各目标 capability 自身事务），结果写回 item.result；返回汇总 |
| `imports.session.discard` | write | POST /imports/{session_id}:discard | 删除暂存文件 |
| ICS 上传 | — | 先用 M07 上传接口（或 session 临时上传 `POST /imports/uploads`），再 create | |

- `commit` 幂等：已成功的 item 不会重复执行（看 result）。
- Agent 通过 `imports.session.commit` 写入时，属于 write，走 M12 提案确认；提案预览直接展示 session 摘要。

事件：`imports.session.ready|committed|failed`。
提交钩子：`register_commit_hook(source_kind, fn(ctx, session, created: dict[item_id, target_id]))`，在提交事务内、所有 item 写入之后调用，钩子失败则整个提交回滚。M09 用它在同一事务中创建课程关联与导入记录。
前端失效：`imports.*` → `importsSession*`。

## 6. 前端
### 6.1 导入入口（扩展点贡献）
- `academics.termWizardImportSources`：ICS 文件、Syllabus（多文件）、课表截图、粘贴文本。
- `grading.assessmentImportSources`：从 syllabus 导入成绩构成（目标为当前课程）。
- `schedule.meetingImportSources`：ICS、课表截图。
- 课程页概览的 `academics.courseInfo` 卡片菜单："从 syllabus 更新课程信息"，走 6.3：同一个审核对话框，只含该课程的 `course_patch`。
- AI 不可用的来源以 `<AiRequired>` 包装显示引导。

### 6.2 审核界面（对话框或全屏抽屉，`/imports/$sessionId` 也可直接打开）
- 顶部：来源、进度（抽取中显示每个文件的步骤）、问题汇总（"3 个日期需要确认、权重合计 95%"）。
- 左侧：按类型分组的 item 列表（课程 → 每门课下的分类/考核/时间段/事件），每项有接受/拒绝开关和问题徽标；"只看有问题的项"筛选。
- 右侧：选中 item 的表单编辑（字段旁显示置信度点和"出处"按钮）；出处按钮打开 M07 预览定位到页并高亮引文。
- 已存在课程的 `course_patch` 显示字段级对比（旧值 → 新值，每个字段可单独取消）。
- 底部：提交（显示将创建/更新的数量）、稍后继续（session 保留）、放弃。
- 提交后显示结果（成功数、失败项及原因，可重试失败项）。

### 6.3 从 syllabus 更新课程信息（审核对话框）
- 课程基本信息设置是自动保存的，没有"保存"按钮可以充当确认，所以不在表单里直接回填（回填即写库，等于未经确认）。
- "从 syllabus 更新课程信息"创建 `target = {kind: course, course_id}`、`source_kind = syllabus` 的 session，打开 6.2 的同一个审核对话框；抽取结果只保留该课程的 `course_patch`（其它类型的 item 丢弃），显示字段级对比（旧值 → 新值，每个字段可单独取消，带置信度点与出处）。
- 点"保存"是唯一的确认步骤；没有任何字段变化时 session 以 `import.no_changes` 结束，对话框显示"已是最新"。
- 标题只取文档里写明的课程名；讲师追加而不是替换。

### 6.4 导入历史
Program 设置下"导入历史"列表：时间、来源、状态、结果摘要，可打开查看。

## 7. Agent 集成
- 暴露全部 capability。
- Skill `import-from-documents.md`：用户上传 syllabus 并说"帮我导入"时：创建 session（source=syllabus，target=当前课程或学期）→ 等待 ready（轮询 `imports.session.get`，或告知用户稍后）→ 向用户概述抽取结果与问题 → 用户确认后 `commit`。不得跳过审核直接逐个调用各模块的 create 能力来"导入"文档内容。

## 8. 错误码
`import.duplicate_course`、`import.duplicate_assessment`、`import.date_unresolved`、`import.term_unresolved`、`import.weights_not_100`（params: total）、`import.course_ref_missing`、`import.ics_invalid`、`import.no_content`（文档中没抽到任何可用信息）、`import.session_not_ready`、`import.session_closed`。

## 9. 测试
- ICS fixtures：UofT ACORN 导出样例、Google Calendar 导出、包含 RRULE/EXDATE/单次事件、跨夏令时。
- Syllabus：3 份真实风格 fixture（英文 PDF、中文 DOCX、扫描图），mock M06 返回固定抽取结果，测试后处理（相对日期、权重校验、分类映射、去重）。
- 提交顺序与 id 回填；部分失败后重试只执行失败项；幂等。
- 向导场景：学期创建后 session 中 term_ref 正确解析。
- `@pytest.mark.live`：用真实模型跑 fixture，检查关键字段召回（课程号、考核数量、权重合计），作为抽取质量回归，CI 默认跳过。

## 10. 验收
- 新学期向导中选择 5 份 syllabus，审核后一次性创建 5 门课程、它们的成绩构成和上课时间，权重异常和无法解析的日期被明确标出。
- 已有课程再次导入同一份 syllabus 不会产生重复数据。

## 实现说明（M08 落地时补充）
以下是实现时做出的取舍与对上文的细化，以代码为准。

**后端**
- 多了第三张表 `imports_uploads`：用户在导入对话框里上传的文件先存在 M08 自己的存储里（`imports/<user>/…`，单个 25 MB），提交时若 M07 已存在就移入目标课程的文件，否则保留到 session 过期。未关联 session 的上传 1 天后清理，session 30 天后清理（`@periodic("imports.cleanup")`）。上传接口 `POST /imports/uploads` 与原文预览 `GET /imports/uploads/{id}/content` 是普通路由，不是 capability。
- 一个 session 一个 job（`imports.extract`，阶段 reading 15 / extracting 75 / checking 10），多个文件在 job 里依次处理，单个文件失败记在 `source_refs[i].status/error_code`，不影响其它文件；全部失败时 session 为 `failed`。没有按文件拆 job。
- ICS 在 `imports.session.create` 里同步解析，session 直接是 `ready`，不进 job。RRULE 与按周重复的单次事件都会合并成时间段（间隔 14 天以上记为隔周）；时间按 Program 时区的墙上时间处理。导入到单门课程时（ICS、课表截图），课程号（没有课程号时按名称）与目标课程不同的课的时间段也列出来，但默认不导入；不带课程的事件（阅读周等）不导入。
- `course_patch` 只在"从 syllabus 更新课程信息"里默认接受，其它入口（成绩册、向导、学期导入）默认不接受；教师是追加到已有列表，不是整表替换；syllabus 没写课程名时不会建议改名，新建课程才用课程号当名称。课程信息已经是最新时 session 以 `import.no_changes` 结束，前端显示中性的"课程信息已是最新"。
- 图片 syllabus 和扫描页的页图交给 `vision` 模型（同时带上文字页）；没有视觉模型时只读文字页，全是图片则该文件以 `ai.not_configured` 失败。
- 抽取期间放弃导入：job 写回前重新读取状态，已放弃就不再写入。
- 原文预览：HTML 和文本带 `Content-Security-Policy: sandbox`，PDF 和图片不带（浏览器的 PDF 查看器在 sandbox 下不渲染）。
- 对 M05（待办）、M07（文件）的依赖按名字晚绑定（`deps.py`）：capability 通过注册表调用，M07 的解析与渲染通过 `importlib`。缺少时对应 item 提交失败（`import.target_unavailable`）或文件读不了（`import.file_unsupported`），模块本身照常工作。M05、M07 已合并，这些路径都已接通；PDF 页数用 M07 `PageRenderer.page_count`（为此新增的公开属性）。
- 新增错误码：`import.category_weight_mismatch`（params expected、total）、`import.target_unavailable`、`import.file_unsupported`、`import.extraction_failed`（job 重试耗尽）、`import.no_changes`。
- 提交：每个 item 一个 SAVEPOINT，失败只回滚该 item 并记录 `result.error_code`；`register_commit_hook(source_kind, fn)` 给 M09 等在同一事务里追加写入，钩子抛错整个提交回滚。SQLite 驱动只在第一条 DML 才开事务，所以第一个 SAVEPOINT 之前会先写一次 status（见 CLAUDE.md 已知坑）。
- 提交后只有失败的 item 还能修改（`imports.item.update`），再次提交只执行失败项；已成功的 item 不会重复写入（幂等）。
- 向导场景：前端把 `course` item 转为 `CourseDraft`（`extras: {importSessionId, importItemId}`），学期创建后调用 `imports.session.commit` 并传 `wizard_courses: [{item_id, course_id}]`；未映射的 course item（用户在向导里删掉的）及依赖它的 item 被拒绝。
- `source_meta.only = "course_info"`：只保留目标课程的 `course_patch`（课程信息卡片的"从 syllabus 更新课程信息"用）。

**前端**
- 新的 manifest 字段 `overlays`（整个登录后应用只渲染一次的组件），导入对话框 `ImportHost` 挂在这里；任何来源调用 `openImport(request)`（`modules/imports/launcher.ts`）打开它，关闭时 promise 返回结果。同一时间只有一个导入，打开第二个会把第一个当作取消。
- 审核里的字段修改在失焦时保存（开关和下拉立即保存），提交和"添加到向导"会先等这些保存完成。
- 审核界面 `SessionView` 同时用于对话框和页面 `/p/$programId/imports/$sessionId`（不是 `/imports/$sessionId`，因为同源托管时后端的 `GET /imports/{id}` 会抢先匹配）。对话框高度固定，读取中、审核、结果三个阶段之间不跳动。
- 出处按钮显示页码和引文，并链接到上传文件（PDF 跳到对应页）；M07 合并后再改为 M07 预览并高亮引文。
- AI 来源的"开始读取"按钮用 `<AiRequired>` 包裹，放在对话框里，入口本身不灰显（入口同时提供 ICS 这类不需要 AI 的来源）。
- 新扩展点 `academics.courseInfoActions`（课程信息卡片右上角"…"菜单），`CourseDraft` 新增 `plannedTerms`（全年课程）。
- **§6.3 改为审核对话框**（所有者 2026-10-19 确认）：原设计的 `imports.extract.course_fields` 与单表单回填不做，§6.3 已按审核对话框改写。
- 成绩册"从 syllabus 导入"在对话框里直接提交，`launch()` 返回空数组，不再交给成绩册的 `create_many`。
- 导入历史是 Program 设置"数据"组下的分区（TanStack Table）。
