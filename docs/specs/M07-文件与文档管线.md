# M07 文件与文档管线（Files & Document Pipeline）

> 依赖：M00、M02、M06（OCR 与 embedding，可选能力）、M11。被依赖：M08（抽取读取解析结果）、M09（Canvas 文件保存到课程文件）、M12（检索与引用）、M13（备份）。
> 核心模块（`kind: 'core'`）。替代旧版 `builtin-course-resources` 插件，并新增文档解析、全文检索与语义检索。

## 1. 目标与功能对齐
旧版功能（保留）：
- 课程文件管理：拖拽/多文件上传、保存外部链接、重命名、删除、文件夹浏览、排序；打开外部链接前确认。
- 账户级存储配额 50MB，上传读取有上限。
- 快速打开小部件：在仪表盘置顶若干文件/链接。
- 文件元数据（名称、类型、大小、时间）格式化显示。

新增：
- 文件预览（PDF、图片、文本/markdown、Office 转换后的 PDF）。
- 上传后自动进入**文档管线**：解析 → 按页文本（markdown）→ 切块 → 全文索引（总是）→ 向量索引（用户配置了 embedding 时）。
- 检索能力 `files.document.search`（关键词 + 语义混合），返回带页码的引用，供 Agent 回答与 M08 抽取使用。
- 重复文件检测（同课程内 sha256 相同提示）。

## 2. 领域模型
```
files_folders
  id, user_id, course_id, parent_id?, name, created_at, updated_at   # 同级按名称排序，没有手动顺序
  UNIQUE(course_id, parent_id, name)

files_items
  id, user_id, course_id, folder_id?, kind ('file'|'link'),
  display_name, original_name?, mime_type?, size_bytes, sha256?, storage_key?,
  url? (link 时), pinned (bool),
  source_kind? ('upload'|'lms'|'agent'), source_ref?,
  doc_status ('none'|'pending'|'processing'|'ready'|'failed'|'unsupported'),
  doc_error_code?, active_document_id?, created_at, updated_at

files_documents                     # 一次解析的产物（文件重新上传/重新解析会生成新版本）
  id, user_id, item_id, parser_fingerprint, page_count, char_count, language?,
  status ('building'|'ready'|'failed'), created_at

files_document_pages
  id, document_id, user_id, page_no (1-based), markdown, ocr_used (bool),
  image_storage_key? (页面缩略图, 预览与多模态复用)

files_chunks
  id, document_id, user_id, item_id, course_id, chunk_no, page_from, page_to,
  heading_path (JSON list), text, token_count, content_hash
files_chunks_fts   # FTS5 虚拟表 (text, heading_path), content='', contentless_delete=1, tokenize='trigram'
                   # 无内容表：正文只存在 files_chunks.text，索引行按 files_chunks.fts_rowid 删除（SQLite ≥ 3.43）
files_chunk_vectors # sqlite-vec 虚拟表 vec0(chunk_id TEXT PRIMARY KEY, user_id TEXT PARTITION KEY, course_id TEXT, embedding float[dim])，
                    # 按 user_id 分区，检索只扫描该用户自己的向量；每个 (embedding model, dim) 一张表，表名含模型指纹
                    # 向量库通过 VectorStore 接口访问（upsert / delete / knn(user_id, filters, k)），实现可替换为 Qdrant
files_index_state
  item_id (PK), user_id, fts_document_id?, vector_document_id?, vector_fingerprint?, updated_at
```
- FTS5 使用 `trigram` 分词器，同时支持中文与英文子串匹配。
- 文件夹只是课程内的组织方式，最多 3 层。

## 3. 文档管线
### 3.1 阶段与任务
上传完成（或 link 指向可下载的 PDF 并由用户选择"保存副本"）→ 入队 `files.process`（`dedupe_key=item_id:sha256`）：
1. **识别类型**：按 magic bytes 判断。支持：PDF、DOCX、PPTX、XLSX/CSV、TXT/MD、HTML、图片（PNG/JPEG/WebP/HEIC）、ICS（交给 M08，不进入文本索引）。其它类型 `doc_status=unsupported`。
2. **解析为按页 markdown**：
   - PDF：PyMuPDF（`pymupdf4llm`）逐页提取；某页文字少于 50 个字符且有图像 → 标记需要 OCR。
   - DOCX/PPTX/XLSX：MarkItDown；PPTX 每张幻灯片一页；DOCX 按分页符或每 3000 字符一页（记录为逻辑页）。
   - 图片：整张作为一页，需要 OCR。
   - OCR：自托管开了本地 OCR（`ai.local_ocr.available`）且用户的 OCR 用本机模型时，先在 `ocr_model` 阶段下载还没有的模型（不算进 OCR 超时；下载失败时，选「自动」的用户改用服务商的 `ocr` 模型，没有或明确选了本机模型就跳过这些页），再在 `ocr_isolated` 子进程里识别（一次一个子进程，每批 32 页，每页限时 `SEMESTRA_LOCAL_OCR_PAGE_TIMEOUT_SECONDS`，第一页另加两分钟加载模型）；否则若 `ai.available(ocr)` → 页面渲染为 PNG（150 DPI）调用 M06 `complete(purpose="ocr")`（2026-10-28 起从 `vision` 拆出独立用途），提示词要求输出 markdown（表格保留为 markdown 表格）；不可用 → 该页文本为空，`doc_status` 仍为 ready 但标记 `ocr_skipped`，前端提示"配置 AI 后可识别扫描页"。
   - 生成每页缩略图（预览与后续多模态复用）。
3. **切块**：按标题层级和段落切分，目标 600 token、重叠 80 token，单块不跨越 3 页以上；记录 `heading_path`、页码范围。
4. **全文索引**：写入 FTS5。
5. **向量索引**（若 `ai.available(embedding)`）：批量 embed（每批 64），写入对应 vec0 表。
6. 原子切换：新 document 全部完成后更新 `files_items.active_document_id` 与 `files_index_state`，再删除旧 document 的 chunks/vectors。
- 任务声明阶段（M00 3.7）：`stages=[("detecting",3),("parsing",25),("ocr",30),("chunking",5),("indexing",7),("embedding",30)]`。`ocr` 阶段用 `ctx.stage("ocr", current=页, total=需 OCR 的页数)`，`embedding` 阶段用批次计数；不需要 OCR 或 embedding 不可用时调用 `skip_stage`。每个阶段之间检查取消。阶段文案 key：`job_step_files_process_<step>`。
- **管线指纹**：`parser_fingerprint = hash(parser_version, ocr_model?, chunker_version)`；`vector_fingerprint = hash(embedding_provider, model, dim)`。用户更换 embedding 模型后，定时任务 `files.reindex_vectors` 为所有 ready 的文档补建新指纹的向量（旧表在完成后删除）；重新解析只在 parser 版本升级或用户手动"重新处理"时进行。
- 失败：`doc_status=failed`，`doc_error_code` ∈ `files.parse_failed`、`files.encrypted_pdf`、`files.too_many_pages`（上限 500 页）、`ai.*`。

### 3.2 检索 `files.document.search`
- 输入：`query`、范围（program_id 必填，term_id?/course_ids?/item_ids?）、`top_k`（默认 8，最大 20）、`mode`（`hybrid` 默认 / `keyword` / `semantic`）。
- 关键词：FTS5 bm25；语义：查询 embed 后 vec0 KNN（k=top_k×4），按范围过滤。
- 混合：Reciprocal Rank Fusion（k=60）合并；同一文件相邻块合并为一个结果。
- 结果：`[{item_id, display_name, course_id, page_from, page_to, heading_path, snippet (高亮), score, citation_id}]`。`citation_id = "<item_id>:p<page_from>-<page_to>"`，前端可据此打开预览定位到页。
- 范围内有文件仍在处理中时，结果附带 `pending_items: [...]`，由调用方决定如何提示；**不**降级为读取半成品。
- 语义模式但 embedding 不可用 → 自动退化为 keyword 并在结果中标记 `mode_used=keyword`。

### 3.3 读取接口（给 M08 和 Agent）
- `files.document.read(item_id, pages?)`：返回指定页的 markdown（最多 30 页一次），用于整份文档抽取；超出时返回 `next_page`。
- `files.document.outline(item_id)`：标题层级与对应页码。

## 4. 存储与配额
- 存储 key：`users/<user_id>/files/<item_id>`；页面缩略图 `users/<user_id>/files/<item_id>/pages/<n>.png`（计入配额的只有原文件）。
- 配额：`USER_STORAGE_QUOTA_BYTES`（托管默认 50MB，自部署可调或设为 0 表示不限）；单文件上限 25MB（配置项）。上传前前端先检查剩余空间，后端流式计数再次检查。
- 本模块向 M00 注册存储用量统计函数。

## 实现说明（M07 落地时补充）
以下是实现时做出的取舍与对上文的细化，以代码为准。

**后端**（`apps/api/src/semestra/modules/files/`）
- 解析不用 MarkItDown（它会拉进 pandas、openai、msal 等一大串依赖）：PDF 用 `pymupdf4llm`（`IdentifyHeaders` 识别标题，逐页 `to_markdown`），DOCX 用 `python-docx`（标题/列表样式、分页符，超过 3000 字符切逻辑页），PPTX 用 `python-pptx`（每张一页，含表格与备注），XLSX/CSV 用 `openpyxl`/`csv`（每 100 行一页，表头重复；去掉末尾的空列与空行，最多 100 列；表格超过页数上限时只保留前面的页，不算失败），HTML 用 BeautifulSoup 去掉 script/style/nav 等后由 `markdownify` 转 Markdown，文本类（编码按 `decode_text`：UTF-8/BOM，否则 `charset-normalizer` 猜测，最后 latin-1）按空行分段、约 3000 字符一页，没有空行的长段再按行、按空白硬切，保证单页不超过 3000 字符），图片用 Pillow（+ `pillow-heif`）。读取器在 `parse/readers.py`，类型识别在 `parse/detect.py`（只看内容，不信扩展名；旧版 `.doc/.ppt` 视为不支持）。
- FTS 表不是 `content='files_chunks'` 外部内容表，而是独立的 `files_chunks_fts(text, heading_path)`，`files_chunks.fts_rowid` 记录对应行，删除时按 rowid 删（外部内容表在删除时必须提供原文，容易出错）。迁移里手写建表；`env.py` 的 `include_object` 忽略 `files_chunks_fts*` 与 `files_vec_*`，`alembic check` 不会把它们当成多余的表。
- 向量表按空间建：`files_vec_<12 位指纹>`，指纹 = sha256(提供方类型, 模型, 维度)；`user_id` 是分区键，`course_id` 是元数据列，可直接在 KNN 里按课程过滤。sqlite-vec 在每个连接打开时加载（`core/db.py`），加载失败只记日志，语义检索自动退化为关键词。KNN 的 k 为 `max(top_k×8, 40)`（只取本人 ready 文档的块后再截断）。指定了 `item_ids` 时不走 KNN，而是对这些文件的块精确计算距离（`nearest_of`），否则全课程最近的块可能都在别的文件里。查询向量按（用户、服务商类型、模型、查询）缓存 10 分钟、最多 512 条（`cachetools.TTLCache`），同一查询不重复付费。
- 存储 key：原文件 `users/<u>/files/<item>/original`，页面图 `users/<u>/files/<item>/pages/<document>/<n>.png`（按文档版本分目录，重新处理时旧图随旧版本删除）。页面图只生成第 1 页（文件网格只用第 1 页；OCR 自己渲染更大的图）。
- 处理任务每个阶段用自己的短事务，解析与 AI 调用期间不持有 SQLite 写锁；新版本完整写入后才切换 `active_document_id`，切换前搜索仍返回旧版本。embedding 失败不算处理失败：文件照常 ready，只有关键词检索；已写入的那几批向量会删掉，定时任务 `files.retry_vectors`（每 6 小时）给还缺向量的用户入队 `files.reindex_vectors`；同一份文档连续 3 次补齐失败（`files_index_state.vector_failures`）后定时任务不再管它，重新处理文件或换 embedding 模型会再试。
- 解析与缩略图在子进程里做（`parse/isolated.py`，forkserver，没有时退回 spawn）：限内存（`RLIMIT_AS`，`SEMESTRA_FILES_PARSE_MEMORY_BYTES`，默认 2 GB）与时长（`SEMESTRA_FILES_PARSE_TIMEOUT_SECONDS`，默认 300 秒），超时、内存不足或被系统杀掉都记为新错误码 `files.too_complex`，进程会被结束。DOCX/PPTX/XLSX 解压后总大小超过 100 MB 直接拒绝（防 zip 炸弹）。页面图与 OCR 渲染按像素封顶（缩略图高不超过 960，OCR 不超过约 600 万像素），超大页面不会撑爆内存。缩略图在解析结果出来之后是尽力而为：失败或超时只是少了图，不会让文件失败。OCR 的页面图也在子进程里渲染（每批 8 页），同时最多 4 页在等图像模型；某一页模型出错只跳过那一页（计入 `ocr_skipped_pages`），其余页照常；密钥无效、模型不存在、服务商不可达、限流这类对每页都一样的错误会停止 OCR，剩下的页都计为跳过。
- 重新处理期间旧版本仍可读（只要有 `active_document_id`），不只看 `doc_status`。
- 换 embedding 模型的重建先用一个探测请求确定当前空间，已在该空间的文档跳过；重建中途模型又变了就丢掉半成品重来（最多 3 次）。
- 中文检索：trigram 至少 3 个字符；查询里 3 字以上的 CJK 词切成滑动三字组，1–2 个字符的词改用 `LIKE` 子串匹配（与索引一样任一命中即可，按命中的词数、再按出现次数排序后取前 200 个块），结果与 FTS 命中合并。查询里的控制字符先去掉。已知限制：FTS5 不能按列分区，MATCH 先在全库匹配再按本人过滤，bm25 的词频也是全库统计；加 UNINDEXED 的 `user_id` 列并不能减少匹配量，真正的办法是按用户分表，等托管版用户多了再做。相邻块只在分数接近时合并（`MERGE_SCORE_RATIO = 0.6`），否则小文件的 KNN 结果会把整份文件合成一个命中。
- 换 embedding 模型不是定时任务，而是订阅 `ai.assignment.updated`（purpose 为 embedding）后入队 `files.reindex_vectors`（`dedupe_key="reindex"`），完成后删除空的旧向量表。
- `files.usage.get` 的路径是 `GET /files-usage`（`/files/usage` 会被 `/files/{item_id}` 抢先匹配）。`files.folder.update` 是 `PATCH /folders/{folder_id}`，`files.folder.delete` 是 `DELETE /folders/{folder_id}?recursive=`。
- 设置命名空间 `files`（学业项目与课程两级，`files/settings.py`）：`auto_index`（默认开）。关闭时新加的可解析文件 `doc_status` 为 `none`、不入队，用户点“建立索引”（即 `files.item.reprocess`）才处理；M08 导入用到这样的课程文件时 `deps.course_file_ready` 会自动触发处理。读 document/outline 时返回 `files.not_indexed`（409）。
- 新增错误码：`files.not_ready`（409，文档还没处理好时读 document/outline）、`files.cancelled`（任务被取消）。新增事件：`files.folder.created|updated|deleted`。`ItemOut` 多了 `page_count`、`ocr_skipped_pages`（扫描页因没有图像模型或模型出错而跳过的页数）与 `job_id`（处理中时的任务，前端显示进度）。
- 上传路由外加一个 ASGI 中间件 `UploadBodyLimit`：请求体明显超过 min("每次最多 10 个文件 × 单文件上限", 配额) 时直接 413，不必读完（配额更小时错误码是 `common.quota_exceeded`）。单文件上限配置项 `SEMESTRA_FILES_MAX_UPLOAD_BYTES`（默认 25 MB）。上传先把所有文件写进存储（不碰数据库，不持写锁），再插入行并在同一事务里重新核对配额，两个并发上传不会一起占掉最后的空间；任何一个失败就回滚并删除已写的文件。
- 文件内容与页面图都带 ETag（内容用 sha256，页面图用文档 id + 页码），`If-None-Match` 命中返回 304；页面图改为 `no-cache`，重新处理后不会看到旧图。
- 文件内容响应：PDF 不加 CSP（浏览器拒绝在 sandbox 文档里运行自带 PDF 查看器，PDF 本身也不能跑脚本），图片 `default-src 'none'`，其余 `sandbox; default-src 'none'`；能跑脚本的类型（HTML、SVG…）只作为附件下载。
