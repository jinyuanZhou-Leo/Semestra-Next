## 实现顺序

```
第 1 批  M00
第 2 批  M01   M15（可从此时起并行，随后续模块补充配置）
第 3 批  M11
第 4 批  M02
第 5 批  M10   M03   M04   M06   M14        ← 可并行
第 6 批  M05（需 M04）   M07（需 M06）     ← 可并行
第 7 批  M08（需 M03 M04 M05 M07）
第 8 批  M09（需 M08 M10）   M12（需 M06 M07 M10）  ← 可并行
第 9 批  M16（需 M09 M10）   M13（需全部存储数据的模块）  ← 可并行
```
同一批内的模块互不依赖，可以分给不同 agent 同时实现。

## 给实现 agent 的工作约定
1. 开始前必读：M00 全文、自己的模块规格、依赖模块规格中的"Capabilities"与"事件"部分，以及`CLAUDE.md`。
2. 只在自己模块的目录与表前缀内写代码；需要别的模块配合时，通过对方已声明的 capability、事件或扩展点；对方没有提供所需接口时，**先修改对方的规格文档并在 PR 描述中说明**，再实现最小改动。
3. 规格中写明的 capability 名称、表名、错误码、扩展点名称是跨模块契约，不得自行改名。
4. 每个模块的交付都必须包含：后端代码与迁移、前端代码、中英文案、skill 文件（如规格要求）、测试、`CLAUDE.md` 中本模块的简要说明，并通过 M00 定义的全部 CI 检查。
5. 规格与实现有偏差时，在同一个 PR 中更新规格，保持文档是事实来源。
6. 遇到规格没有覆盖的产品决策，选择最符合本模块"目标"一节的方案，在 PR 描述中列出，供 Jinyuan 审阅。
