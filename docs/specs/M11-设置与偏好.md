# M11 设置与偏好（Settings Framework, Preferences, Theme）

> 依赖：M00、M01。被依赖：所有提供设置分区的模块；M02 起的模块都会用到偏好与 `useUiPref`。实现顺序上紧接 M01（Program/学期/课程级设置页的作用域部分在 M02 完成后自然可用）。
> 本模块解决旧版"设置逻辑不清晰、设置项分散、插件与主题耦合"的问题。

## 1. 原则
1. **三类设置，各有固定归属**：
   - **账户偏好**（与学业数据无关的个人偏好）：语言、主题、强调色、时间格式、一周起始日等 → 本模块 `settings_preferences`。
   - **实体属性**（Program 名称、GPA 换算表、学期日期、课程学分……）→ 由拥有该实体的模块存储为普通字段，只是**界面上**挂在对应级别的设置页里。
   - **模块/插件配置**（日历默认视图、待办默认列表、某插件的选项）→ 本模块的通用 `settings_values`，带作用域继承。
2. **设置入口只有两类**：全局"设置"（账户级）和每个 Program/学期/课程的"设置"（作用域级，从页头齿轮进入）。设置不是一个 Page，也不是插件。
3. **主题与插件解耦**：主题只是一组 design token；模块与插件只能读取 token，不能注册主题、不能修改全局样式。
4. **界面状态**（排序方式、折叠状态、上次视图）不是设置，存 `settings_ui_state`，不在设置页显示。

## 2. 领域模型
```
settings_preferences
  user_id (PK), locale ('en'|'zh-CN'|null=跟随浏览器), theme ('system'|'light'|'dark'),
  accent ('neutral'|'blue'|'violet'|'green'|'orange'|'rose'|'teal'|'amber'),
  time_format ('auto'|'12h'|'24h'), week_start (1=周一|7=周日|0=跟随 locale),
  reduce_motion ('system'|'on'|'off'), active_program_id?, updated_at

settings_values                         # 模块/插件配置，带作用域继承
  id, user_id, namespace (如 'calendar', 'tasks', 'plugin.pomodoro'),
  scope_type ('account'|'program'|'term'|'course'), scope_id? (account 为空),
  data JSON (只含该层显式设置的 key), updated_at
  UNIQUE(user_id, namespace, scope_type, scope_id)

settings_ui_state                       # useUiPref 的后端存储
  user_id, key (≤128 字符), value JSON (≤16KB), updated_at, PRIMARY KEY (user_id, key)
```

## 3. 配置命名空间与继承
- 模块在后端声明：
```python
register_settings(
    namespace="calendar",
    schema=CalendarSettings,              # Pydantic，所有字段有默认值
    levels=("account", "program", "term"),# 允许在哪些级别覆盖
    plugin_id=None,
)
```
- 解析：`resolve(namespace, scope)` 按 `account → program → term → course` 依次合并显式设置的 key，最后用 schema 默认值补全；返回 `{values, sources: {key: level}}`。课程的 program/term 由 M02 解析（课程取其当前学期，年课取包含今天的学期）。
- 写入只写当前层的显式 key；"恢复为上一级"删除该层的 key。
- 插件卸载不删除其设置；`plugins.purge` 时删除 `namespace = 'plugin.<id>'` 的所有行。
- 删除作用域（学期、课程、Program）时删除对应层的行（订阅 `academics.*.deleting`）。

## 4. Capabilities
| name | effect | http | 说明 |
|---|---|---|---|
| `settings.preferences.get` | read | GET /me/preferences | agent 可读（用于时间格式与语言） |
| `settings.preferences.update` | write | PATCH /me/preferences | `expose=("http",)`；发布 `settings.preferences.updated` |
| `settings.values.get` | read | GET /settings/{namespace} | 参数 scope_type、scope_id；返回 resolved values + sources |
| `settings.values.update` | write | PATCH /settings/{namespace} | 写入当前层 |
| `settings.values.reset` | write | DELETE /settings/{namespace}/keys/{key} | 恢复为上一级 |
| `settings.schemas.list` | read | GET /settings/schemas | 所有命名空间的 JSON Schema、允许级别、所属插件（前端自动生成表单用） |
| `settings.ui_state.get_many` | read | POST /me/ui-state:get | 批量读取 key（启动时预取常用前缀） |
| `settings.ui_state.set` | write | PUT /me/ui-state/{key} | `expose=("http",)` |

Agent：可读 `preferences.get`、`values.get`；可写 `values.update`（例如"把日历默认改成月视图"），偏好写入不开放（避免 agent 改语言）。
事件：`settings.preferences.updated`、`settings.values.updated`（payload: namespace, scope）。
前端失效：对应 `settingsPreferences*`、`settingsValues*`。

## 5. 前端
### 5.1 设置框架
- `SettingsSectionContribution`（M00 契约的完整版）：
  ```ts
  { id, level: 'account'|'program'|'term'|'course', group?: string, title, description?, icon?, order,
    pluginId?, component?: (props: {scope}) => JSX,      // 自定义
    namespace?: string,                                 // 或者：按命名空间 schema 自动生成表单
    fields?: FieldOverrides                             // 自动表单的字段顺序、控件类型、说明文案 key
  }
  ```
- 布局：左侧分区导航（按 group 分组，粘性），右侧分区内容；滚动联动高亮当前分区；URL `#<sectionId>` 定位。
- **自动保存**：字段变更后 600ms 防抖保存，分区标题旁显示"已保存/保存中/保存失败（重试）"；离开页面前 flush。需要确认的危险操作（删除）放在分区底部的"危险区域"，使用确认对话框。
- 自动生成表单：根据 JSON Schema 类型选择控件（bool→Switch，enum→Select/Segmented，number→NumberInput 带 min/max，string→Input，time→TimePicker）；每个字段在非 account 级别显示"继承自：账户/Program/学期"徽标与"恢复"按钮。
- 文案：自动表单的标题与说明来自 Paraglide 消息 `settings_<namespace>_<field>_label/_description`，缺失时 CI 报错。

### 5.2 页面结构
- **设置是对话框，不是页面**（形态照 shadcn 的 sidebar-13「A sidebar in a dialog」）：左侧分组、右侧当前分组的全部分区；账户、Program、学期、课程四个级别共用同一个 `SettingsDialog`，挂在登录后的布局里。URL 为当前页加 `?settings=<level>/<group>#<section>`（level 为 `account|program|term|course`，group 可省略表示第一组），所以浏览器返回键先关闭对话框，链接可分享；切换分组用 replace，不堆历史记录。旧路由 `/settings/$group`、`/p/…/settings/$group` 仍可用，只做重定向到「作用域页面 + `?settings=`」。
- 全局设置（`level=account`）：左侧按小标题分三块，每块下是分组，分组下是内置分区：
  - **个人**：账户（资料、登录方式；M01）、安全（会话、访问令牌；M01）、偏好（语言、主题（系统/浅色/深色，带预览）、强调色（8 个色块）、时间格式、一周起始日、减少动效）。
  - **功能**：AI（M06）、日历（M04；待办全局默认 M05 若有账户级字段也放这里或「功能」）、集成（LMS 连接，M09 核心模块，始终显示；provider 表单由 `lms.providerUi` 提供；Program 设置与课程设置中也有 M09 的 LMS 分区）、插件（M10）。没有指定分组的账户级分区落在「功能」（`features`）。
  - **系统**：数据（导出、导入备份、删除账户；M13）、关于（版本号、构建时间、GitHub 链接、开源许可）。
  - 分组 id：`account|security|preferences|ai|calendar|features|integrations|plugins|data|about`；小标题只在账户级出现，空分组与空小标题不显示。
- Program 设置（`level=program`，在 Program 页打开）：常规（基本信息、学科颜色；M02）、成绩（GPA 与成绩；M03，分组 id `grades`）、日历（课程类型与日历偏好；M04）、待办（M05）、导入历史（M08）、各插件 program 级分区、危险区域（删除 Program，放在常规）。
- 学期设置（`level=term`）、课程设置（`level=course`）：同一框架，分区由各模块按 level 贡献；只在对应作用域的页面上可打开，其它页面上的该级别参数被忽略。
- 作用域页头右侧齿轮按钮打开对应级别的设置对话框，侧边栏「设置」打开账户设置；关闭（✕、Esc、返回键）回到打开前的页面。窄屏（<md）没有左侧列，改用页头里的下拉选择分组。

### 5.3 主题实现
- `ThemeProvider`（M00 提供骨架）读取偏好：在 `<html>` 上设置 `class="dark"` 与 `data-accent="<accent>"`；`theme.css` 中每个 accent 覆盖 `--primary`、`--ring`、`--chart-1` 等少数 token（明暗各一套）。
- 首屏防闪烁：偏好同时写入 localStorage，`index.html` 内联脚本在 React 加载前设置 class 与 data 属性。
- 减少动效：设置 `data-reduce-motion`，`motion` 库的 `MotionConfig reducedMotion` 跟随。

### 5.4 语言
- 切换语言即时生效（Paraglide `setLocale`），同时 `PATCH /me/preferences`；`<html lang>` 同步；后端邮件语言取该偏好。
- 未登录页面（登录页）提供语言切换下拉，选择存 localStorage，注册后写入偏好。

### 5.5 `useUiPref`
- `useUiPref<T>(key, defaultValue, { scope? })`：读写 `settings_ui_state`；本地乐观更新、300ms 防抖写入；启动时批量预取 `layout.*`、`calendar.*`、`tasks.*` 等常用前缀。key 命名规范 `<module>.<what>[.<scopeId>]`。

## 6. 错误码
`settings.unknown_namespace`、`settings.level_not_allowed`（params: namespace, level）、`settings.invalid_value`（字段级，复用 `common.validation` 结构）、`settings.ui_state_too_large`。

## 7. 测试
- 继承解析：四层覆盖、恢复上一级、sources 正确；课程解析学期（年课按今天）。
- schema 校验失败的写入被拒；未知 key 被拒。
- 作用域删除清理；插件 purge 清理。
- 前端：自动表单生成、继承徽标与恢复、自动保存状态与离开前 flush、主题首屏无闪烁（Playwright 检查首帧 class）。

## 8. 验收
- 所有设置项都能在"全局设置"或"某个 Program/学期/课程的设置"中找到，且只出现在一个地方。
- 在学期级覆盖日历默认视图后，课程页显示"继承自学期"，点击恢复后跟随账户设置。

## 9. 实现说明与偏离（已落地，其它模块按此对接）

后端 `apps/api/src/semestra/modules/settings/`，前端框架 `apps/web/src/app/settings/`，内置分区内容 `apps/web/src/modules/settings/`。

- **三类设置的边界**：账户偏好（`settings_preferences`）；实体自身属性（名称、日期，留在所属模块）；模块/插件配置（`settings_values`，经 `register_settings` 声明）。前端设置页只是三者的壳，不关心谁在贡献。
- **URL**：设置对话框由 `?settings=<level>/<group>` 控制（group 为 `general|account|preferences|features|integrations|plugins|data|about`），分区用 `#<sectionId>` 定位；`useSettingsDialog()`（`app/settings/use-settings-dialog.ts`）提供 `open/select/close`，打开会在历史里压一条并打标记，关闭时有标记就 `history.back()`，否则 replace 掉参数。所有入口（侧边栏、页头齿轮、`AiRequired` 的链接、命令面板的 `settings.plugins`）都走它。作用域从当前页面的路由参数得到，不再由路由传入。对话框里可以再叠 AlertDialog、Select 等弹层，Esc 只关最上面一层。
- **分组归属**：分区不写 `group` 时，账户级归“功能”(`features`)，其余级别归“常规”(`general`)。
- **插件的账户级分区不进导航**：带 `pluginId` 的 `level: 'account'` 分区只在插件自己的详情页渲染（M10 用 `<PluginSettingsSections pluginId>`），设置页的“插件”分组只放 M10 的插件管理分区。这样“插件设置在插件里”，主题/语言等核心设置与插件完全解耦。
- **自动表单**：`NamespaceForm` 读取 `settings.schemas.list`（已向 agent 开放）的 JSON Schema 生成控件；`FieldOverrides` 支持 `order`、`hidden`、`controls`。列表/对象类字段生成不了，需要自定义 `component`。数字字段本地校验 min/max，不合法的值不发送。
- **文案缺失时**：运行时回退为字段名（不抛错）；CI 由后端测试 `tests/test_settings_messages.py` 检查：已注册命名空间的每个字段都有 `_label`，有 `description` 的有 `_description`，`Literal` 字段每个取值有 `_option_<value>`，en 与 zh-CN 都要有。命名空间里的 `.`、`-` 在消息 key 里变成 `_`。
- **作用域解析钩子**：M11 不知道课程属于哪个学期。`registry.set_scope_resolver(async (ctx, scope_type, scope_id) -> ScopeChain)` 由 M02 注册；在注册前所有非账户作用域一律 `common.not_found`（宁可拒绝，也不让用户读写别人的作用域）。年课程的 `term_id` 取包含今天的学期，没有则为 `None`。
- **清理事件用 `*.deleted`**：M00 的事件总线只在提交后派发，没有同步的 `deleting` 钩子，所以订阅 `academics.{program,term,course}.deleted`（payload 含对应 `*_id`，事件 `user_id` 必填）。级联删除时 M02 必须为被级联的学期、课程各发一次 `deleted`，否则它们的设置残留（残留无害但占空间）。删除 Program 时同时把偏好里的 `active_program_id` 置空。
- **主题**：强调色是 8 个 `data-accent`（含 `neutral`，默认 `blue` 即旧调色板）。`theme.css` 里只用 `--accent-hue` / `--accent-chroma` 两个变量派生 `--primary`、`--ring`、`--chart-*`、`--sidebar-primary`，新增强调色只加一段色相覆盖。首屏脚本是 `public/theme-init.js`（CSP 只允许同源脚本，所以不内联），读取 localStorage 的 `semestra.theme|accent|reduce-motion` 与 `PARAGLIDE_LOCALE`。
- **语言与格式**：`LocaleProvider` 用 `setLocale(…, {reload:false})` 并以 `key` 重挂载子树（Paraglide 的消息是普通函数，不是响应式的）；时间格式、一周起始日变化同样重挂载。登录页选择语言只写本地，首次登录后写入账户偏好。
- **减少动效**：“关”只表示不强制，覆盖不了操作系统的“减少动效”设置。
- **一周起始日**：`week_start=0` 表示跟随语言（中文周一、英文周日）。M02 规格写“默认周一”，与此不同，M04 实现日历时以 `lib/format.ts` 的 `firstDayOfWeek()` 为准。
- **`useUiPref`**：写入失败静默（只留在本标签页缓存）；没有每用户 key 数量上限（单值大小有限制，见 `settings.ui_state_too_large`）。登录布局加载时预取 `layout.*|calendar.*|tasks.*|academics.*|onboarding.*|commands.*`。
- **关于页**：只有版本号、构建时间、GitHub 链接；开源许可与第三方许可清单在有发布流程（M15）后再补。
- **没有侧边栏之前**：M02 落地前，首页放一个“设置”链接作为入口。
- **`ui` 组件**：`switch`、`select`、`radio-group` 是手写的（shadcn registry 在沙箱里不可达），接口与 shadcn 生成的一致，之后可用 CLI 覆盖。
