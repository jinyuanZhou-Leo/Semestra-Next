# M18 通知

## 1. 目标

在上课、事件开始和待办截止前提醒学生，并在需要处理的事发生时（导入可以审核、Sem 等待确认、新登录）通知他们，即使没有打开 Semestra。用的是浏览器自带的 Web Push（RFC 8030/8291/8292），不依赖任何第三方推送服务账号，自部署同样可用。

不做：邮件通知（新登录邮件仍属 M01）、应用内通知中心、Service Worker 离线缓存。

## 2. 范围

- 后端模块 `apps/api/src/semestra/modules/notifications/`：设备订阅、加密发送、提醒计划与发送、动态通知订阅、设置命名空间 `notifications`。
- 前端模块 `apps/web/src/modules/notifications/`：`public/sw.js`、本设备状态 `push.ts`、设置分组“通知”、onboarding 步骤。
- 番茄钟（M14）的完成通知改走本模块的 `showLocal`。

## 3. 数据模型

| 表 | 说明 |
|---|---|
| `notifications_devices` | 一个浏览器的推送订阅：`session_id`（FK `auth_sessions`，级联删除）、`endpoint`（唯一）、`p256dh`、`auth`、`created_at`、`last_seen_at` |
| `notifications_reminders` | 未来 36 小时内的提醒计划：`key`（`<occurrence id>:<开始时间>:<提前分钟>` 或摘要键，按用户唯一；含开始时间，改了时间会按新时间再提醒）、`kind`、`program_id`（FK，级联）、`fire_at`、`expires_at`、`params`、`status`（`pending`/`sent`/`skipped`） |

- 设备属于登录会话：退出登录、撤销会话、会话过期后不再发送；同一 endpoint 再次登记会移到当前会话。
- 两张表都是可再生的派生数据，不进备份（`portability` 覆盖测试的 `NOT_ADAPTED` 列出 `notifications_`）。

## 4. 后端

### 4.1 发送（`webpush.py`、`service.py`）

- 加密 `aes128gcm`（`http_ece`），VAPID 用 `py_vapid`。VAPID P-256 私钥由 `SEMESTRA_SECRET_KEY` 经 HKDF 派生，不另存；更换密钥后前端发现服务器公钥变化，会自动重新订阅。JWT 有效期 55 分钟（Apple 拒绝超过 1 小时的令牌），`sub` 用 `public_web_origin`（https）或 `mailto:` 发件地址。
- 只允许发往已知推送服务：`fcm.googleapis.com`、`*.push.services.mozilla.com`、`*.push.apple.com`、`*.notify.windows.com`，只能 https、443 端口，经 `core/http.safe_client` 发出。
- 404/410 视为订阅失效，删除该设备。
- 文本由服务器渲染（M00 的例外之一）：`texts/<locale>.json`，`$变量` 占位，按用户语言与时间格式。负载 `{title, body, url, tag, hidden_only}`。
- `notify_after_commit(ctx, Message, user_id=…, exclude_session=…)`：提交后在系统上下文里检查设置与免打扰再发送。推送不走 `core_jobs`（否则会出现在状态条）。

### 4.2 提醒（`reminders.py`）

- 来源：课程与事件来自日历聚合（M04 `collect()`）的 `schedule.meetings`、`schedule.events`；截止提醒只来自未完成的待办（M05 `tasks.service.program_rows(open_only=True)`，包括每个有日期的考核对应的那条待办），所以勾掉考核的待办（已提交）就不再提醒，不另读 `grading.assessments`。全天项不单独提醒，计入每日摘要。
- 计划：每 6 小时（`@periodic notifications.reminders.plan`）、收到 `calendar.changed`（只重算该学业项目）、`settings.values.updated`（命名空间 `notifications`）和第一次登记设备时，删掉待发的行，重新生成未来 36 小时的行。没有设备的用户不生成。
- 计划时保留 `fire_at` 在最近 15 分钟内的行（刚到点、还没被 tick 发出的不会因重新计划丢失；已发的行靠唯一键挡住重复）。
- 发送：每分钟（`notifications.reminders.send`）取到点的行，用 `UPDATE … WHERE status='pending' RETURNING` 原子认领（多进程同时跑 tick 也不会重复发送），每发一条提交一次（等推送服务时不持有写锁）；晚于 15 分钟的标记 `skipped`；落在免打扰时段的标记 `skipped`（不顺延）。
- 时区：每日摘要与免打扰按当前学业项目的时区。

### 4.3 动态（`subscribers.py`）

| 事件 | 通知 | 开关 |
|---|---|---|
| `core.job.finished`（M00 新增，任务进入终态时派发，包括排队中取消与租约过期） | 导出完成/失败、恢复完成/失败、本地模型下载完成/失败、导入抽取失败 | `jobs` |
| `imports.session.ready` | 导入可以审核 | `jobs` |
| `agent.proposals.created`（M12 新增） | Sem 等待确认 | `assistant` |
| `auth.session.created`（M01 新增） | 新登录（不发给刚登录的会话） | `sign_in` |

动态通知带 `hidden_only`：有可见的 Semestra 标签页时 Service Worker 静音显示后立即关闭（订阅是 `userVisibleOnly`，静默推送会让 Safari 吊销订阅、Chrome 弹出默认提示）。新登录与提醒总是显示。只有会话仍有效的设备才算“有设备”（计划与发送用同一个条件 `service.live`）。

### 4.4 Canvas 更新（`watch.py`）

- `@periodic notifications.lms`（每 6 小时，启动 10 分钟后第一次）：对有有效设备、`lms` 不是 `off` 的用户先取 M09 `lms.watch.watched_links`，再对每门课调用 `course_news(ctx, link_id, announcements=…)` 并立即提交（每门课一个事务，不在持有 SQLite 写锁时等平台响应），每门课每类一条通知：新成绩 `lms_grades_*`、作业变更（名称、截止、权重）`lms_changes_*`、新公告 `lms_announcements_*`（`_one`/`_other` 按条数）。点击打开课程成绩页；公告在装了 Canvas Tab 时打开它的公告页（只有一条时定位到该条），否则打开课程。
- 什么算“新”由 M09 决定并记住（M09 §4.7）：每项变化只报一次，课程第一次被检查、或距上次检查超过 2 天时只记录不报（服务器停机后恢复不会补发旧变化）。这些通知不带 `hidden_only`，应用在前台时也显示：应用里没有对应提示，而且变化已被记为报过。免打扰时段内不检查，留到之后，所以不会因此漏报。

### 4.5 其他模块的提醒（`reminder_source`）

- `reminders.reminder_source(kind, ReminderSource(plan, message))`：`plan(ctx, programs, since, end)` 返回 `Planned(key, program_id, fire_at, expires_at, params)`，与课程、待办提醒一起存进 `notifications_reminders`；`message(ctx, row)` 在到点时决定发什么，返回 `None` 不发。是否有提醒由该模块自己的设置决定；设备、免打扰、认领与发送仍在本模块。设置变化后由该模块调用 `reminders.plan(ctx, [program_id])`。
- 习惯打卡（M14）：卡片设置 `remind` + `remind_at`（学业项目时区），到点时今天没打卡（每周目标：本周还没达标且今天没打卡）才发 `habit_daily`/`habit_weekly`，点击打开卡片所在的看板。卡片设置变化（`layouts.card.settings_updated`）时重新计划；到点时重新读卡片和打卡记录，所以提前打卡、删卡、卸载插件后都不会再发。

## 5. 设置（命名空间 `notifications`，账户级）

| 字段 | 取值 | 默认 |
|---|---|---|
| `class_reminder` | `off`/`0`/`5`/`10`/`15`/`30`（提前分钟） | `10` |
| `event_reminder` | `off`/`0`/`15`/`30`/`60`/`1440` | `30` |
| `task_reminder` | `off`/`0`/`15`/`60`/`180`/`1440` | `60` |
| `daily_digest` | `off`/`6`…`10`（整点） | `8` |
| `jobs`、`assistant`、`sign_in` | 开关 | 开 |
| `lms` | `off`/`updates`（新成绩与作业变更）/`all`（再加新公告） | `updates` |
| `quiet_hours` + `quiet_start`/`quiet_end` | 开关 + `HH:MM` | 关，23:00–07:00 |

设置跟着账户走；某台设备收不收由它自己的订阅决定。

|---|---|

## 7. 前端

- `public/sw.js` 只处理 `push` 与 `notificationclick`：点击时让已打开的标签页导航（`semestra:navigate` 消息，`NotificationsSync` 接收），没有就打开新窗口。
- `push.ts` 是全应用唯一的设备状态（`checking`/`unsupported`/`install`/`off`/`blocked`/`on`）：`syncDevice`（每次启动重新登记，跟随当前会话）、`enableDevice`（必须在点击中调用）、`disableDevice`、`showLocal`（页面自己发的通知，只在 `on` 时）、`forgetDevice`（退出登录后退订，下一个登录的人不会继承）。iPhone/iPad 只有添加到主屏幕后才有 Web Push，未添加时状态为 `install`。
- 设置分组“通知”（个人，在“偏好”之后）：本设备（设备名 + 开关，开启后旁边是“发送测试通知”；被拦截或需要先添加到主屏幕时是一条 `Alert`）、提醒、动态、免打扰；后三个是 `notifications` 命名空间的生成表单，每类提醒一个下拉，第一项“关闭”；免打扰的两个时间用 `FieldOverrides.when` 挂在开关下，开启时展开。说明文字只留标签说不清的（`jobs`）。Canvas（`lms`）在动态里，是一个下拉。
- onboarding 步骤 `notifications.enable`（order 200，在连接 AI 之后，`available: canOffer`）：轮换的通知示例（减少动态效果时只显示第一条）、三类（课程与事件 / 待办 / 动态）各一个总开关，副标题显示当前取值，点整行展开该类的详细设置，底部“开启通知”。设置值和 schema 都加载完才显示分类（之前是同高的骨架），重新打开一类时恢复 schema 默认值。
