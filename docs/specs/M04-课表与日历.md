# M04 课表与日历（Schedule & Calendar）

> 依赖：M00、M02、M11。被依赖：M05、M03、M09（作为日历源注册方）、M08（ICS 导入写入课表）、M12。
> 核心模块（`kind: 'core'`）。替代旧版 `builtin-event-core` 插件中的课表与日历部分（待办拆到 M05）。

## 1. 目标与功能对齐
旧版功能（保留）：
- 事件类型（LECTURE/LEC、PRACTICAL/PRA、TUTORIAL/TUT，可自定义，带缩写、颜色、图标）。
- 课程教学班（section）：编号、类型、讲师、周模式（每周/隔周）、起止周；每个教学班有若干每周上课时间（meeting）：星期、开始/结束时间、地点、可选标题，按节启用/停用。周次只属于教学班，同一教学班的各节周次总是相同。界面中文译名：section＝教学班，meeting＝上课时间（不用「时间段」，Jinyuan 2026-10-20）。
- 课程事件（覆盖/附加时间、跳过、备注）。
- 从 ICS 导入课程时间段（如学校系统导出的课表）。
- 日历：周视图、月视图，学期周次标注（阅读周感知、阅读周停课），多来源叠加（课表、待办、考核截止、LMS 事件），来源筛选，周视图宽度可配置，导航状态记忆。
- 课表导出：PNG、PDF、ICS，可选周范围、跳过项的显示方式。
- 小部件：今日/本周课表摘要。
- 时间段冲突提示。

新版变化：
- 日历聚合在**后端**完成（`calendar.occurrence.list`），iOS、Agent、ICS 订阅共用同一份结果。
- 上课时间段挂在 **(课程, 学期)** 上，年课上下学期可以不同。
- 单次事件（考试、Office Hour、补课）与周期时间段分开建模；周期时间段的单次例外（停课、调课）用例外表。
- 新增 **ICS 订阅链接**（只读，可加到 Apple/Google 日历）。
- 新增 Program 级 **"今天"** 页面（手机上是议程列表，见 M17）。
- 事件类型提升为 Program 级（同一学校的类型约定一致）。

## 2. 领域模型
```
schedule_event_types
  id, user_id, program_id, code (大写, 如 "LEC"), name ("Lecture"), color? (token/hex), icon? (lucide 名),
  builtin (bool), position
  UNIQUE(program_id, code)
  # Program 创建时写入内置 LEC/PRA/TUT（name 显示时按 locale 翻译内置项）

schedule_sections                      # 教学班：共享的类型、编号、讲师与周次
  id, user_id, course_id, term_id, type_code, section_code ("LEC0101"，可为空), instructor?,
  recurrence ('weekly' | 'biweekly'), anchor_week (int, 隔周时从第几周开始),
  start_week (int, 默认 1), end_week? (int, 空=到学期末),
  skip_breaks (bool, 默认 true, 假期周不上课), created_at, updated_at
  CHECK end_week IS NULL OR end_week >= start_week
  UNIQUE(course_id, term_id, type_code, section_code) WHERE section_code != ''

schedule_meetings                      # 教学班的每周上课时间
  id, user_id, section_id (级联删除), title?, location?,
  weekday (1=周一..7=周日), start_time (Time), end_time (Time),
  enabled (bool), source_kind?, source_ref?, created_at, updated_at
  CHECK start_time < end_time

schedule_meeting_exceptions
  id, user_id, meeting_id, original_date (Date),
  kind ('cancelled' | 'moved'),
  new_date?, new_start_time?, new_end_time?, new_location?, note?
  UNIQUE(meeting_id, original_date)

schedule_events                        # 单次事件
  id, user_id, program_id, term_id?, course_id?, type_code?,
  title, start_at (UTC), end_at (UTC), all_day (bool), location?, note?,
  source_kind?, source_ref?, created_at, updated_at

schedule_feeds                         # ICS 订阅（每个 Program 至多一条未撤销）
  id, user_id, program_id, token_hash, prefix, token_encrypted?,
  sources JSON ["schedule", "assessments", "tasks", "lms"], created_at, last_fetched_at?, revoked_at?
```
- 时间语义：meeting 的星期与时间是 **Program 时区** 的本地时间；展开为具体时刻时按 Program 时区转换为 UTC，正确处理夏令时。
- 周次映射由 M02 的 `term_week_of` 提供。`skip_breaks=true` 时假期周不生成实例；`count_break_weeks=false` 时 `start_week/end_week` 按不计假期的周次解释。

## 3. 日历聚合
### 3.1 后端源注册
```python
@calendar_source("schedule.meetings")          # 本模块
async def meetings_source(ctx, q: OccurrenceQuery) -> list[Occurrence]: ...
```
`OccurrenceQuery(range_start, range_end, program_id, term_id?, course_ids?)`；
`Occurrence { id (稳定: "<source>:<ref>[:<date>]"), source, kind ('class'|'event'|'task'), title, start_at, end_at?, all_day, course_id?, type_code?, location?, color_ref?, status? ('cancelled'|'moved'|'done'|'overdue'), ref: {entity, id}, meta: {} }`。
已注册源：`schedule.meetings`、`schedule.events`（本模块）、`tasks.due`（M05：有截止日期的任务，已完成的标 `done`；每个有截止日期的考核都有一个任务，考核截止只经它显示）、`lms.events`（M09：LMS 自己的日历事件，不含作业）。日历只画三类东西：课、事件、待办；同一件事只出现一次，不需要跨源去重。

### 3.2 规则
- 范围上限 120 天；超过返回 `common.validation`。
- 结果按 start_at 排序；同一时间段的冲突检测：`class` 与 `class`/`event` 重叠时在 meta 中标记 `conflicts_with: [occurrence_id]`。
- 被取消的实例保留（status=cancelled），前端按偏好显示为划线或隐藏。
- 假期周在结果中附带 `breaks: [{name, start_date, end_date}]` 与 `weeks: [{week_number|null, start_date, label}]`，前端用于周标签。

| `schedule.meeting.create` | write | POST /sections/{section_id}/meetings | 给教学班加一节 |
| `schedule.meeting.update` | write | PATCH /meetings/{meeting_id} | 星期、时间、地点、标题、启用 |
| `schedule.meeting.delete` | destructive | DELETE /meetings/{meeting_id} | 删掉最后一节时教学班一并删除 |
| `schedule.meeting.set_enabled` | write | PUT /courses/{course_id}/meetings:enabled | 批量启用/停用（例如只保留自己所在的 TUT 段）；只返回状态有变化的 meeting |
| `schedule.exception.upsert` | write | PUT /meetings/{meeting_id}/exceptions/{original_date} | 取消或调课单次 |
| `schedule.exception.delete` | write | DELETE /meetings/{meeting_id}/exceptions/{original_date} | 恢复 |
| `schedule.event.create/update/delete` | write | /programs/{program_id}/events... | 单次事件 |
| `schedule.conflict.list` | read | GET /terms/{term_id}/schedule-conflicts | 每周模板中的冲突对 |
| `schedule.export.ics` | read | GET /programs/{program_id}/calendar.ics | 参数同 occurrences，返回文件（`routes.py`） |
| `schedule.feed.get` | read | GET /programs/{program_id}/calendar-feed | Program 的订阅链接（未开启为 `null`），含 `url` |
| `schedule.feed.create` | write | POST /programs/{program_id}/calendar-feed | 开启；已开启则返回现有链接 |
| `schedule.feed.update` / `reset` / `revoke` | write | PATCH /calendar-feeds/{id}、POST …/reset、DELETE /calendar-feeds/{id} | 改包含内容；换新地址（旧地址失效）；停用 |
| 订阅端点 | public | GET /feeds/{token}.ics | `routes.py`；按 token 生成，最近 12 个月 + 未来 6 个月；限流 |

事件：`schedule.section.created/updated/deleted`（payload: course_id、section_ids、program_id；上课时间与例外的增删改也发所属教学班的 `updated`）、`schedule.event.*`、`schedule.exception.*`、`schedule.event_type.*`、以及统一的 `calendar.changed`（任何源变化时由各模块发布，payload: program_id）。
订阅：`academics.course.deleting`、`academics.term.deleting`（删除相关教学班/event）、`academics.course.terms_changed`（删除不再关联学期的教学班，并清空该课程在这些学期的 event 的 `term_id`）、`academics.program.created`（写内置事件类型）。
前端失效：`calendar.changed` → `calendarOccurrenceList*`、`calendarTodayGet*`；`schedule.*` → `scheduleSection*`、`scheduleEvent*`。

## 5. 前端
### 5.1 Program Page `today`（"今天"）
- "今天"是 program 作用域下的固定 Page，**页面主体是一个卡片网格（Board，作用域类型 `today`，`scope_id` 为 program_id）**，复用 M10 的编辑模式、添加卡片、默认模板；M14 的个人类小插件（番茄钟、习惯打卡、便签、计数器、世界时钟）声明 `scopes` 含 `today` 后可以放在这里。
- 固定页头（不是卡片）：日期、当前学期第 N 周（或假期名）。
- 本模块与 M05 提供的默认卡片，默认布局为：`schedule.today`（xl）→ `schedule.upcoming`（l）→ `tasks.today`（l）。
  - `schedule.today`：今天的课程与事件时间线（时间、课程颜色条、类型缩写、地点、取消/调课标记），当前时间指示线，下一节课倒计时。
  - `schedule.upcoming`：未来 7 天到期的未完成待办（含考核的待办），按日期分组。
  - `tasks.today`（M05）：今日待办与逾期，可直接勾选完成。
- 移除原来的扩展点 `schedule.todaySections`，由卡片取代。
- 手机上不显示看板，换成议程列表（M17 `mobile/TodayAgenda`）：今天的课程与事件、到期待办，可勾选；卡片只在电脑上显示。

### 5.2 学期 Page `calendar`
- 使用 FullCalendar 7（`@fullcalendar/react` 一个包，插件从 `@fullcalendar/react/daygrid`、`/timegrid`、`/list`、`/interaction` 导入，均为 MIT 部分；peer 依赖 `temporal-polyfill`）。
- 视图：周（默认）、月、日程列表、**课表**（不带日期的一周模板视图，展示 enabled 的 meeting，冲突处并排显示并带警示图标）。
- 周标签显示学期周次（"第 5 周"/"阅读周"）；假期周背景着色。
- 左侧筛选面板：来源开关（课表、事件、考核截止、待办、LMS）、课程多选（颜色点）、显示取消的课程；状态存 `useUiPref('calendar.filters.<termId>')`。
- 交互：点击实例弹出详情卡（课程、时间、地点、来源，操作：打开来源、对课表实例"取消本次/调课/编辑整个教学班"）；拖拽空白创建单次事件；拖动单次事件改时间；拖动 meeting 实例时询问"只改这一次（生成例外）/修改整个教学班"。
- 导航状态（当前视图、日期）存 UI 偏好，返回页面时恢复；"今天"按钮。
- 偏好（M11 calendar 分区，本模块提供）：默认视图、显示时间范围（默认 8:00–22:00）、是否显示周末、周视图最小列宽（宽屏横向滚动）、取消的课显示方式（划线/隐藏）。
- 前端渲染契约 **`CalendarSourceContribution`**（M00 manifest 字段 `calendarSources`）：`{ source: 'tasks.due', label, icon, defaultVisible, onOpen(occurrence, navigate), complete?, reschedule?, create? }`，用于筛选面板标签与点击行为；数据本身全部来自后端。`complete(occurrence, completed)`：条目上显示复选框，勾选立即保存（乐观更新，失败恢复），详情里有“标记为完成/未完成”；`reschedule: { allowed, save }`：可拖到别的日期或时间（拖到全天行保留原来的时间），`allowed` 为假的不能拖（考核的待办）；周视图把 `kind: task` 的条目都放在全天行（有时间的在标题前显示时间，按截止时间排序），因为待办是时间点而不是时段，23:59 截止的会落在显示的时段之外；没有结束时间的条目按 1 分钟画，不会跨到第二天；`create: { label, form }`：日历“新建”对话框顶部的分段切换多一个选项（“事件 | 待办”），选中后换成该源的表单（`preloadable`，打开对话框时预加载）。

### 5.3 课程 Page `schedule`
- 按学期分组（年课显示两个学期页签），每个学期内按事件类型分组列出 meeting：教学班编号、星期、时间、周模式、周范围、地点、讲师、启用开关（停用的灰显）。
- 布局自上而下分三块，每块有标题和一句说明；添加入口是每块标题右侧的 outline 小按钮（有数据时显示；没有数据时在空状态里），不在表格末行，也不再有页面顶部的统一"添加"菜单：
  1. **每周上课时间**：标题右侧是「从已有资料添加」下拉（扩展点 **`schedule.meetingImportSources`** 的来源，M08 贡献 ICS 与课表截图）和「添加教学班」；下面是全宽周视图（块标题为教学班编号）和一张教学班表（2026-11-07 改版）。表格**每个教学班一行**（按 Program 的类型顺序、再按编号排）：展开按钮、整体开关（有一节开着就显示开，关掉即关闭全部）、编号（第二行是类型与讲师）、上课时间汇总（同一时间的几天合并，如「周一、周三 10:00 – 11:00」）、地点、周次和 ⋯ 菜单（编辑教学班、添加时间、只保留这个教学班、删除教学班）。展开后每节课一行（浅底、淡入），开关与教学班同尺寸、稍向右缩进，有自己的星期与时间、地点和 ⋯（编辑上课时间）。
     - **教学班对话框**只放教学班的字段：类型、编号、讲师；「上课时间」是一张真正的表（TanStack Table：星期、开始、结束、地点、移除；移除是与假期表一致的 `destructive` 垃圾桶图标按钮），表格最后一行是「添加时间」（`ActionRow`），点击在表内追加一行（沿用上一行、顺延一天），对话框里不再叠加别的弹层；「周次」是一行分段选择「整个学期 / 指定周次」，默认整个学期（每周、第 1 周起到学期末、假期周不上课），选「指定周次」才展开重复（每周/隔周，隔周时填起始周）、起止周与「假期周不上课」三行。保存走 `schedule.section.save`，一个事务里写教学班并增、改、删它的时间；删除教学班走 `schedule.section.delete`。
     - **上课时间对话框**只放这一节的字段：星期、开始、结束、地点和可选标题；左下角删除这节课。教学班、讲师和周次只在教学班对话框里改。
     - 没有 meeting 时是带实线框的空状态，内含「添加教学班」主按钮。
  2. **单次事件**：表格 ⋯ 菜单编辑、删除，标题右侧「添加单次事件」；空状态里是同名链接按钮。
  3. **停课与调课**：表格每行可恢复，标题右侧「停课或调课」打开对话框（只列启用的教学班，顺序同表格；原定日期只能选该教学班在学期内真正上课的日子（取自日历源，已考虑隔周、周次范围与假期），日历限定在学期内；停课或调到新的日期、时间、地点）；空状态里是同名链接按钮。没有 meeting 也没有例外时整块不显示。
- 添加/编辑 meeting 对话框。

### 5.4 导出
- 日历页工具栏的「导出 ▾」（secondary 按钮，主按钮是「添加单次事件」）是一个菜单，三项各带一句说明，各自打开对话框（`components/ExportDialog.tsx` 的 `ShareDialog`），选项用设置行（`SettingsGroup`/`SettingRow`、`ChoiceControl`、每个来源一个 `Switch`）：
  - **图片或 PDF**：前端渲染（`modern-screenshot` 生成高分辨率 PNG；PDF 用 `pdf-lib` 嵌入图片，A4 横向）。左侧实时预览第一页，右侧选项：格式、范围（单周/多周/每周课表）、包含、已取消的课、主题。按日期排列各天（周起点为周日的 Program 不会画乱）。
  - **日历文件（.ics）**：范围默认整个学期，可选单周/多周与包含来源，调用 `schedule.export.ics` 下载；底部链接「要自动同步？用订阅链接」切到订阅。
  - **订阅链接**（`components/FeedPanel.tsx`）：仿 Google 日历的私密地址，每个 Program 一个链接。未开启时一行说明 +「开启」；开启后显示链接（复制、`webcal://` 用日历应用打开、添加到 Google 日历、上次同步时间），「包含」开关即时改内容（至少保留一项），「重置链接」与「停用链接」各有确认框。说明里写明知道链接的人都能看到。

### 5.5 Cards
- `schedule.today`（today/program/term，m/l/xl；today 作用域默认 xl）：今天的课程时间线，xl 为完整版，m/l 为精简版。时间列上下两行（开始、结束），点一行打开该事件（与日历的 `onOpen` 相同）。
- `schedule.upcoming`（today/program，m/l）：未来 7 天的截止，按日期分组。
- `schedule.week`（term/course，l/xl）：近几日课表迷你网格，从昨天开始，l 显示 5 天、xl 显示 7 天（隐藏周末时跳过周末，最多 5 天，同一个星期几不会出现两次），今天的列头高亮；时间轴只覆盖显示的课程（至少 4 小时），行高按卡片高度缩放，放不下再滚动；点课程打开对应详情。
- `schedule.next`（course，s）：这门课的下一次上课时间与地点。

### 5.6 设置分区
- Program 级"课程类型"：事件类型表格（code、名称、缩写显示、颜色、图标、排序；内置项可改颜色图标、不可删除）。
- 账户级"日历"：见 5.2 偏好。

## 6. Agent 集成
- 全部 capability 暴露；`calendar.today.get` 与 `calendar.occurrence.list` 是回答"我明天几点有课/这周有什么 due"的主要工具（description 中写明优先使用 today）。
- Skills：
  - `answer-schedule-questions.md`：时间相关问题统一用 Program 时区解释"明天/下周三"；先 `calendar.today.get` 或带范围的 `calendar.occurrence.list`，回答时附上周次。

## 实现说明（M04 落地时补充）
以下是实现时做出的取舍与对上文的细化，以代码为准。

**后端**（`apps/api/src/semestra/modules/schedule/`）
- 纯规则在 `rules.py`（实例展开、DST 换算、重叠判断），聚合注册表在 `calendar.py`：其他模块用 `@calendar_source("<模块>.<源>")` 注册 `async (ctx, OccurrenceQuery) -> list[Occurrence]`，`collect()` 负责过滤未注册的源、排序与冲突标记。`OccurrenceQuery.wants_course(course_id)` 是课程过滤的统一写法（`course_ids` 为空表示全部；指定课程时，不属于任何课程的条目被排除）。
- 日期范围一律是 `[start, end)`（`end` 为最后一天的下一天，Program 时区）。`calendar.occurrence.list` 上限 120 天；ICS 导出（`GET /programs/{id}/calendar.ics`，参数同 occurrences）放宽到 400 天，方便导出整学年。
- `calendar.today.get` 返回字段 `day`（不是 `date`，避免与 Pydantic 类型名冲突）、`week`（学期名、周次或假期名）、`items`（今天的课与事件）、`upcoming`（今天起 7 天的未完成任务）、`tasks`（今天到期与逾期的未完成任务）。
- 单次事件的 schema 名为 `OneOffEvent`（生成的 TS 类型 `Event` 会与 DOM 冲突）；另加了 `schedule.event.list`（课程页需要列出单次事件）。事件时间不带时区偏移时按 Program 时区解释；全天事件存为当地零点到最后一天的下一天零点。
- 事件类型的 `code` 创建后不可改（时间段与事件按 code 引用）；内置类型名称固定（前端按语言显示），可改颜色、图标、顺序，不可删除。删除使用中的类型返回 `schedule.event_type_in_use`（params: count）。
- 例外的 `original_date` 必须是该时间段按规则生成的日期；调课可以移到任意日期（包括假期周）。修改星期、学期、重复方式或起止周后，不再生成的日期上的例外会被删除（改回去也不会复活）。
- 起始时间落在春季夏令时跳过的那一小时里（如多伦多 3 月某个周日 02:30）时，开始时间顺延，课程保持原来的时长。`calendar` 设置的 `day_end` 只接受 `00:00`–`23:59` 和 `24:00`。
- 跨周期的周次：`count_break_weeks=false` 时，未编号的假期周沿用上一周的编号判断起止周；隔周时间段不会落在未编号的假期周。
- 订阅（`schedule.feed.*`）只暴露 HTTP，不给 agent/MCP：链接本身就是凭证。按 token 的 sha256 查找，token 另用 `core/security.encrypt` 加密保存，链接随时可再显示（0029 之前的链接只有哈希，界面提示重置；迁移时每个 Program 只保留最新一条）；`/feeds/{token}.ics` 每个 token 每小时 60 次（复用 M01 的持久化限流），窗口为过去 365 天到未来 183 天，读取时更新 `last_fetched_at`。
- 课程/学期/Program 删除的清理在 `*.deleting` 事务内完成，不发 `calendar.changed`（删除事件本身已让前端刷新）。课程解除学期关联是提交后的 `terms_changed`，清理在其后单独提交，所以会再发 `schedule.section.deleted`、`schedule.event.updated` 与 `calendar.changed`，避免前端在清理前重新拉到旧数据。
- ICS 导出另收 `exclude_course_ids`（日历筛选里隐藏的课程，没有课程的条目保留），与 PNG/PDF 导出一致。
- 设置命名空间 `calendar`（账户/Program/学期三级）：`default_view`、`day_start`、`day_end`、`show_weekends`、`min_column_width`、`cancelled_display`。

**前端**（`apps/web/src/modules/schedule/`）
- 日历用 FullCalendar 7.1（原生 React 实现）。FullCalendar 只认浏览器本地时间，所以把 Program 时区的“墙上时间”以不带偏移的 ISO 字符串喂给它，读回时再用 `@date-fns/tz` 转换（`time.ts`）；浏览器时区与 Program 不同也能正确显示与拖动。`plugins`、`locales` 必须是模块级常量，否则每次渲染都会重置视图、反复触发 `datesSet`。
- 事件请求的日期范围不从 FullCalendar 的 `datesSet` 读，而是由 `occurrenceRange(视图, 日期, 一周起始日)` 自己算（周视图/列表为所在周，月视图为该月的六周网格，覆盖 FullCalendar 实际显示的范围），所以页面 `prefetch` 能在日历画出来之前就发出首屏请求；当前范围加载完后再预取前后各一个范围，翻页时不会先出现空周。

- 课表视图（timetable）与课程页的周预览、导出共用一个不依赖 FullCalendar 的静态周网格 `components/WeekGrid.tsx`（重叠项并排、冲突标记）。学期课表与导出用 `schedule.section.list_for_term`（`GET /terms/{term_id}/sections`，只开放 HTTP）一次取全。

**教学班表（2026-11-08，迁移 0037）**
- 原来教学班只是“同课程、学期、类型、编号的若干上课时间”，周次存在每节上，所以一个教学班的各节可能周次不同，界面只能显示「各不相同」。现在 `schedule_sections` 保存类型、编号、讲师和周次，`schedule_meetings` 只保存星期、时间、地点、标题与启用状态，结构上不会再出现各节周次不同。迁移不改动任何一节课：同一（用户、课程、学期、类型、编号）下周次相同（重复方式、隔周起始周（仅隔周）、起止周、假期周不上课都相同）的各节合成一个教学班；同一编号下周次不同时，节数最多的周次组保留编号（并列时取按星期、开始时间、id 排第一的那节所在的组），其余每组各成一个不带编号的教学班，编号写进这些节的 `title`（原来有标题的保留原标题）；没有编号的每节各成一个教学班。讲师取组内第一个非空的。
- 同一课程、学期、类型下编号唯一（编号为空的不限），冲突返回 `schedule.section_exists`（409）。只想让某一节从第 N 周起上课，用例外（停课）或拆成单独的教学班。
- `schedule.section.create_many`（导入与 Sem 共用）遵循同一规则：带周次的条目，编号对应的教学班周次相同就加入；周次不同时不改那个教学班，条目成为不带编号的教学班（节的标题为编号），重复导入按 source 找回；只有同一次调用里该编号、相同周次的条目合起来包含该教学班的全部节（整班重复导入）时才改它的周次。导入（M08）每条 `meeting` 用自己的周次，同一教学班（课程、学期、类型、编号）的各条在一次调用里写入（失败时退回逐条写入，各自记录错误），所以不会生成文件里没有的课，也不会改已有教学班的周次。
- 日历条目 `meta` 带 `section_id`；`updated_at` 取上课时间与教学班中较新的那个。备份格式 schedule v2（不读旧版）。
