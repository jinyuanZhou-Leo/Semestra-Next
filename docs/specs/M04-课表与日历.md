# M04 课表与日历（Schedule & Calendar）

> 依赖：M00、M02、M11。被依赖：M05、M03、M09（作为日历源注册方）、M08（ICS 导入写入课表）、M12。
> 核心模块（`kind: 'core'`）。替代旧版 `builtin-event-core` 插件中的课表与日历部分（待办拆到 M05）。

## 1. 目标与功能对齐
旧版功能（保留）：
- 事件类型（LECTURE/LEC、PRACTICAL/PRA、TUTORIAL/TUT，可自定义，带缩写、颜色、图标）。
- 课程上课时间段（section）：编号、类型、标题、讲师、地点、星期、开始/结束时间、周模式（每周/隔周）、起止周；按段启用/停用。
- 课程事件（覆盖/附加时间、跳过、备注）。
- 从 ICS 导入课程时间段（如学校系统导出的课表）。
- 日历：周视图、月视图，学期周次标注（阅读周感知、阅读周停课），多来源叠加（课表、待办、考核截止、LMS 事件），来源筛选，周视图宽度可配置，导航状态记忆。
- 课表导出：PNG、PDF、ICS，可选周范围、跳过项的显示方式。
- 小部件：今日/本周课表摘要。
- 时间段冲突提示。

新版变化：
- 日历聚合在**后端**完成（`calendar.occurrences`），iOS、Agent、ICS 订阅共用同一份结果。
- 上课时间段挂在 **(课程, 学期)** 上，年课上下学期可以不同。
- 单次事件（考试、Office Hour、补课）与周期时间段分开建模；周期时间段的单次例外（停课、调课）用例外表。
- 新增 **ICS 订阅链接**（只读，可加到 Apple/Google 日历）。
- 新增 Program 级 **"今天"** 页面（移动端也可用）。
- 事件类型提升为 Program 级（同一学校的类型约定一致）。

## 2. 领域模型
```
schedule_event_types
  id, user_id, program_id, code (大写, 如 "LEC"), name ("Lecture"), color? (token/hex), icon? (lucide 名),
  builtin (bool), position
  UNIQUE(program_id, code)
  # Program 创建时写入内置 LEC/PRA/TUT（name 显示时按 locale 翻译内置项）

schedule_meetings                      # 周期性上课时间段
  id, user_id, course_id, term_id, section_code ("LEC0101"), type_code,
  title?, instructor?, location?,
  weekday (1=周一..7=周日), start_time (Time), end_time (Time),
  recurrence ('weekly' | 'biweekly'), anchor_week (int, 隔周时从第几周开始),
  start_week (int, 默认 1), end_week? (int, 空=到学期末),
  skip_breaks (bool, 默认 true, 假期周不上课),
  enabled (bool), source_kind?, source_ref?, created_at, updated_at
  CHECK start_time < end_time

schedule_meeting_exceptions
  id, user_id, meeting_id, original_date (Date),
  kind ('cancelled' | 'moved'),
  new_date?, new_start_time?, new_end_time?, new_location?, note?
  UNIQUE(meeting_id, original_date)

schedule_events                        # 单次事件
  id, user_id, program_id, term_id?, course_id?, type_code?,
  title, start_at (UTC), end_at (UTC), all_day (bool), location?, note?,
  source_kind?, source_ref?, created_at, updated_at

schedule_feeds                         # ICS 订阅
  id, user_id, program_id, token_hash, prefix, name,
  sources JSON ["schedule", "assessments", "tasks", "lms"], created_at, last_fetched_at?, revoked_at?
```
- 时间语义：meeting 的星期与时间是 **Program 时区** 的本地时间；展开为具体时刻时按 Program 时区转换为 UTC，正确处理夏令时。
- 周次映射由 M02 的 `term_week_of` 提供。`skip_breaks=true` 时假期周不生成实例；`count_break_weeks=false` 时 `start_week/end_week` 按不计假期的周次解释。

## 3. 日历聚合
### 3.1 后端源注册
```python
@calendar_source("schedule.meetings")          # 本模块
async def meetings_source(ctx, q: OccurrenceQuery) -> list[Occurrence]: ...
```
`OccurrenceQuery(range_start, range_end, program_id, term_id?, course_ids?)`；
`Occurrence { id (稳定: "<source>:<ref>[:<date>]"), source, kind ('class'|'event'|'deadline'|'task'), title, start_at, end_at?, all_day, course_id?, type_code?, location?, color_ref?, status? ('cancelled'|'moved'|'done'|'overdue'), ref: {entity, id}, meta: {} }`。
已注册源：`schedule.meetings`、`schedule.events`（本模块）、`grading.assessments`（M03：截止时间为 deadline）、`tasks.due`（M05：有截止日期的未完成任务）、`lms.events`（M09：LMS 日历事件，可选）。

### 3.2 规则
- 范围上限 120 天；超过返回 `common.validation`。
- 结果按 start_at 排序；同一时间段的冲突检测：`class` 与 `class`/`event` 重叠时在 meta 中标记 `conflicts_with: [occurrence_id]`。
- 被取消的实例保留（status=cancelled），前端按偏好显示为划线或隐藏。
- 假期周在结果中附带 `breaks: [{name, start_date, end_date}]` 与 `weeks: [{week_number|null, start_date, label}]`，前端用于周标签。

事件：`schedule.meeting.*`、`schedule.event.*`、`schedule.exception.*`、`schedule.event_type.*`、以及统一的 `calendar.changed`（任何源变化时由各模块发布，payload: program_id）。
订阅：`academics.course.deleting`、`academics.term.deleting`（删除相关 meeting/event）、`academics.course.terms_changed`（删除不再关联学期的 meeting）、`academics.program.created`（写内置事件类型）。
前端失效：`calendar.changed` → `calendarOccurrences*`、`calendarToday*`；`schedule.*` → `scheduleMeeting*`、`scheduleEvent*`。

## 5. 前端
### 5.1 Program Page `today`（"今天"，移动端可用）
- "今天"是 program 作用域下的固定 Page，**页面主体是一个卡片网格（Board，作用域类型 `today`，`scope_id` 为 program_id）**，复用 M10 的编辑模式、添加卡片、默认模板；M14 的个人类小插件（番茄钟、习惯打卡、便签、计数器、世界时钟）声明 `scopes` 含 `today` 后可以放在这里。
- 固定页头（不是卡片）：日期、当前学期第 N 周（或假期名）。
- 本模块与 M05 提供的默认卡片，默认布局为：`schedule.today`（xl）→ `schedule.upcoming`（l）→ `tasks.today`（l）。
  - `schedule.today`：今天的课程与事件时间线（时间、课程颜色条、类型缩写、地点、取消/调课标记），当前时间指示线，下一节课倒计时。
  - `schedule.upcoming`：未来 7 天的 deadline（考核、带截止的任务），按日期分组。
  - `tasks.today`（M05）：今日待办与逾期，可直接勾选完成。
- 移除原来的扩展点 `schedule.todaySections`，由卡片取代。
- 窄屏布局为单列（M10 的 1 列规则），手机上可查看与勾选，编辑布局建议在桌面端。

### 5.2 学期 Page `calendar`
- 使用 FullCalendar（`@fullcalendar/react` + daygrid、timegrid、list、interaction，均为 MIT 部分）。
- 视图：周（默认）、月、日程列表、**课表**（不带日期的一周模板视图，展示 enabled 的 meeting，冲突处并排显示并带警示图标）。
- 周标签显示学期周次（"第 5 周"/"阅读周"）；假期周背景着色。
- 左侧筛选面板：来源开关（课表、事件、考核截止、待办、LMS）、课程多选（颜色点）、显示取消的课程；状态存 `useUiPref('calendar.filters.<termId>')`。
- 交互：点击实例弹出详情卡（课程、时间、地点、来源，操作：打开来源、对课表实例"取消本次/调课/编辑整个时间段"）；拖拽空白创建单次事件；拖动单次事件改时间；拖动 meeting 实例时询问"只改这一次（生成例外）/修改整个时间段"。
- 导航状态（当前视图、日期）存 UI 偏好，返回页面时恢复；"今天"按钮。
- 偏好（M11 calendar 分区，本模块提供）：默认视图、显示时间范围（默认 8:00–22:00）、是否显示周末、周视图最小列宽（宽屏横向滚动）、取消的课显示方式（划线/隐藏）。
- 前端渲染契约 **`CalendarSourceContribution`**（M00 manifest 字段 `calendarSources`）：`{ source: 'grading.assessments', label, icon, defaultVisible, onOpen(occurrence, navigate) }`，用于筛选面板标签与点击行为；数据本身全部来自后端。

### 5.3 课程 Page `schedule`
- 按学期分组（年课显示两个学期页签），每个学期内按事件类型分组列出 meeting：时间段编号、星期、时间、周模式、周范围、地点、讲师、启用开关（停用的灰显）。
- 添加/编辑 meeting 对话框；"从 ICS 导入"入口（M08 贡献，扩展点 **`schedule.meetingImportSources`**）。
- 单次事件列表（考试、补课）与"例外"列表（停课、调课），可恢复。
- 本课程的迷你周视图预览。

### 5.4 导出
- 课表视图与周视图提供"导出"：
  - **PNG / PDF**：前端渲染（`modern-screenshot`/`html-to-image` 生成高分辨率 PNG；PDF 用 `pdf-lib` 嵌入图片，A4 横向）。选项：周（单周/周范围/学期模板）、包含来源、取消的课显示方式、明暗主题。
  - **ICS**：调用 `schedule.export.ics` 下载。
  - **订阅**：创建订阅链接、复制、撤销（说明：链接任何人可读，请勿公开分享）。

### 5.5 Cards
- `schedule.today`（today/program/term，m/l/xl；today 作用域默认 xl）：今天的课程时间线，xl 为完整版，m/l 为精简版。
- `schedule.upcoming`（today/program，m/l）：未来 7 天的截止，按日期分组。
- `schedule.week`（term/course，l/xl）：本周课表迷你网格。
- `schedule.next`（course，s）：这门课的下一次上课时间与地点。

### 5.6 设置分区
- Program 级"课程类型"：事件类型表格（code、名称、缩写显示、颜色、图标、排序；内置项可改颜色图标、不可删除）。
- 账户级"日历"：见 5.2 偏好。

## 6. Agent 集成
- 全部 capability 暴露；`calendar.today` 与 `calendar.occurrences` 是回答"我明天几点有课/这周有什么 due"的主要工具（description 中写明优先使用 today）。
- Skills：
  - `answer-schedule-questions.md`：时间相关问题统一用 Program 时区解释"明天/下周三"；先 `calendar.today` 或带范围的 `calendar.occurrences`，回答时附上周次。
  - `edit-class-schedule.md`：取消单次课用 `schedule.exception.upsert`，不要删除整个 meeting；新建 meeting 前用 `schedule.conflicts` 提醒冲突。

## 7. 错误码
`schedule.term_not_in_course`、`schedule.time_range_invalid`、`schedule.week_range_invalid`、`schedule.event_type_in_use`（params: count）、`schedule.range_too_large`、`schedule.feed_revoked`。

## 实现说明（M04 落地时补充）
以下是实现时做出的取舍与对上文的细化，以代码为准。

**后端**（`apps/api/src/semestra/modules/schedule/`）
- 纯规则在 `rules.py`（实例展开、DST 换算、重叠判断），聚合注册表在 `calendar.py`：其他模块用 `@calendar_source("<模块>.<源>")` 注册 `async (ctx, OccurrenceQuery) -> list[Occurrence]`，`collect()` 负责过滤未注册的源、排序与冲突标记。`OccurrenceQuery.wants_course(course_id)` 是课程过滤的统一写法（`course_ids` 为空表示全部；指定课程时，不属于任何课程的条目被排除）。
- 日期范围一律是 `[start, end)`（`end` 为最后一天的下一天，Program 时区）。`calendar.occurrences` 上限 120 天；ICS 导出（`GET /programs/{id}/calendar.ics`，参数同 occurrences）放宽到 400 天，方便导出整学年。
- `calendar.today` 返回字段 `day`（不是 `date`，避免与 Pydantic 类型名冲突）、`week`（学期名、周次或假期名）、`items`（今天的课与事件）、`upcoming`（今天起 7 天的 deadline 与任务）、`tasks`（今天到期与逾期的任务）。
- 单次事件的 schema 名为 `OneOffEvent`（生成的 TS 类型 `Event` 会与 DOM 冲突）；另加了 `schedule.event.list`（课程页需要列出单次事件）。事件时间不带时区偏移时按 Program 时区解释；全天事件存为当地零点到最后一天的下一天零点。
- 事件类型的 `code` 创建后不可改（时间段与事件按 code 引用）；内置类型名称固定（前端按语言显示），可改颜色、图标、顺序，不可删除。删除使用中的类型返回 `schedule.event_type_in_use`（params: count）。
- 例外的 `original_date` 必须是该时间段按规则生成的日期；调课可以移到任意日期（包括假期周）。
- 跨周期的周次：`count_break_weeks=false` 时，未编号的假期周沿用上一周的编号判断起止周；隔周时间段不会落在未编号的假期周。
- 订阅（`schedule.feed.*`）只暴露 HTTP，不给 agent/MCP：链接本身就是凭证。token 只存 sha256 与前 6 位；`/feeds/{token}.ics` 每个 token 每小时 60 次（复用 M01 的持久化限流），窗口为过去 365 天到未来 183 天，读取时更新 `last_fetched_at`。
- 清理（课程/学期/Program 删除、课程解除学期关联）在 `*.deleting` 事务内完成，不发 `calendar.changed`（删除事件本身已让前端刷新）。
- 设置命名空间 `calendar`（账户/Program/学期三级）：`default_view`、`day_start`、`day_end`、`show_weekends`、`min_column_width`、`cancelled_display`。

**前端**（`apps/web/src/modules/schedule/`）
- 日历用 FullCalendar 6.1（7.x 的 React API 不同）。FullCalendar 只认浏览器本地时间，所以把 Program 时区的“墙上时间”以不带偏移的 ISO 字符串喂给它，读回时再用 `@date-fns/tz` 转换（`time.ts`）；浏览器时区与 Program 不同也能正确显示与拖动。`plugins`、`locales` 必须是模块级常量，否则每次渲染都会重置视图、反复触发 `datesSet`。
- `CalendarSourceContribution.onOpen(occurrence, navigate, { programId })`：比上文多了第三个参数，因为 Occurrence 不带 Program。
- "今天"页的卡片网格用 `<CardGrid scope board="today">`；`BoardKind`、`useCards(board)`、manifest 的 `defaultBoard`（`{ card, size? }`）与 M10 约定一致。M10 合并后需要运行 `pnpm --filter @semestra/web manifest:export` 更新 `web_manifest.json`。
- 课表视图（timetable）与课程页的周预览、导出共用一个不依赖 FullCalendar 的静态周网格 `components/WeekGrid.tsx`（重叠项并排、冲突标记）。没有“按学期列出时间段”的接口，学期课表按课程并行请求（一个学期的课程数很少）。
- 筛选状态存 `calendar.filters.<termId>`（来源开关、隐藏的课程、是否显示取消的课；记“隐藏”而不是“显示”，新课程默认出现），导航状态存 `calendar.nav.<termId>`。课程过滤在前端做，这样不属于课程的个人事件不会被筛掉。
- 拖动单次事件直接改时间；拖动课次弹出“只改这一次 / 修改整个时间段”，已调过的课次只能改这一次；关闭询问即复位。拖到全天行或跨天的课次直接复位。
- 导出：PNG/PDF 在前端渲染（`modern-screenshot`，PDF 用 `pdf-lib`，每周一页 A4 横向），选项为单周/多周/学期模板、来源、取消的课显示方式、明暗主题；ICS 走 `lib/api-extras.ts` 的 `downloadFile`（该接口不在 OpenAPI 里）。
- 删除时间段、删除事件、删除类型、撤销订阅是仅有的确认框（不可撤销）；取消本次课不确认，可在详情或课程页“停课与调课”里恢复。
- 扩展点 `schedule.meetingImportSources`（`types.ts`）：`{ id, title, icon, description?, launch({ programId, courseId, termId }) }`，在课程课表页显示为按钮，M08 贡献 ICS/截图导入。
- `ui/table.tsx`、`ui/tabs.tsx` 是临时手写的 shadcn 同名组件（云端连不上 shadcn registry），导出名与 CLI 版一致；CLI 版进 main 后直接替换。
