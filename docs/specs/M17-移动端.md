# M17 移动端（手机网页）

> 依赖：M00（扩展契约）、M02（Program 路由与外壳）、M04（今天）、M05（待办）、M11（设置对话框）。被依赖：无。
> 只有前端，没有后端改动和新表。方案与样例见项目文档“移动端适配方案”（2026-10-29 定稿：范围甲、底部标签栏、今天用议程列表）。

## 1. 目标与约束
- 手机上能看今天的课、勾待办、记一条待办；其余功能留在电脑上。
- **桌面界面不因移动端改变**：桌面组件里不写手机分支、不加窄屏类名。验收时桌面页面截图与改动前逐像素一致。
- **桌面维护成本不上升**：手机是一个刻意保持很小的固定集合，桌面 PR 不需要考虑手机，除非改了手机也在用的 hook、纯函数的接口（类型检查会提示）。
- 以后的 iOS App 用 SwiftUI 原生写，和手机网页互不依赖；手机网页只求“能用”，也是 App 信息架构的原型。网页不做 Service Worker 和网页推送，推送以后交给 App（APNs）。

## 2. 结构
- **断点**：视口宽度 < 768px（与 shadcn `useIsMobile` 相同），或触屏（`pointer: coarse`）且高度 < 500px——手机横过来有 844–932px 宽，这样不会跳回桌面外壳、丢掉打开的抽屉和没输完的快速添加；鼠标/触控板设备是 `pointer: fine`，不受影响。`app/mobile/phone.ts` 的 `isPhone()` / `usePhone()`（`PHONE_QUERY`）用 `matchMedia` + `useSyncExternalStore`，首次渲染就有正确值，手机不会先画一次桌面外壳。iPad 两个方向都 ≥ 768px，用桌面界面；768–1023px 的桌面界面继续不保证（M00 §4）。
- **外壳**：`routes/_authed.p.$programId.tsx` 在手机上渲染 `app/mobile/MobileShell`（`preloadable`，loader 里预加载，桌面不下载），否则照旧渲染 `AppShell` + `<Outlet />`。手机外壳不渲染子路由组件：它自己读 `/_authed/p/$programId/$page` 的匹配结果，渲染该页的 `mobile.component`；其余地址（学期、课程、助手、设置页、导入等）显示“请在电脑上打开”，按钮回到第一个标签页；`/p/$programId` 跳到第一个标签页。
- **页面**：`PageContribution.mobile?: { component, tab?: { order } }`，只对 Program 页有效。带 `tab` 的页面按 `order` 进底部标签栏，最后固定一个“更多”。`preloadPage` 在手机上（任何作用域）只加载 `mobile.component`，不加载桌面页面、侧边栏导航和看板卡片，也不跑 `prefetch`；学期、课程页没有手机版，所以什么都不加载。
- **URL 不分叉**：手机和桌面用同一套地址（`/p/<id>/today`、`/p/<id>/tasks`），链接在两端都能打开，以后 App 的 Universal Links 也能对上。
- **桌面外壳**：`AppShell`、`AppSidebar`、`SidebarTerms`、`AssistantDock`、`AssistantPage`、`StatusBar` 不再有 `isMobile` 分支（桌面外壳不会在 768px 以下渲染）；`SidebarNavProps` 与 `AssistantContribution.SidebarNav` 去掉了只为关抽屉存在的 `onNavigate`。手机上没有任务状态条（M10）。

## 3. 隔离规则（`.oxlintrc.json` 的 `no-restricted-imports`）
- `apps/web/src` 里任何文件不能 import `**/mobile/*`，例外只有模块 `manifest.ts`（声明 `mobile.component`）、`routes/_authed.p.$programId.tsx`、`app/registry.ts` 和测试文件。
- 桌面代码也不能 import `@/hooks/use-mobile`（`useIsMobile`）：以前的 `isMobile` 分支就是这样混进来的。生成的 `src/ui/sidebar` 用它，不受影响。
- `**/mobile/**` 里的文件不能 import `**/pages/*`、`**/cards/*`、`@/app/board/*`、`@/app/host/*`（看板渲染 `CardGrid`、`PageHeader`、`StatusBar` 等桌面外壳部件；`PluginBoundary` 除外）、`@/modules/academics/shell/*`。手机代码只复用数据与逻辑：各模块的 `queries.ts`、`actions.ts`、`completion.ts`、`due.ts`、`quick-add.ts`（从 `QuickAdd` 抽出的状态 hook）、`lib/format`、`courseColor`，以及很小的叶子组件（`PriorityMarks`、`UserAvatar`、`TodaySubtitle`）。
- 文案共用 Paraglide，手机专用的放 `mobile_*`。

## 5. PWA
- `public/manifest.webmanifest`（`display: standalone`，`start_url: /login`：已登录会直接进应用，未登录先登录，不经过官网首页）与 `public/icons/`（192/512、maskable 512、`apple-touch-icon` 180，源文件 `icon.svg`：品牌蓝底白色学位帽）。
- `index.html` 只加了 manifest、`apple-touch-icon`、`apple-mobile-web-app-*` 和 `viewport-fit=cover`；不加 favicon 与 `theme-color`，免得桌面浏览器的标签页外观变化。底部标签栏与抽屉用 `env(safe-area-inset-bottom)` 让开 Home 指示条。
- `background_color`/`theme_color` 固定白色：manifest 没有按深浅色切换的写法，Android 在深色模式下启动已安装的应用时会闪一下白色启动画面，接受这一点。
- 没有 Service Worker：没有缓存失效问题，也不影响“部署后缺块刷新一次”。iOS 添加到主屏幕后的应用有独立 Cookie，需要在里面再登录一次。
