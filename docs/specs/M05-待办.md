# M05 待办（Tasks）

> 依赖：M00、M02、M04（日历源、"今天"扩展点）、M11。可选联动：M03（考核生成任务）。被依赖：M08/M09（导入为任务）、M12。
> 核心模块（`kind: 'core'`）。替代旧版 `builtin-event-core` 中的 Todo。

## 1. 目标与功能对齐
旧版功能（保留）：
- 学期级待办，类 Apple 提醒事项：分组（section）、任务（标题、备注、截止日期与时间、优先级 LOW/MEDIUM/HIGH/URGENT、完成状态、关联课程）。
- 分组内行内快速创建；行内编辑标题与课程标签；分组显示/隐藏与排序偏好持久化。
- 已完成汇总，一键清除已完成；破坏性操作二次确认。
- 课程页显示该课程的待办（与学期待办是同一份数据的过滤视图）。
- Program 级待办默认设置。
- 待办出现在日历中。

新版变化：
- 任务属于 **Program**，可选关联学期与课程（关联课程时学期自动取课程在任务截止日所在的学期，否则取当前学期）。这样年课的任务不会被困在某一个学期里。
- 智能列表：今天、计划中（有截止日期）、全部、已完成、按课程。
- 可选：考核自动生成任务（每个考核对应一个任务，截止日期随考核同步，完成任务不影响成绩）。

## 2. 领域模型
```
tasks_lists
  id, user_id, program_id, term_id? (空 = Program 级列表，所有学期可见),
  name, color?, icon?, position, created_at, updated_at
  UNIQUE(program_id, term_id, name)

tasks_items
  id, user_id, program_id, term_id?, course_id? (ON DELETE SET NULL), list_id? (ON DELETE SET NULL),
  title, notes (markdown, 默认 ""), due_date?, due_time? (Program 时区本地时间),
  priority ('none'|'low'|'medium'|'high'|'urgent'), flagged (bool),
  completed_at? (UTC), position (列表内手动排序，浮点/分数索引),
  source_kind? ('lms'|'syllabus'|'agent'|'manual'), source_ref?,
  assessment_id? (FK grading_assessments.id ON DELETE CASCADE),
  UNIQUE(user_id, source_kind, source_ref) WHERE source_kind = 'lms',
  UNIQUE(assessment_id) WHERE assessment_id IS NOT NULL
  created_at, updated_at

```
Program 级默认不建表，走 M11 设置命名空间 `tasks`（Program 级）：`default_priority`（默认 none）、`show_completed_in_lists`（默认 false）、`smart_parsing`（新待办标题的智能解析，默认 true，见 §5.1）。没有"默认列表"：未指定列表的任务归入"未归类"。

## 3. 业务规则
- 创建任务时：给了 `course_id` 未给 `term_id` → 取课程关联学期中包含截止日期的那个，没有截止日期则取包含今天的，否则取课程最早的学期。
- `list_id` 为空的任务显示在"未归类"（每个 Program 的虚拟列表，API 视图名仍是 `inbox`）。
- 完成：设置 `completed_at`；取消完成：清空。"清除已完成"删除指定范围（列表/学期/全部）内已完成任务，返回数量。
- 考核的待办（不变式）：**每个有截止日期的考核恰好有一个任务**，经 `assessment_id` 外键关联，只由 `tasks/auto.py` 维护，没有开关。订阅 `grading.assessment.created|updated`：创建或同步任务（标题 `"<课程 code> · <考核标题>"`，截止取考核 due，学期按课程与截止日推断，priority=medium）；考核出分或标为舍弃时任务自动完成；为已过截止日期的考核新建的任务照常未完成（逾期，交没交由用户勾选；owner 2026-11-07 决定），只有迁移 0033 把升级前已过期的考核的任务记为已完成（`completed_at` 取截止时间）；考核去掉截止日期时任务删除；考核删除时由同事务订阅 `grading.assessment.deleting` 删除任务并发 `tasks.item.deleted`（外键 CASCADE 兜底）。
- 考核的任务跟随考核：标题、截止日期与课程不能在待办里改（`tasks.item.update` 改动这些字段返回 409 `tasks.managed_by_assessment`，前端详情面板与行内编辑把它们设为只读，详情里的“成绩册”块链接到考核所在行）；也不能单独删除（`tasks.item.delete` 返回同一错误码，`fields: ["delete"]`），删除列表时它们移到“未归类”，“清除已完成”跳过它们；完成状态、优先级、标记、列表和备注可以改。Agent/MCP 不能把 `source_kind` 设为 `lms`（不传时记为 `agent`）。
- 排序：列表内默认按 `position`；可选按截止日期、优先级、创建时间、标题（偏好）。
- 逾期：未完成且截止时间早于现在（Program 时区）。

订阅：`academics.course.deleting`（清空 course_id）、`academics.term.deleting`（删除该学期的列表，任务的 term_id 置空并移入未归类）、`academics.program.deleting`、`grading.assessment.*`（自动任务）。
前端失效：`tasks.*` → `tasksItem*`、`tasksList*`、`tasksItemCount*`。

## 5. 前端
### 5.1 学期 Page `tasks`（也可从 Program 级入口进入，显示 Program 全部）
- 左栏：智能列表（今天、计划中、全部、已标记、已完成，带数量）+ 未归类 + 用户列表（学期列表在上，Program 级列表在下）+ "按课程"折叠组（本学期课程，颜色点）。新建列表、拖拽排序。
  （2026-10-31 改回页面左栏）这些入口在待办页自己的左栏（`components/TaskLists.tsx` 的 `TaskListsColumn`，嵌套的 shadcn `Sidebar collapsible="none"`，宽 14rem，随页面滚动时吸顶；"按课程"默认折叠，UI 偏好 `tasks.sidebar_courses_open`），Program 与学期的待办页都有；应用侧边栏里不再展开子项，切到别的页面时侧边栏不会变形。页面宽度不到 720px 时左栏隐藏，页面标题变成列表下拉菜单，当前列表旁的 ⋯ 提供重命名、上移/下移、删除。课程待办页仍是分段控件。
- 右栏：标题行右侧是排序和"新待办"按钮（快捷键 `N`），下面是任务列表，列表末尾有一行空心圆圈。按钮和空心圆圈都打开同一个新待办行：标题、备注和与编辑行相同的属性小块（日期、时间、优先级、课程、标记），初始值跟随当前列表（"今天"/"计划中"默认今天到期，"已标记"默认标记，课程列表默认该课程，优先级取设置里的默认值）；回车添加并留在这一行继续输入，点击行外添加已输入的内容并收起，Esc 放弃。空列表在打开新待办行时用它替换空状态。（2026-11-07 起不再有顶部快速添加框，手机端同样改为新待办抽屉，见 M17。）新待办的标题会被实时解析（2026-11-12 恢复，`parse.ts` + `dates.ts` + `draft.ts` 的 `useNewTaskDraft`，桌面新待办行与手机抽屉共用）：日期与时间用 chrono-node（只引入 `chrono-node/en` 与 `chrono-node/zh/hans`，界面语言优先；`dates.ts` 在第一次输入新待办时才按需加载），按 Program 时区的当前时刻计算相对日期，只收 chrono 标为确定的日（`day`/`weekday`）或确定上下午的钟点（单独的“一点”“at 3”“3月”不算）；最后一个独立的 `!`/`!!`/`!!!`（含全角；紧跟汉字时要两三个）为低/中/高优先级；课号（字母 + 数字，可带空格与后缀，不区分大小写）与小块可选的课程比对，完整课号或唯一对上一门课的前缀才算（课程页里不识别）。识别出的词在标题里加底色（`components/TitleInput.tsx`：输入框文字透明，上面叠一层同样排版的副本），它设置的小块用同样的底色（`TITLE_TINT`，与 Sem 的引用一致）；保存时这些词从标题中去掉（中文两侧不补空格）；点带底色的词即保留为文字，手动改小块则以手动值为准（只改时间时日期仍跟随标题）；整个标题只剩日期或记号时不识别。编辑已有待办的标题不解析。设置 `tasks.smart_parsing`（Program 级，默认开）关闭时整个解析不运行，chrono-node 也不加载。每行：圆形勾选框、标题（单击标题或备注即把这一行就地展开编辑，参照 Apple 提醒事项：标题可改，下面是灰色占位的「备注」和一排属性小块：日期、时间（有日期时）、优先级、课程、标记，小块改动立即保存；同一时间只展开一行，点另一行时前一行先保存再收起；回车或点击行外保存并收起，Esc 放弃标题与备注的修改；标题清空后收起即直接删除、不确认；展开收起不做高度动画）；待办出现与消失有高度与透明度的过渡（`components/presence.tsx`，motion 的 `AnimatePresence`）：新添加的行从零高度展开，完成、删除或移出列表的行收起，周围的行随之平滑移动；虚拟列表里滚出视口的行、首次加载以及一次增减超过 3 行（切换列表）都不播放，减少动态效果时不播放、优先级记号放在标题前（照 Apple 提醒事项：`!` 低=灰色、`!!` 中=`warning`、`!!!` 高=`destructive`，都不跟随强调色；无优先级不显示）、已标记旗子、截止（相对时间，逾期红色）、课程标签（课程颜色，点击更换）；行尾的标记（旗子）按钮和 `⋯` 菜单（编辑详情、优先级、删除）在悬停、聚焦或选中该行时出现，触屏（`pointer-coarse`）上常显。
- `⋯` 菜单的"编辑详情"（或选中行后按 `Enter`）打开右侧详情边栏：备注、截止日期时间选择器、优先级（带 `!` 记号的 `ToggleGroup`：无 / 低 / 中 / 高）、标记、列表（空值叫"未归类"）、课程、来源（若来自 LMS）、删除。其他模块经扩展点 `tasks.detailSections`（`TaskDetailSection`，`modules/tasks/types.ts`）在课程下方加块：M03 给考核的待办加“成绩册”块（分类 · 占比 · 成绩或未评分，“打开”跳到 `grades?assessment=<id>`），M09 给从平台导入的待办（导入成待办或成考核）加平台块（已提交时间 / 已评分 / 缺交 / 未提交，“在 Canvas 中打开”）；考核的待办下方只留一句说明。点"保存"（或 `Cmd+Enter`）后边栏关闭；保存失败时保持打开。
- 勾选完成：先不保存，这一行留在原位显示为已完成 5 秒（`completion.ts`，模块级等待表，列表行、卡片和空格键共用），5 秒内再点一次即撤销、不发请求；到时前 0.25 s 行淡出，然后调用 `tasks.item.complete` 移到已完成区。离开页面不影响等待；标签页隐藏或关闭时立即用 `keepalive` 请求保存，退出登录前先保存（会话已失效时丢弃），等待中的任务被删除时取消等待。动画只在刚勾选的 0.5 s 内（`checking` 阶段）播放，等待中重新挂载的行不会重播。勾选时的动画：圆圈轻弹、对勾画出、标题删除线从左到右划过（样式在 `theme.css` 的 `[data-completing]`）；减少动态效果时没有动画，等待照旧。取消已完成任务的勾选立即生效。
- 已完成区：列表底部折叠"已完成 N 项"，展开查看与恢复；"清除已完成"（确认）。
- 键盘：`N` 新建、`↑↓` 选择、`空格` 完成、`Enter` 打开详情（`空格`/`Enter` 只在没有聚焦任何控件时作用于选中的任务，否则交给聚焦的按钮/链接）、`Delete` 删除（确认）、`Cmd+Enter` 保存详情。

## 10. 实现说明（偏离与补充）
- 设置：用 M11 的 `register_settings(namespace="tasks", levels=("program",))`，不建 `tasks_preferences` 表，也没有 `tasks.preferences.*` capability、`default_list_id`；前端设置分区由 manifest 的 `settingsSections` 自动生成。
- 学期视图包含没有学期的任务（Program 级任务在每个学期页都可见）；`tasks.item.count` 支持 `course_id`。
- 日历源 `tasks.due` 返回范围内所有有截止日期的任务，已完成的标 `status: done`（日历里变淡，勾选不会让它消失；`include_overdue` 只带未完成的逾期任务），`meta.term_id` 给出任务的学期，`meta.assessment_id` 标出考核的任务。考核的截止日期只经它的任务显示，日历没有单独的考核源。前端在 manifest 的 `calendarSources` 提供 `complete`（勾选）、`reschedule`（拖动改截止，考核的任务不能拖）和 `create`（日历“新建 → 待办”，`components/CalendarTaskForm.tsx`）。ICS 导出不含已完成的任务。
- 优先级：界面只提供四档（无 / 低 / 中 / 高），用彩色 `!`/`!!`/`!!!` 记号表示。后端仍保留 `urgent`（Agent/API 可写入），界面把它显示为"高"，用户不改优先级时保存不会把它降级；按优先级排序时 `urgent` 仍排在 `high` 前。设置里的"默认优先级"也只有四档，已存的 `urgent` 读作 `high`。
- "已标记"（`flagged`）用旗子图标（同提醒事项）；优先级不用旗子，避免混淆（Jinyuan 2026-10-20）。字段名与智能列表不变。
- "收件箱"改名"未归类"（Unsorted）：入口、卡片设置选项、详情里列表选择的空值都叫这个名字；API 视图名、`tasks.counts.inbox` 与卡片设置的取值 `inbox` 不变。
- 列表重名检查在同一学期（或同为 Program 级）内忽略大小写与首尾空格。
- 考核的任务由 `auto.py` 按批维护：M03 一次批量创建只发一个带 `assessment_ids` 的事件，`auto.sync` 一次读出这批考核、它们已有的任务、可接管的同来源待办、课程与学期（`service.term_lookup`），不逐条查询。
- 删除学期/课程/Program 的清理订阅 `academics.*.deleting`（同事务）。
- 前端拖拽排序用 dnd-kit，仅在"手动"排序的列表/未归类里可拖。
- Page 的页头由宿主 `ScopeHeader` 渲染，页面本身不再画标题。
- `tasks.item.query` 多了 `completed`（`exclude` 默认 / `include` / `only`，2026-10-31 由 `include_completed` 和 `only_completed` 两个布尔合并）：`only` 只返回该视图下已完成的任务。列表主体只查未完成，已完成折叠区单独查，已完成任务堆积不会挤掉未完成任务。
- 清除已完成：按钮只在"已完成"智能列表、某个用户列表和"按课程"里出现，那里列出的已完成任务正是会被删除的；学期范围和学期视图一致，包含没有学期的任务；确认框写出数量。
- 详情在右侧 `Sheet` 里打开，不再占用页面的一列；单击行只选中（键盘操作的对象），不打开边栏。
- "今天"、逾期和"明天"等相对日期按 Program 时区计算（`useProgramToday`），与后端一致。
- 勾选和拖动排序对已缓存的列表做乐观更新，失败时回滚。
- 用语：模块名叫"待办"，页面内的具体对象统一叫"任务"，这是有意的。
- 删除课程时（考核被一并删除且不发事件），该课程的考核任务（无论是否完成）一起删除并发 `tasks.item.deleted`；课程自己的普通待办保留，只去掉课程。
- `tasks.item.query` 的视图、日期、排序和分页都在 SQL 里完成，返回 `total`；只有模糊搜索和按标题排序（需要归一化）才在 Python 里处理全部匹配行。前端已完成区折叠时只请求一行拿 `total`，展开后按页加载（「显示更多」）；未完成列表一页 500 条，同样可以加载更多。
- 学期自己的列表（`term_id` 非空）显示它的全部任务，即使任务因年课被推断到别的学期；Program 级列表在学期页仍只显示该学期和无学期的任务。`task-counts` 的列表角标与此一致。
- 删除列表并删除任务、清除已完成：一条 SQL 删除，发一次带 `task_ids` 的 `tasks.item.deleted`（LMS 据此忘掉导入记录）。考核的任务和其他待办一样在 `tasks.due` 里，变动时发 `calendar.changed`；这个事件在事件总线上声明为可合并（`events.coalesce`），同一事务里一批任务只派发一次，提醒也只重算一次。
- 手动排序的浮点位置在某个缝隙用尽时（中点不再严格位于两邻居之间）把整个列表按 1024 的间距重排。
- 列表按学期分组：Program 页的侧边栏和标题菜单按学期（学期名为组标题）列出，Program 级列表单独一组（「所有学期」）；学期页是本学期一组加「所有学期」一组。只有一组时不显示组标题；拖动和上移/下移只在组内。
- 新待办在保存中也能继续回车添加。"今天"与"计划中"里添加的任务默认今天到期。学期看板上的"今天"卡片只显示该学期（与无学期）的任务。
- 卡片设置表单（`settings.component`）由看板传入 `scope`，"列表"卡片据此只列出该学期能看到的列表。
- 备份：tasks 适配器 v2（`assessment_id` 是可选引用，考核没导入时任务变成普通待办）；v1 备份按 0033 的规则转换后导入（M13 §11）。
- 接管同来源的待办（2026-11-07，PR #255）：考核第一次需要任务时，如果已有一个没关联考核、`source_kind`/`source_ref` 与考核相同的任务（例如先导入为待办的 Canvas 作业，再"加入成绩簿"），就把它的 `assessment_id` 设成这个考核，而不是新建一个，保留用户在它上面的完成状态、优先级、列表和备注。接管先于截止日期检查：考核没有截止日期时，被接管的待办随即删除，不会留下导入记录指不到的待办。考核已有自己的任务时（手动添加的考核后来绑定到 Canvas 作业，2026-11-10），同来源的待办同样接管，考核原来的任务删除；原来任务上用户设的内容并入保留的待办（`auto._merge`：任一完成即完成、取较高优先级、任一加旗即加旗、备注拼接、没有列表时带上列表）。`tasks/subscribers.py` 在事务内订阅 `grading.assessment.created`/`updated`（M03 用 `publish_in_transaction` 再 `publish` 发出），所以导入提交时考核的待办已经存在，同一次读取里的提交检测能勾掉它。
