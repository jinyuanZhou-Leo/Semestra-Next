# M00 工程基础与共享约定

> 所有模块的前置模块。本模块完成后，其它模块的 agent 只需在约定好的位置添加代码，不需要再做任何基础设施决策。
> 本文中"必须"是硬性约定，其它模块不得偏离；如需偏离，先修改本文档。

## 1. 目标

1. 建立 monorepo（即本仓库根目录）：后端 `apps/api`、前端 `apps/web`、生成客户端 `packages/api-client`、部署 `deploy/`。
2. 后端核心：配置、数据库、迁移、请求上下文、统一错误、**Capability 注册表**（一份定义 → REST + Agent tool + MCP tool）、后台任务队列、领域事件总线、实时推送（SSE）、文件存储抽象、日志、测试基建。
3. 前端核心：Vite + React + TanStack Router 骨架、生成客户端接入 TanStack Query、i18n（Paraglide）、主题 token、shadcn/ui（Base UI）、**扩展契约**（模块 manifest、Page、Card、设置分区、命令、日历源）及其最小宿主实现。
4. 工具链与 CI：lint、format、类型检查、测试、OpenAPI 漂移检查。

本模块**不**实现任何业务功能。交付时提供一个示例模块 `example`（一个 capability、一个页面、一个卡片、一个设置分区）证明所有通路可用，交付后删除或保留为模板 `apps/api/src/semestra/modules/_template`、`apps/web/src/modules/_template`。

## 3. 后端约定

### 3.1 依赖与版本
- Python 3.15，uv 管理；依赖：fastapi、uvicorn[standard]、pydantic v2、pydantic-settings、sqlalchemy 2.x（async）、aiosqlite、alembic、httpx、structlog、python-multipart、sse-starlette、argon2-cffi、pyjwt、cryptography。
- 工具：ruff（lint + format）、pyright（strict 于 `core/`，basic 于 modules）、pytest、pytest-asyncio、hypothesis（计算类模块可选）。
- 版本全部在 `uv.lock` 锁定。
- 初始化时逐一确认带 C 扩展的依赖（pydantic-core、pymupdf、sqlite-vec、argon2-cffi、cryptography 等）已发布 3.15 wheel；若某个依赖暂无 3.15 支持，先在 `CLAUDE.md` 记录并寻找替代，不得私自降级 Python 版本。

### 3.2 配置
- `core/config.py`：`Settings(BaseSettings)`，环境变量前缀 `SEMESTRA_`。至少包含：`ENV`（dev/test/prod）、`DATABASE_URL`（默认 `sqlite+aiosqlite:///./data/semestra.db`）、`DATA_DIR`、`SECRET_KEY`、`ENCRYPTION_KEY`（用于加密用户密钥，Fernet）、`PUBLIC_WEB_ORIGIN`（如 `https://semestra.jyleo.cc`）、`PUBLIC_API_ORIGIN`、`CORS_ORIGINS`、`COOKIE_DOMAIN`、`STORAGE_BACKEND`（local）、`STORAGE_LOCAL_ROOT`、`USER_STORAGE_QUOTA_BYTES`（默认 52428800）、`EMAIL_BACKEND`（resend/smtp/console）及对应参数、`GOOGLE_CLIENT_ID`、`LOG_LEVEL`。
- 各模块新增配置项写进同一个 `Settings`，并在 `deploy/.env.example` 补充说明。

### 3.3 数据库
- SQLAlchemy 2.0 async，`Mapped[]` 类型化声明，统一 `Base`。
- SQLite 连接时执行：`PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON; PRAGMA busy_timeout=5000; PRAGMA synchronous=NORMAL`。
- **主键**：`id: str`，UUIDv7（`uuid.uuid7()`，标准库自带），字符串存储。
- **时间**：所有时间戳为 UTC，列类型 `DateTime(timezone=True)`，通过 TypeDecorator 保证读出为带时区的 `datetime`。日期（不带时间）用 `Date`。本地时间段（课表的 10:00–11:00）用 `Time`。
- 公共 mixin：`TimestampMixin(created_at, updated_at)`、`OwnedMixin(user_id FK users.id ON DELETE CASCADE)`。
- **所有用户数据表必须带 `user_id`**（即使可以通过父表推导），用于权限过滤与账户删除；查询一律经过 `ctx.user_id` 过滤。
- JSON 字段用 `JSON` 类型，并在 schema 层用 Pydantic 模型校验，不允许"任意 dict 透传"。
- **派生值不入库**（GPA、平均分、学分合计等实时计算）。
- 表名：`<module>_<entity>` 复数蛇形，例如 `academics_courses`、`grading_assessments`。每个模块只能写自己前缀的表；读取其它模块数据必须调用对方的 service 函数，不得直接查询对方的表。
- 迁移：Alembic 单链。每个模块在实现时生成自己的迁移；合并前必须基于最新 head 重新生成，保证单 head。CI 检查 `alembic heads` 只有一个，以及 `alembic upgrade head` + `alembic check`（模型与迁移一致）。

### 3.4 请求上下文
```python
@dataclass
class Ctx:
    db: AsyncSession
    user: User | None          # 未登录为 None
    locale: str                # 来自用户偏好或 Accept-Language
    now: datetime              # 请求开始时间（UTC），测试中可注入
    scope: ScopeRef | None     # 当前界面所在作用域，见下
    actor: Literal["user", "agent", "mcp", "system"]
    request_id: str
```
- `ScopeRef(program_id, term_id | None, course_id | None)`：前端在请求头 `X-Semestra-Scope: program:<id>;term:<id>;course:<id>` 传入当前页面作用域；Agent 调用时由会话上下文注入。服务函数**不得依赖 scope 做权限**，scope 只用于补全缺省参数（例如"把这门课的作业 3 改到周五"）。
- 依赖注入：`get_ctx`（必需登录）、`get_optional_ctx`。

### 3.5 统一错误
```python
class AppError(Exception):
    code: str          # 点分错误码，模块前缀，如 "grading.weights_not_100"
    status: int        # HTTP 状态
    params: dict       # 用于前端插值的参数
```
- 响应体固定：`{"error": {"code": "...", "params": {...}, "request_id": "..."}}`。**后端不返回面向用户的文案**，前端按 `code` 翻译（`messages/*.json` 中 `error.<code>`）。
- 通用错误码（core 提供）：`common.not_found`、`common.forbidden`、`common.unauthenticated`、`common.validation`（params 内含字段级错误列表 `[{"loc": [...], "code": "..."}]`）、`common.conflict`、`common.rate_limited`（params: `retry_after_seconds`）、`common.quota_exceeded`、`common.unavailable`、`common.internal`。
- Pydantic 校验错误统一转换为 `common.validation`。
- 访问别人的数据一律返回 `common.not_found`（不泄露存在性）。

### 3.6 Capability 注册表（核心机制）
每个业务操作定义一次，自动得到 REST 路由、Agent tool、MCP tool。

```python
@capability(
    name="grading.assessment.create",          # 全局唯一，<module>.<entity>.<verb>
    summary="Create an assessment in a course gradebook.",
    description="""Use when the user wants to add a graded item (quiz, exam, assignment...) to a course.
Do not use to record a score on an existing assessment; use grading.assessment.update.""",
    effect="write",                             # "read" | "write" | "destructive"
    http=Http("POST", "/courses/{course_id}/assessments"),  # 可选；None 表示只给 agent/mcp
    expose=("http", "agent", "mcp"),            # 默认全部
    tags=("grading",),
    agent_core=False,                           # True = 始终绑定给 Agent（见 M12，总数上限 20）
)
async def create_assessment(ctx: Ctx, inp: CreateAssessmentInput) -> Assessment: ...
```
规则：
- 输入、输出都是 Pydantic 模型；`description` 写给模型看（何时用、何时不用、负例），**英文**。字段 `Field(description=...)` 必填，枚举一律用 `Literal`/`Enum`。
- HTTP 路由由框架生成：路径参数从输入模型中同名字段提取，其余字段：GET/DELETE 作为 query，POST/PUT/PATCH 作为 JSON body。OpenAPI 的 `operationId` = capability name 的 camelCase（如 `gradingAssessmentCreate`），供前端生成 hook 名。
- `effect="write"|"destructive"` 的 capability 被 Agent 调用时走 M12 的提案确认流程；被 HTTP 调用时直接执行。
- write/destructive capability 可选声明 `preview=async def (ctx, inp) -> Preview`，返回给用户确认用的变更预览（`Preview{ title, summary, changes: [{entity, id?, field?, before?, after?}] }`）；未声明时 M12 用输入参数生成默认预览。
- 读操作必须幂等；列表类 capability 必须支持分页（`cursor`/`limit`）和**字段选择**（`fields: list[...] | None`），以减少 agent 上下文。
- 搜索类 capability 必须支持模糊匹配（大小写不敏感、子串、课程号去空格比较）。
- 权限：框架在调用前确保 `ctx.user` 存在（除非标记 `public=True`）；资源归属校验在 service 内完成。
- 插件的 capability 额外带 `plugin_id`，用户未安装该插件时：HTTP 返回 `plugins.not_installed`，agent/MCP 列表中不出现。
- 注册表 API：`registry.list(expose="agent", user=...)`、`registry.get(name)`、`registry.invoke(ctx, name, raw_args)`（含校验）。M12 与 MCP 端点只使用这三个函数。
- **非 capability 路由**（文件上传/下载、SSE、OAuth 回调、ICS 订阅）放在模块 `routes.py`，同样走统一错误与 ctx。

### 3.7 后台任务
- 表 `core_jobs`：`id, user_id, kind, status(pending|running|succeeded|failed|cancelled), progress(0-100), step(str), payload JSON, result JSON, error_code, error_params JSON, attempts, max_attempts, cancel_requested(bool), lease_owner, lease_expires_at, dedupe_key(unique nullable), created_at, started_at, finished_at`。
- `@job_handler("files.parse")` 注册处理器：`async def handler(ctx: JobCtx, payload: Model) -> Model`；`JobCtx` 提供 `report(progress, step)`、`check_cancelled()`（被取消时抛 `JobCancelled`）、`db`、`user`。
- Worker：应用进程内 asyncio 任务，默认并发 2（可配置），租约 60 秒、心跳续约，崩溃后租约过期自动回收重试；指数退避，超过 `max_attempts` 置 failed。
- `enqueue(ctx, kind, payload, dedupe_key=None)` 返回 Job；同一 `dedupe_key` 存在未完成任务时返回已有任务。
- 能力：`core.job.get`、`core.job.list`（当前用户）、`core.job.cancel`。进行中的任务不能删除；终态任务保留 7 天后清理（定时任务）。
- 定时任务：`@periodic("core.cleanup", every=timedelta(hours=1))`，同进程调度。

### 3.8 领域事件与实时推送
- 进程内事件总线：`await events.publish(ctx, "academics.course.deleted", {"course_id": ...})`，订阅者 `@events.subscribe("academics.course.deleted")`。事件在 **事务提交后** 派发。用于跨模块清理和联动，例如课程删除后 M05 清理关联待办的 course_id。
- 实时推送：`GET /events/stream`（SSE，需登录）。服务端把与该用户相关的事件以 `{"type": "...", "data": {...}}` 推送；前端根据事件类型失效对应 TanStack Query 缓存。用途：Agent 或另一个标签页修改数据后界面自动刷新、任务进度更新。
- 每个模块在自己的 spec 中列出它发布的事件和对应失效的前端 query key 前缀。
- 实现：单进程内存广播即可（单 VM 部署）；接口抽象保留，以后可换 Redis。

### 3.9 文件存储
- `Storage` 协议：`put(key, stream, content_type) -> StoredObject(size, sha256)`、`open(key) -> AsyncIterator[bytes]`、`delete(key)`、`exists(key)`。
- 实现 `LocalStorage(root)`；key 规范 `users/<user_id>/<module>/<uuid>`。
- 上传读取必须流式并边读边计数，超过单文件上限或用户配额立即中止（`common.quota_exceeded`）。
- 配额：`core.storage.usage(ctx)` 汇总各模块登记的用量（各模块通过 `storage_usage_providers` 注册统计函数）。

### 3.10 安全
- 密码 Argon2id；令牌签名 HS256（`SECRET_KEY`）。
- 用户提供的第三方密钥（LLM key、Canvas token）用 `core.security.encrypt/decrypt`（Fernet，`ENCRYPTION_KEY`）加密存储；任何响应与日志不得出现明文，只返回掩码（如 `sk-…abcd`）。
- 出站请求（Canvas、用户填写的 LLM base URL）必须经过 `core.http.safe_client()`：禁止访问私网/回环/链路本地地址（自部署可通过 `SEMESTRA_ALLOW_PRIVATE_EGRESS=true` 放开），禁止跟随跨域重定向。
- CORS：仅允许 `CORS_ORIGINS`，`allow_credentials=True`。
- CSRF：Cookie 会话下所有写请求必须带 `X-Semestra-CSRF` 头（双提交 Cookie），Bearer token 请求豁免。具体由 M01 实现，core 提供中间件挂点。

### 3.11 i18n（后端）
- 后端不返回界面文案。唯一例外是**邮件**和**导出文件**（ICS 的事件标题由用户数据组成，无需翻译；PDF/PNG 由前端生成）。邮件模板放 `modules/<m>/templates/<locale>/`，`core.i18n.render_email(template, locale, params)`。
- 支持的 locale：`en`、`zh-CN`；新增语言只需加文案文件。

### 3.12 日志与可观测性
- structlog JSON 日志，字段含 `request_id, user_id, capability, duration_ms`。禁止记录请求体中的密码、密钥、token、文件内容。
- `GET /healthz`（存活）、`GET /readyz`（数据库可写、worker 运行）。

### 3.13 测试
- pytest + pytest-asyncio；每个测试使用独立的临时 SQLite 文件并跑全部迁移（session 级缓存模板库后复制，保证速度）。
- `client` fixture：`httpx.AsyncClient(transport=ASGITransport(app))`，**禁止依赖外部运行的服务**。
- `make_user()`、`login_as(user)` fixture 由 M01 提供；M00 先提供一个直接注入 ctx.user 的测试辅助。
- 外部 HTTP（Canvas、LLM）一律用 `respx` mock；可选的真实集成测试标记 `@pytest.mark.live`，CI 默认跳过。
- 每个 capability 至少一个成功用例和一个越权用例（访问他人资源得到 `common.not_found`）。

## 4. 前端约定

### 4.1 依赖与版本
- React 19.x、TypeScript 7（tsgo）、Vite 最新、pnpm；全部精确版本锁定。
- TanStack Router（文件路由，`@tanstack/router-plugin`）、TanStack Query、TanStack Form、TanStack Table、TanStack Virtual（按需）。
- shadcn/ui（Base UI 版本）+ Tailwind v4；图标 lucide-react；动画只用 `motion`；日期 `date-fns` + `@date-fns/tz`；校验 zod。
- 开启 React Compiler。
- 工具：oxlint、oxfmt、Vitest + Testing Library、Playwright（E2E 冒烟）、MSW（组件测试中 mock API）。

### 4.2 API 客户端
- 后端 `uv run semestra openapi > packages/api-client/openapi.json`；`pnpm gen:api` 用 `@hey-api/openapi-ts` 生成：类型、SDK 函数、TanStack Query 插件（`queryOptions`、`mutationOptions`、query key 工厂）。
- 客户端统一配置：`baseUrl = import.meta.env.VITE_API_ORIGIN`、`credentials: 'include'`、自动附带 CSRF 头与 `X-Semestra-Scope`、401 时触发会话过期处理（M01）。
- 错误统一解析为 `ApiError { code, params, status }`；`toast.error(t(errorMessage(err)))` 工具函数。
- CI 检查：重新生成后 `git diff --exit-code`，保证前后端契约同步。
- **禁止**在前端手写 fetch 调用后端业务接口（文件上传/下载、SSE 等生成器不覆盖的情况放在 `lib/api-extras.ts`）。

### 4.3 路由
- 文件路由，路由参数与 search params 用 zod 校验。
- 顶层路由（各模块在自己的 spec 中细化）：
  - `/login`、`/auth/*`（M01）
  - `/onboarding`（M02）
  - `/` → 重定向到当前 Program
  - `/p/$programId`（Program 概览）
  - `/p/$programId/t/$termId/$page?`（学期作用域页面）
  - `/p/$programId/c/$courseId/$page?`（课程作用域页面）
  - `/p/$programId/settings/*`（Program 设置）
  - `/settings/*`（账户与全局设置，M11）
- 作用域页面的 `$page` 是扩展契约中 Page 的 `id`；未知 id 显示"页面不可用"空状态。

### 4.4 扩展契约（模块与插件共用）
每个前端模块在 `modules/<id>/manifest.ts` 导出：
```ts
export default defineModule({
  id: 'grading',
  kind: 'core',                 // 'core' 不可卸载 | 'plugin' 可安装/卸载
  name: m.grading_name,         // Paraglide 消息函数
  description: m.grading_description,
  icon: GraduationCap,
  pages: [ /* PageContribution */ ],
  cards: [ /* CardContribution */ ],
  settingsSections: [ /* SettingsSectionContribution */ ],
  commands: [ /* CommandContribution */ ],
  calendarSources: [ /* CalendarSourceContribution，见 M04 */ ],
  searchProviders: [ /* 全局搜索（命令面板）结果来源 */ ],
  extensions: { /* 其它模块定义的扩展点，key 为 '<定义方模块>.<扩展点>'，如 'academics.courseColumns' */ },
})
```
- **模块自定义扩展点**：某个模块需要别的模块往自己的界面里插内容时（例如 M02 的课程表格需要 M03 提供成绩列），由定义方在自己的 spec 里声明扩展点名称与类型，贡献方在 `extensions` 中提供。宿主提供 `useExtensions<T>('academics.courseColumns')` 读取所有贡献。
- **PageContribution**：`{ id, scopes: ('program'|'term'|'course')[], title, icon, component: lazy(() => import(...)), order, isAvailable?(scope) }`。作用域导航栏显示该作用域所有可用 Page。
- **CardContribution**：`{ id, scopes, title, icon, sizes: ('s'|'m'|'l'|'xl')[] , defaultSize, component, settings?: { schema: zod, component? }, multiple: boolean }`。尺寸语义：s=1×1、m=2×1、l=2×2、xl=4×2（网格 4 列）。Card 组件接收 `{ scope, instanceId, size, settings }`。
- **SettingsSectionContribution**：`{ id, level: 'account'|'program'|'term'|'course', title, order, component }`（细节见 M11）。
- **CommandContribution**：`{ id, title, keywords, icon, scopes?, run(ctx) | to }`（细节见 M10）。
- 宿主注册表 `app/registry.ts` 收集所有 manifest，并按用户已安装插件过滤 `kind: 'plugin'` 的模块（安装状态来自 M10 API；M10 完成前视为全部已安装）。
- M00 提供最小宿主：作用域导航栏（列出 Page）、静态网格渲染 Card（不可拖拽）、设置页按分区渲染。M10/M11 在此基础上增强，不改契约。
- 后端对应：插件在后端也有同名 `plugin_id`，capability 与 job 可带 `plugin_id`；插件清单（id、名称、kind、提供的 Page/Card id）由后端 `plugins.catalog.list` 返回，用于安装管理（M10）。前后端插件 id 必须一致。

### 4.5 i18n（前端）
- Paraglide JS（inlang），消息文件 `messages/en.json`、`messages/zh-CN.json`，key 命名 `<module>_<area>_<name>`（Paraglide 要求标识符形式），错误文案 `error_<code 中的点替换为下划线>`。
- 每个模块交付时两种语言都必须完整；CI 运行 inlang lint 检查缺失翻译。
- 语言切换：用户偏好（M11）> 浏览器语言 > `en`。URL 不带语言前缀（应用为登录后私有页面）。
- 日期、时间、数字、百分比格式一律使用 `Intl`（封装在 `lib/format.ts`：`formatDate`, `formatTime`, `formatPercent`, `formatGpa`, `formatCredits`），跟随当前 locale 与用户偏好（12/24 小时制、一周起始日）。
- 禁止在组件中硬编码任何用户可见字符串。

### 4.6 主题与设计 token
- 全部颜色、圆角、阴影、间距通过 CSS 变量定义在 `app/theme.css`（shadcn token 体系：`--background`、`--foreground`、`--primary`、`--muted`、`--card`、`--border`、`--ring`、`--chart-1..8` 等），支持 `light`、`dark`、`system`。
- **课程/学科颜色**使用一组固定的 12 色调色板 token `--subject-1..12`（明暗两套），以及用户自定义 hex。组件只通过 `subjectColor(colorRef)` 工具获取颜色，自动适配明暗模式。
- 模块和插件**只能消费 token**，不得写死颜色值，不得注入全局样式。
- 主题切换与强调色设置由 M11 实现，M00 提供 token 与 `ThemeProvider`。

### 4.7 状态与数据
- 服务端数据只走 TanStack Query；不引入全局状态库。界面局部状态用 React state；需要跨刷新保留的 UI 状态（例如某页面的排序方式）用 `useUiPref(key, default)`，存后端用户 UI 偏好（M11 提供 API；M11 完成前退化为 localStorage）。
- SSE 客户端（`app/realtime.ts`）：连接 `/events/stream`，按事件类型映射到 query key 前缀进行 `invalidateQueries`；各模块在自己的 manifest 旁导出 `realtimeInvalidations: Record<eventType, QueryKeyPrefix[]>`。

### 4.8 UI 规范
- `ui/` 只由 shadcn CLI 生成，禁止修改；需要扩展时在 `components/` 封装。
- 破坏性操作必须二次确认（`ConfirmDialog`，文案说明后果）；表单提交中锁定表单与关闭按钮，主按钮显示加载状态。
- 异步列表的加载态、空态、错误态（带重试）三者齐全，用统一的 `AsyncBoundary` / `EmptyState` 组件。
- 可访问性：WCAG AA；仅图标按钮必须有 `aria-label`；所有交互可键盘操作；遵循 `prefers-reduced-motion`。
- 桌面优先：主布局为左侧导航 + 内容区，最小支持宽度 1024px；窄屏（<768px）只保证 M02 定义的"今天"页面和基础导航可用，其它页面显示"请在桌面端使用"提示并给出返回入口。

### 4.9 测试
- Vitest 组件测试覆盖关键交互；MSW mock 生成客户端的接口。
- Playwright 冒烟：登录 → 创建 Program → 创建学期 → 添加课程 → 打开课程页（由 M02 补全）。

## 5. 工具链与 CI
- 根脚本：`pnpm dev`（并行启动 api 与 web）、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm gen:api`。
- GitHub Actions：`api`（ruff、pyright、pytest、alembic 单 head 与 check）、`web`（oxlint、oxfmt --check、tsgo、vitest、inlang lint）、`contract`（生成 openapi 与客户端后无 diff）、`e2e`（Playwright，PR 上可选）。
- 预提交钩子可选，不强制。
- `CLAUDE.md`：写清本文件中的硬性约定摘要和常用命令，供后续 agent 阅读。
