# M15 部署与运维

> 依赖：M00（可在 M00 完成后立即开始，随其它模块推进补充配置）。
> 目标形态：自部署版（单机 Docker Compose 一条命令启动）。官方托管版的部署脚本、运维手册与安全清单不放在仓库里（由维护者单独保管），仓库里与之相关的只有 `apps/web/vercel.json`、`apps/site/vercel.json`。

## 1. 产物
1. **API 镜像** `ghcr.io/jinyuanzhou-leo/semestra-api:<version>`：多阶段构建（uv 安装依赖 → 精简运行镜像，Python 3.14 slim），非 root 用户，入口 `deploy/docker/entrypoint.sh`：（`SEMESTRA_AUTO_SECRETS=true` 时先生成密钥）→ `alembic upgrade head` → `semestra serve`（即 uvicorn，`--proxy-headers`，信任的代理 IP 由 `FORWARDED_ALLOW_IPS` 控制；单进程，worker 并发由 M00 job 配置控制）。Dockerfile 为 `deploy/docker/Dockerfile`（构建上下文是仓库根目录），目标 `api`、`api-office`、`allinone`、`allinone-ocr`。运行层预留了安装文档管线（M07）所需系统库的位置，目前只有 `ca-certificates`、`tzdata`；M07 需要额外库时在那一层追加。LibreOffice 不包含，由 `api-office` 目标（镜像标签后缀 `-office`）提供，用于转换旧版 Office 格式。自托管默认用 `allinone-ocr` 目标（标签后缀 `-ocr`，amd64 + arm64）：装 `ocr` extra 与 `libgl1`、`libglib2.0-0t64`，设 `SEMESTRA_LOCAL_OCR=true`；镜像不带模型，第一次用到时下载到 `/data/ocr-models`（`PADDLE_PDX_CACHE_HOME`），默认模型由 `LOCAL_OCR_MODEL` 构建参数决定（默认 PP-OCRv6_medium）。
2. **Web 静态产物**：`pnpm --filter @semestra/web build` 输出 `apps/web/dist`。
3. **一体镜像** `semestra-allinone`（自部署用）：在 API 镜像基础上内置 web 静态文件，由 FastAPI 在同源提供（`SEMESTRA_SERVE_WEB=true`，实现见 `core/webapp.py`），此时 `PUBLIC_WEB_ORIGIN == PUBLIC_API_ORIGIN`，Cookie 不需要跨子域配置，构建时 `VITE_API_ORIGIN` 为空（相对路径请求）。SPA 回退规则：先匹配所有 API 路由；未匹配的 GET 若对应 `dist` 中的文件则返回文件（`assets/` 下为 immutable 长缓存），否则仅当请求 `Accept: text/html` 时返回 `index.html`（`no-cache`），其它情况返回标准 404 错误信封。**约束：后端的 GET 路径不得与前端路由同名**（浏览器直接打开该路径会得到 API 响应而不是页面）；后端的 POST 等其它方法不受影响，例如 `POST /auth/...` 与前端 `/auth/*` 页面可以共存。

## 2. 路径与环境变量
### 2.1 官网与文档
官网 `apps/site`（Astro，`base: '/landing'`）与文档 `apps/docs`（Next 静态导出，`basePath: '/docs'`，`/docs` 按浏览器语言跳转到 `/docs/en` 或 `/docs/zh`）是独立的静态站点，不在一体镜像里；自部署实例只有应用与 API。

本地开发端口：应用 5173、API 8000、官网 4321（`pnpm site:dev`）、文档 3001（`pnpm docs:dev`）。FastAPI 自带的 `/docs`、`/redoc` 已关闭，以免和文档冲突（schema 仍在 `/openapi.json`）。

### 2.2 关键环境变量（`deploy/.env.example` 完整列出并注释）
`SEMESTRA_ENV=prod`、`SEMESTRA_SECRET_KEY`、`SEMESTRA_ENCRYPTION_KEY`（Fernet，**丢失将无法解密用户密钥**，需离线备份；自部署可用 `SEMESTRA_AUTO_SECRETS` 自动生成到 `/data/secrets.env`）、`SEMESTRA_PUBLIC_WEB_ORIGIN` 与 `SEMESTRA_PUBLIC_API_ORIGIN`（一体镜像两者相同，即实例的地址）、`SEMESTRA_CORS_ORIGINS=[]` 且不设 `SEMESTRA_COOKIE_DOMAIN`（同源；只有前端与 API 分开部署时才需要这两项）、`SEMESTRA_EMAIL_BACKEND`（`console`/`smtp`/`resend`）与对应凭证、`SEMESTRA_EMAIL_FROM`、`SEMESTRA_GOOGLE_CLIENT_ID`（可选）、`SEMESTRA_USER_STORAGE_QUOTA_BYTES`、`SEMESTRA_JOB_CONCURRENCY`、`SEMESTRA_SENTRY_DSN`（可选）。其余部署相关：`SEMESTRA_SERVE_WEB`、`SEMESTRA_WEB_DIST_DIR`、`SEMESTRA_BACKUP_DIR`、`SEMESTRA_BACKUP_KEEP`；容器入口开关 `SEMESTRA_AUTO_SECRETS`、`SEMESTRA_SKIP_MIGRATIONS`。

## 3. 自部署版
- `deploy/selfhost/docker-compose.yml`：`semestra`（一体镜像）+ 可选 `caddy`（有域名时自动 HTTPS）+ 可选 `ollama`（profile `ai-local`，提供本地 chat/embedding 模型，并通过 `SEMESTRA_INSTANCE_AI_*` 配置为实例级提供方）。
- 首次启动：compose 设置 `SEMESTRA_AUTO_SECRETS=true`，若未设置 `SECRET_KEY`/`ENCRYPTION_KEY`，entrypoint 自动生成并写入 `/data/secrets.env`（权限 600，日志提示备份该文件）；环境变量里显式给出的值优先于文件。`Settings` 也会直接读取 `<DATA_DIR>/secrets.env`，所以绕过 entrypoint 的 `docker exec … semestra backup` 等进程同样能拿到密钥。
- 默认 `EMAIL_BACKEND=console`：验证码打印在容器日志中；文档说明如何配置 SMTP。也提供 `SEMESTRA_SINGLE_USER=true` 模式：首次访问创建管理员账户（邮箱 + 密码），之后关闭注册（**由 M01 实现**，见第 8 节）。
- 配额默认不限（`USER_STORAGE_QUOTA_BYTES=0`），允许私网出站（`ALLOW_PRIVATE_EGRESS=true`，方便连接内网 Ollama/Canvas）。
- 文档 `deploy/selfhost/README.md`（中英）：一条命令启动、升级（`docker compose pull && up -d`，迁移自动执行）、备份（复制 `/data` 目录，或设置 `SEMESTRA_BACKUP_DIR` 启用内置每日备份：SQLite 在线备份 API 生成一致性快照、保留最近 `SEMESTRA_BACKUP_KEEP` 份，上传文件增量镜像到 `<目录>/storage`；也可随时 `semestra backup <目录>` 手动执行）、配置 AI。

## 4. 可观测性与运维
- 日志：JSON 到 stdout，Docker 日志轮转（10MB × 5）。
- 错误追踪：Sentry（后端 `sentry-sdk`，前端 `@sentry/react`，实现见 `core/observability.py` 与 `apps/web/src/app/sentry.ts`），DSN 为空时不启用（前端也不会下载 SDK）；不上传请求体与用户内容（后端 `send_default_pii=False` 且 `before_send` 清除请求体/Cookie/请求头/用户；前端 `beforeSend` 只保留不含查询串的 URL）。
- 健康检查：`/healthz`、`/readyz`；可用 UptimeRobot 之类的服务监控 `/healthz`。
- 指标（可选）：`/metrics`（Prometheus 格式，仅内网/需 token）：请求数与延迟、job 队列长度与失败数、AI 调用量。**尚未实现**，等 M00 的 job 队列与 capability 注册表落地后再做。
- 数据库维护：每周 `VACUUM`/`ANALYZE` 定时任务（M00 periodic，夜间执行）。**尚未实现**，依赖 M00 的 `@periodic`；如果部署方用 Litestream 之类的工具持续复制 WAL，`VACUUM` 会产生大量 WAL，上线该任务时需要一并评估。

## 5. CI/CD 汇总（`.github/workflows/`）
- `ci.yml`：PR 与 main 上运行 M00 定义的 api/web/contract 检查；按改动路径跳过无关 job，同一 PR 的新推送取消旧运行；草稿 PR 不跑，标成准备好评审时运行（`deploy-check.yml` 同理）。
- `deploy-check.yml`：PR 与 main 上仅在部署相关文件（`deploy/**`、`.dockerignore`、workflow）变化时运行，也可手动触发：shellcheck、actionlint、自部署 compose 与 Caddyfile 校验，构建 `api`、`allinone` 镜像并冒烟（非 root、缺密钥拒绝启动、自动生成密钥并在重启后保持不变、迁移、`semestra backup`、同源托管前端）。
- `e2e.yml`：上线前只手动触发（main 或 PR 分支）：启动一体镜像 + Playwright 冒烟（`E2E_BASE_URL` 指向容器）。
- `version.yml`：`main` 每次推送时运行 Changesets：有待发布的 changeset 就更新「Release (version packages)」PR（`pnpm release:version`：版本号、`release-notes/<版本>.json`、`CHANGELOG.md`、`apps/api` 的 `pyproject.toml`/`uv.lock`/OpenAPI）；该 PR 合并后打 tag `v<版本>` 并以 `workflow_call` 调用 `release.yml`。
- `release.yml`：tag `v*`（必须在 `main` 上；`push` 或 `workflow_call` 传入）→ 构建自部署镜像（`api`、`api-office`、`allinone`）推送 GHCR → 创建 GitHub Release（正文来自 `release-notes/<版本>.json`）。不部署托管版：后端由维护者手动部署；前端与文档的 Vercel 项目只在合并版本 PR 的那个提交上构建生产版本（`scripts/vercel-ignore-build.sh`，看这个提交是否新增了 `release-notes/<版本>.json`），官网仍在 `main` 每次更新时部署。改了接口的版本，要在合并版本 PR 之前先部署后端。
- 版本号：全仓库一个产品版本（SemVer，所有 `@semestra/*` 包同号，`pyproject.toml` 同步），后端从已安装的 `semestra-api` 发行包读取（`semestra.__version__`，`/healthz` 与 OpenAPI 都带上），前端在构建时从 `apps/web/package.json` 注入 `SEMESTRA_VERSION`。

## 6. 安全清单
托管版的上线安全清单与恢复演练记录不在仓库里。自部署时至少确认：`/data/secrets.env`（或显式设置的 `SEMESTRA_ENCRYPTION_KEY`）已离线备份，丢失后用户保存的第三方密钥无法解密；有公网域名时经 Caddy 走 HTTPS。

## 7. 验收
- 自部署版：在一台空白 Linux 机器上 `docker compose up -d` 后 2 分钟内可以访问并注册使用。
