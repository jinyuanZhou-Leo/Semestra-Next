# Semestra-Next 技术选型与重设计 · v0.3

> 状态：技术选型已确定。**各模块的详细设计以 `specs/` 下的模块规格为准，本文与之不一致处以规格为准**（例如 Python 版本定为 3.15，所有功能一次性完整实现、不分阶段）。v0.3 补入插件、AI 费用、域名、年课成绩、i18n 的回答（2026-10-17）。依据：旧仓库 main `ef15bd3` 的 `backend/models.py`、`frontend/src/plugins/*`、`plugin-system/*`。

## 0. 旧版问题的根因

| 问题 | 代码里的表现 | 根因 |
|---|---|---|
| 实体层级混乱 | `Program > Semester > Course`，但 `Course.semester_id` 可空（为年课开的口子），`Course.program_id` 也可空；UI 又叫 "Workspace" | 同一概念多个名字，两条挂载路径 |
| 插件启用复杂 | `ProgramPluginInstallation` → `SemesterPluginActivation` + `ProgramCoursePluginActivation` + `plugin_auto_enable_semesters="ask"` | 三层安装/激活状态 |
| Tab 模型复杂 | `Tab`、`TabSetting`（三选一作用域）、`WorkspaceTabOrderEntry`（三种 bucket） | 实例、设置、排序拆成三张表，作用域各不同 |
| 设置分散 | `User.user_setting`、Program 的若干列、`TabSetting`、`Widget.settings`；Settings 和 Dashboard 本身是 Tab 插件 | 宿主核心功能被做成插件 |
| 冗余持久化 | `cgpa_scaled`、`average_percentage`、`grade_scaled` 存库 | 派生值入库 |

原则：**一个概念一个名字、一条挂载路径；核心功能不是插件；派生值不入库；业务逻辑只在后端。**

## 1. 技术选型

### 后端
- Python 3.15 + FastAPI + Pydantic v2 + SQLAlchemy 2.x（`Mapped[]`）+ Alembic + SQLite（WAL、`foreign_keys=ON`、JSON 列用 `JSON` 类型）。不用 SQLModel，ORM 与 API Schema 分离。
- **按领域分包**：`academics/`、`grading/`、`schedule/`、`tasks/`、`files/`、`lms/`（Provider 架构，目前只有 Canvas）、`plugins/`、`auth/`、`ai/`。每个包内 `models / schemas / service / router`。
- **服务层是唯一真相源**：所有业务操作写成带 Pydantic 输入输出的服务函数，REST 路由、Agent tool、MCP 都只是它的薄包装（见第 3 节）。这也是 iOS App 能复用全部逻辑的前提。
- 工具链：ruff、pyright（或 ty）、pytest（内存 SQLite + `httpx.ASGITransport`，不依赖运行中的服务）。
- 认证：Google OAuth 用 Authlib，邮箱验证码自实现。**同时支持两种凭证**：网页用 HttpOnly Cookie 会话，原生 App 用 access/refresh token。现在就按这个设计，后面加 iOS 不用改认证。
- 后台任务（Canvas 同步、文件解析、AI 抽取）：用进程内任务队列（数据库里一张 `jobs` 表 + asyncio worker），前端轮询或 SSE 看进度。单 VM + SQLite 场景不引入 Redis/Celery。
- 文件存储：抽象成 `Storage` 接口，VM 和本地部署用本地磁盘，以后可换 GCS。

### 前端
- React 19 + Vite + TS 7 + pnpm；TanStack Router（文件路由、类型化 params/search）、TanStack Query；Table/Virtual 按需。
- **OpenAPI 生成客户端**：`@hey-api/openapi-ts` 生成类型、请求函数和 Query hooks。将来 iOS 也可以用同一份 OpenAPI 生成 Swift 客户端（swift-openapi-generator）。
- UI：Tailwind v4 + shadcn/ui（Base UI 版）；动画只保留 motion 一个库。
- 校验 zod；lint/format 用 oxlint + oxfmt（TS 7 下 typescript-eslint 可能跟不上）；Vitest + 少量 Playwright E2E。TS 等关键依赖锁精确版本。
- **i18n**：采用 **Paraglide JS**（编译期生成、每条文案是一个有类型的函数，漏翻译或 key 写错会编译报错，按需打包；官方有 TanStack Router 示例）。备选 i18next，生态最大但 key 是字符串、类型安全要额外配置。约定：
  - 后端不返回界面文案，只返回**错误码 + 参数**，由前端翻译。
  - 日期、数字、学分格式全部用 `Intl`，跟随用户 locale。
  - 用户 locale 存在账户偏好里，未登录时跟随浏览器。
- **移动端**：同意桌面优先。建议只保证移动网页上"今天"（课表 + 待办 + 近期 due）这一组页面可用，其它页面在窄屏上提示去桌面端。iOS 原生 App 我认为方向对，前提就是上面说的"业务逻辑只在后端 + OpenAPI 契约 + token 认证"，按此设计即可，不用为它额外做事。

### 部署
- **域名**：（2026-10-22 修订）应用、API、官网（`/landing`）与文档（`/docs`）都在 `semestra.jyleo.cc` 一个域名下，由 GCP VM 上的 Caddy 按路径分流（见 M15）。同源，Cookie 是第一方且不需要 CORS；Cookie 设 `HttpOnly; Secure; SameSite=Lax`。
  - 这比 Vercel rewrite 转发更合适：Agent 对话和任务进度要用 SSE 长连接，经过 Vercel 代理会受它的超时和缓冲限制；iOS App 和外部 MCP 客户端本来也需要直连 API 域名。
- VM 上用 Docker Compose（API + Caddy 自动 HTTPS），SQLite 用 Litestream 持续备份到 GCS。
- 本地自部署：同一个 Compose 文件，额外打一个把前端静态文件也交给 FastAPI/Caddy 托管的镜像，一条命令起整套。

### 目录
```
Semestra-Next/
  apps/web/              # React SPA
  apps/api/              # FastAPI
  packages/api-client/   # OpenAPI 生成
  deploy/                # Compose、Caddy、Litestream
```
旧版 Semestra 保持独立仓库不动，本仓库即新版根目录。

## 2. 重设计

### 2.1 实体层级
```
User
 └─ Program（可多个，注册时自动建一个；只有一个时 UI 不显示切换器）
     ├─ Term（学期，属于 Program）
     └─ Course（属于 Program，覆盖 1..n 个连续 Term）
```
- **年课的正解**：Course 直接属于 Program，通过 `course_terms(course_id, term_id)` 关联它覆盖的学期。半年课关联 1 个，年课关联 2 个（或更多）。课程在每个关联的学期里都会显示，GPA 只按课程计一次，不会重复。
- 课表时间段（Section/Meeting）挂在 `(course, term)` 上，因为年课上下学期的上课时间可能不同。
- 去掉 "Workspace" 这个数据概念；UI 上就是"学期页"和"课程页"。
- GPA、学期平均、课程成绩实时计算，不入库。
- 年课只有一个最终成绩，成绩挂在 Course 上。学期平均默认把年课算进结束学期，这条规则放在 Program 的 GPA 设置里，可以改。

### 2.2 设置
三类，各有固定归属：
1. **账户偏好**（主题、语言、时区、外观、AI 提供方）——挂 User。主题是一组 design token（CSS 变量），**插件只能消费 token，不能定义或修改主题**。
2. **学业配置**（GPA 换算表、学分要求、学期日期、课程属性）——实体自己的字段。
3. **插件配置**——`plugin_settings(plugin_id, scope_type, scope_id, data JSON)`，插件声明 schema，宿主统一渲染表单。

入口：一个全局"设置"页面（账户、插件管理、AI），加上每个 Program/Term/Course 自己的"属性"面板。

### 2.3 插件与 UI 形态
- 核心功能不是插件：概览、课程、日历/课表、成绩、待办、文件。
- **插件 = 第一方功能模块 + manifest**，代码都打包在应用里，"安装"只是用户层面的开关（`user_plugins(user_id, plugin_id, enabled)`），不做运行时加载。
- 插件可以贡献四种东西：
  - **Page**：挂在 Term 或 Course 下的完整页面（原 Tab）。
  - **Card**：概览网格里的卡片（原 Widget），固定几种尺寸。
  - **Settings section**：见 2.2。
  - **Agent tools**：见第 3 节。
- 启用模型一层：用户安装插件 → 插件声明出现在哪些作用域 → 用户可以在某个作用域隐藏或排序。排序/隐藏存在 `layouts(scope_type, scope_id, data JSON)`。
- 插件后端部分（如需要自己的表）也按领域包组织，插件卸载不删数据，只是隐藏。

## 3. AI 架构

### 3.1 能力层：一份定义，三种出口
每个模块的操作定义成一个 **Capability**：名字、描述、Pydantic 输入/输出、是否有副作用、所需权限。同一个 Capability 自动生成：
- REST 路由（给网页和 iOS）
- Agent tool（给应用内的对话助手）
- MCP tool（FastAPI 里挂一个 MCP 端点，用户可以把 Semestra 接到 Claude Desktop 等外部客户端）

插件通过同一个注册表贡献自己的 Capability，于是"插件提供 tool 给 agent"是自动得到的，不需要额外机制。

服务层按 Capability 的形状写（清晰的输入输出 schema、描述文本、副作用标记），Agent 运行时直接建立在它之上。

### 3.2 Skill
每个模块附带一份 skill（markdown：什么时候用、常见流程、注意事项），例如"录入一门课的成绩构成"、"从 syllabus 建课"。Agent 按需加载，避免把所有 tool 一次塞进上下文。

### 3.3 写操作需要用户确认
有副作用的 tool 默认走"提案 → 用户确认 → 执行"：Agent 生成变更预览（要建哪些 due、改哪些成绩权重），用户点确认才落库。这与 LangGraph 的 interrupt / human-in-the-loop 正好对应。

### 3.4 文档智能解析（syllabus、课表等）
流程：上传文件 → 文本/版面抽取（PDF、DOCX、图片 OCR）→ LLM 结构化输出到 Pydantic schema（课程号、名称、讲师、学分、年课/半年课、成绩构成、due 列表、课程简介等）→ **生成一个"导入草稿"，用户逐项核对、修改后确认** → 写入。
- 每个抽取字段带来源位置（页码/原文片段），方便核对。
- 抽取 schema 和 Canvas 导入共用同一套"导入草稿"模型，两条导入路径只有数据来源不同。
- 这是一个后台 job，进度通过 SSE 推给前端。

### 3.5 参考 bid-analysis-agent 的取舍
读了它的 `agent/`（tools、mcp、runtime、skills）和 `docs/mcp-design-best-practice.md`、`skills-best-practice.md`。功能形态值得沿用，实现方式要改进：

**沿用的做法**
- **渐进式暴露**：不把所有 tool 一次给模型，而是提供 `search_tools` / `invoke_tool` 和 `search_skills` / `read_skill` 这类元工具，模型先搜后用。Semestra 模块和插件多了之后同样需要。
- **Skill 写法**：单一职责；description 写给路由看（Use When / Do Not Use When）；正文是步骤化 Workflow 加输出格式；可以绑定斜杠命令（如 `/import-syllabus`）。
- **Tool 设计规范**：一个 tool 一个动作、名字是动词、参数少、尽量用 enum、描述里写负例、返回结构稳定、读操作幂等。直接作为 Semestra 写 Capability 的规范。
- **写操作确认**：有副作用的 tool 先返回"待确认"状态并持久化在对话里，用户确认或拒绝后再继续。
- **上下文绑定**：它把当前项目 `project_id` 绑进 tool context。Semestra 对应的是"用户当前打开的 Term/Course"，Agent 在课程页里说"把作业 3 的 due 改到周五"时不需要再问是哪门课。
- **AI 产出先是待审状态并带引用**：AI 生成的条目是 PENDING，带原文出处。对应 3.4 的导入草稿。
- **索引未就绪时直接拒绝 RAG 请求**（它返回 409），不要让模型在半成品索引上答题。

**要改进的地方**
- 它的 `tools.py` 有近千行手写 handler，参数是 `dict`，必填参数靠手工校验，和服务层、REST 层是三份重复定义。Semestra 用 3.1 的 Capability 注册表：handler 直接收 Pydantic 模型，JSON Schema 自动生成，REST、Agent tool、MCP 都从同一份定义派生。
- 它的 MCP 注册表和 Agent tool 注册表是两套。Semestra 合成一套。
- 确认流程靠在 tool 结果里塞 `confirmationRequired` 字典，再从消息历史里找回待确认调用。Semestra 改成显式的 `proposals` 记录（包含变更预览和 diff），确认接口只执行 proposal，状态更清楚，iOS 也能复用。

### 3.6 文档处理管线（解析 → 抽取 / 索引）
参考 bid-analysis-agent 的 `file_parse_service`、`document_chunker`、`document_index_service`、`document_pipeline_fingerprint`、`vector_store_service`。那边约 3800 行，面向大量招标文件；Semestra 的文档量小得多（syllabus、课表、课件、笔记），保留骨架、压缩实现。

```
上传 → files（按 sha256 去重，保留版本）
     → parse job（后台任务）→ document：按页的结构化文本（markdown）+ 每页来源信息
          ├─ 消费者 A：结构化抽取 → 导入草稿（syllabus / 课表 → 课程、成绩构成、due…）
          └─ 消费者 B：切块 → embedding → 索引 → 检索（课程资料问答、Agent 引用）
```

**沿用的做法**
- **上传和处理分离**：上传只存原文件和元数据，之后入队后台任务。任务有状态机（PENDING / RUNNING / 终态）、进度、可取消，进行中的任务不能删除。
- **按页保存解析产物**，每个 chunk 带 `source_ref`（文件版本、页码、标题路径），回答和抽取结果都能跳回原文所在页。
- **管线指纹**：解析器版本、切块配置、embedding 模型各自算一个指纹。配置变化时只重跑受影响的阶段，没变就复用缓存。
- **原子切换索引**：新索引完整建好后再把文件的 `active_index` 指过去，旧的随后清理；检索永远不会读到建了一半的索引。
- **检索按作用域过滤**（它的 `QueryScope`）：Semestra 按 Program / Term / Course 过滤。
- **未就绪即拒绝**：所选文件索引未完成时直接返回错误，不降级。

**Semestra 的取舍**
- **抽取不依赖 RAG**：一份 syllabus 通常十几页，直接把整份解析文本交给长上下文模型做结构化输出，比检索后再抽更准也更简单。所以抽取直接读全文，检索索引服务于问答与 Agent 引用。
- **解析器**：数字版 PDF 用 PyMuPDF（pymupdf4llm 输出 markdown），DOCX/PPTX 用 MarkItDown 或对应库，ICS 直接解析成课表；扫描件和图片交给多模态模型做 OCR，不在 VM 上部署 PaddleOCR 这类重依赖。LibreOffice 只在需要转老格式时作为可选依赖。
- **混合检索**：学生的查询里常有课程号、作业编号（"APS105 Lab 3"），纯向量检索对这类关键词不敏感。建议 SQLite FTS5 关键词检索加向量检索合并排序，rerank 设为可选。
- **向量库可替换**：默认 `sqlite-vec`（和主库同一个文件，自部署零额外服务），接口上保留切换 Qdrant 的能力。
- **Embedding 提供方可配置**（OpenAI 兼容接口 / 本地 Ollama），模型名和维度写进指纹，换模型自动触发重建，不像对方那样把维度固定死在代码里。
- **任务队列复用**：解析、抽取、索引、Canvas 同步都走 1 节的同一张 `jobs` 表和 worker，不为文档单独做一套。

### 3.7 运行时与模型
- Agent 运行时：LangGraph（checkpoint 存 SQLite），等功能开始做时再细化。
- 模型提供方做成可配置（Anthropic / OpenAI 兼容接口 / 本地 Ollama）。
- **BYOK**：用户在设置里填自己的 key，后端加密存储（主密钥来自环境变量），界面只显示"已配置"，不回显，也不写日志。
- **为付费 plan 预留**：所有 AI 调用都经过一个 `resolve_ai_provider(user, purpose)`，现在只返回用户自己的 key；以后加付费 plan 时在这里返回平台的 key，并加上额度和用量记录（每次调用都记 token 用量，现在就记，以后计费直接可用）。
- 向量检索使用 `sqlite-vec`，与主库同一文件，少一个服务；接口保留切换 Qdrant 的能力。
